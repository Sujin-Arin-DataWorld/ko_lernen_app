# 일두고택 V3 건물별 가변 공정·문화 Lernpfad 설계

- 날짜: 2026-08-29
- 상태: 사용자 문서 승인 완료 (2026-08-29)
- 대상: 일두고택 V3 건물·문·담장·마당의 공정 에셋과 이를 한국어 Lernpfad에 연결하는 앱 흐름
- 기존 문서와의 관계: `2026-08-28-ildu-v3-blueprint-led-eight-stage-assets-design.md`의 정본·도면·95% 일치도 원칙은 유지하되, 모든 구조물을 8단계로 고정한 §5, §9~§11의 단계 수·진행 계약은 이 문서가 대체한다.

## 1. 목표

외국인 학습자가 일두고택을 꾸미는 동안 한옥의 모양뿐 아니라 다음을 한국어로 이해하고 사용할 수 있게 한다.

1. 건물이 실제로 어떤 순서와 결구로 지어지는가
2. 사랑채·안채·사당·곳간·문처럼 서로 다른 공간이 누구에게 어떤 기능과 의미를 가졌는가
3. 현판·한자어·공간 질서에 담긴 조선시대 가치와 사회적 한계는 무엇인가
4. 그 가치가 2026년의 직장·학교·친구·가족·온라인 생활에서 어떤 질문으로 이어지는가
5. 학습자가 그 질문에 관계와 장면에 맞는 자연스러운 한국어로 어떻게 행동하는가

건축은 학습 보상의 배경이 아니다. 학습 내용이 공정과 직접 연결되고, 완료한 의사소통 행동이 실제 건물 부재의 설치로 남는 기억 장치다.

## 2. 최우선 원칙

우선순위는 다음과 같다.

1. 실제 공법과 도면
2. 각 건물의 기능·정체성·문화적 의미
3. 현재 V3 원본과의 시각적 동일성
4. 한국어 학습 목표와 2026년의 실제 의사소통 장면
5. 플레이 시간과 제작 편의

건물별 플레이 시간을 같게 만들기 위해 공정을 합치거나 늘리지 않는다. 작은 협문이 4단계이고 사랑채가 12단계여도 정상이다.

## 3. 공통 공법 어휘와 가변 단계

모든 건물이 공유하는 것은 단계 번호가 아니라 `processTag`다.

| processTag | 의미 |
|---|---|
| `site` | 터 정리·규준·배수·기둥 중심 잡기 |
| `foundation` | 초석·자연석/장대석 기단·도면에 있는 계단 |
| `frame_posts` | 전후 기둥열·고주·평주·동바리·바닥틀 |
| `frame_beams` | 보·도리·대공·종보·대량의 결구 |
| `rafters_sanja` | 서까래·추녀·선자연·산자 |
| `roof_bed` | 적심·볏짚·진흙/보토 지붕바탕 |
| `roof_tiles` | 암키와·수키와·내림마루·용마루·기와 마감 |
| `floor_numaru` | 마루판·누마루·난간·쪽마루 |
| `wall_infill` | 회벽·판벽·심벽·창고형 벽체 |
| `doors_changho` | 문선·살문·널문·문살·한지 창호 |
| `identity_finish` | 현판·단청·의례 요소·건물 고유 마감 |
| `complete` | V3 정본과 승인된 고유 오버레이를 합성한 완성 상태 |

각 건물은 도면과 정본을 조사한 뒤 필요한 태그만 선택하고, 중요한 공정은 여러 단계로 분리한다. 사용하지 않는 태그는 빈 단계로 만들지 않는다.

예상 범위는 제작량 견적에만 사용하며 런타임 규칙으로 고정하지 않는다.

| 구조물 유형 | 예상 단계 범위 |
|---|---:|
| 사랑채·안채 | 10~12 |
| 안사랑채·중문간채·아래채·곳간채 | 7~10 |
| 창고·화장실·사당 | 5~8 |
| 협문·사당문·솟을대문 | 4~7 |
| 담장·우물·마당·연못 | 3~6 |

## 4. 건물별 프로파일 확정 절차

전체 건물에 공통 스켈레톤을 복제하지 않는다. 각 구조물마다 다음 순서로 `BuildingConstructionPlan`을 확정한다.

1. 지정 V3 원본의 파일·SHA-256·알파 bbox·바닥 접점을 잠근다.
2. `ildu_Blueprint`의 평면·정면·배면·측면·단면·상세를 건물별로 연결한다.
3. 칸 수, 기둥열, 지붕 형식, 기단, 문·창호, 계단, 마루, 고유 장식을 기록한다.
4. 실제로 화면에 구분되어야 학습 의미가 생기는 공정만 단계로 분리한다.
5. 각 단계가 어떤 Lernpfad 모듈과 연결되는지 지정한다.
6. 완성 원본으로 자연스럽게 이어지는지 자동·시각 검증한다.

일반적인 한옥 관습은 도면과 원본이 답하지 않는 부분의 임의 보충 근거가 아니다. 근거가 부족한 부재는 생성하지 않고 건축 검수 항목으로 남긴다.

## 5. 데이터 계약

단계 배열 길이는 가변이며 숫자 `8`을 도메인 의미로 저장하지 않는다.

```text
EstateConstructionPlan
  estateId
  planVersion
  worldCanvas
  viewport
  siteStageIds[]
  buildingOrder[]

BuildingConstructionPlan
  buildingId
  planVersion
  canonicalAsset
  canonicalSha256
  buildingRole
  culturalMeaning
  stages[]

ConstructionStage
  stageId
  sequence
  processTags[]
  baseAsset
  overlayAssets[]
  requiredModuleIds[]
  optionalModuleIds[]
  completionEffect
  fallbackStageId

LearningModule
  moduleId
  sourceRefs[]
  levelBand
  knowledgeLenses[]
  speechBrief
  targetExpressions[]
  acceptedVariants[]
  completionEvidence
```

진행도는 `buildingId + planVersion + completedStageIds + completedModuleIds`로 저장한다. 배열 인덱스만 저장하지 않는다. 단계가 재구성되어도 안정적인 `stageId`와 명시적 마이그레이션으로 기존 완료 상태를 보존한다.

현재 사랑채 8단계 시범은 `pending_review`이고 런타임 사용자가 없으므로 가변 단계 전환을 위한 사용자 데이터 마이그레이션은 필요하지 않다.

`EstateConstructionPlan`은 개별 건물 이전의 흙바닥 정리, 배수·마당, 바깥 담장, 문, 내부 박석·통로 공정을 관리한다. 그 뒤 `buildingOrder`가 건물별 가변 계획을 연결한다. 대지 공정과 건물 공정을 하나의 거대한 단계 배열로 평탄화하지 않는다.

## 6. Lernpfad 연결 단위

이미지 한 단계에는 기본 1~3개의 필수 학습 모듈을 연결한다. 건물 정체성에 중요한 내용은 모듈을 늘리기보다 별도 건축 단계로 분리한다.

학습 모듈은 필요한 렌즈만 선택한다.

1. **형태·어휘** — 부재명, 한자 음과 뜻, 현대 한자어 연결
2. **역사 장면** — 누가 이 공간을 사용했고 어떤 관계와 행위가 있었는가
3. **문화 의미** — 건물·현판·배치가 드러낸 가치와 사회적 메시지
4. **비판적 렌즈** — 가문·신분·성별·공동체 규범의 힘과 한계
5. **2026년 장면** — 현대 직장·학교·친구·가족·온라인에서 만나는 대응 상황
6. **한국어 행동** — 장면과 관계에 맞는 실제 발화·쓰기·중재
7. **건축 행동** — 학습 완료 후 부재·창호·현판을 직접 설치

모든 모듈에 한자를 억지로 넣지 않는다. 현판·명칭·현대 한자어와 의미 연결이 실제로 존재할 때만 사용한다.

## 7. 역사에서 2026년으로 이어지는 다리

각 문화 모듈은 `과거 설명 → 현대 정답`의 단선 구조를 사용하지 않는다.

```text
한자·건축물 관찰
  → 조선시대 공간과 관계
  → 그 가치가 중요했던 이유
  → 당시 질서의 혜택과 한계
  → 2026년의 구체적 갈등 상황
  → 관계에 맞는 한국어 행동
  → 건축 요소 설치
```

현대 장면은 과거 가치를 그대로 복종시키지 않는다. 학습자는 여러 선택 중 하나를 고르고 이유를 말할 수 있다. 앱은 도덕적 선택을 정답·오답으로 채점하지 않고, 목표 한국어의 의사소통 기능과 과제 수행만 평가한다.

역사 주장에는 국가유산·공공기관·조사보고서·검증된 학술자료의 `sourceRefs`가 필요하다. 근거가 다른 해석은 사실처럼 합치지 않고 문화 노트에서 해석 범위를 밝힌다.

## 8. 2026년 한국어 원문 계약

한국어가 의미 정본이다. 독일어와 영어는 한국어 문장 표면을 번역하지 않고 동일한 의사소통 사건에서 독립 현지화한다.

모든 현대 장면은 작성 전에 다음 `speechBrief`를 잠근다.

```text
scene/channel/purpose
speaker/addressee/relationship
speech style and honorific targets
speech act/register/emotion
known facts and unresolved facts
target expression/grammar
accepted natural variants
forbidden invention
```

기본 화법은 다음과 같다.

- 직장 동료·낯선 사람·서비스 관계: 자연스러운 해요체
- 가까운 친구: 장면이 허가한 반말
- 상급자·연장자·고객: 청자 대우, 주체 높임, 호칭을 별도 판정
- 온라인: 공개 댓글, 단체 채팅, 개인 메시지를 같은 말투로 취급하지 않음

`그냥`, `일단`, `좀`, `괜히`, `-것 같아요`, `-지 않을까요` 같은 표현은 완화·망설임·제안 등 실제 기능이 있을 때만 쓴다. 현대성을 보이기 위한 신조어·줄임말·유행어 남발은 금지한다.

“내가 오래 지키고 싶은 기준은…” 같은 사전식 작문 프롬프트 대신 상대 발화가 있는 장면을 제시한다.

```text
동료: 이 정도는 그냥 넘어가도 되지 않을까요? 괜히 일만 커질 것 같은데요.
학습자 후보: 그냥 넘기기엔 나중에 더 커질 수도 있을 것 같아요.
             지금 공유하는 게 낫지 않을까요?
```

정답 문장 하나만 강제하지 않는다. 의미·화행·관계·목표 문법을 보존한 `acceptedVariants`를 제공하고, 자유 응답은 의미 선택과 언어 정확성을 분리해 피드백한다.

국립국어원 최신 일상 대화·음성·온라인 말뭉치는 후보 검증에 사용하되 문장·ID·단원 순서를 제품 데이터로 복제하지 않는다. 실제 앱 수록 전에는 한국어 화자와 한국어교육 검수를 별도 게이트로 유지하며 자동 검사를 “원어민 검증”이라고 부르지 않는다.

## 9. CEFR별 수행

레벨은 희귀 한자어나 문장 길이가 아니라 수행 기능으로 나눈다.

| 레벨 | 수행 |
|---|---|
| A1–A2 | 부재·공간·한자어의 구체적 의미를 알아보고 짧은 선택·응답을 말함 |
| B1–B2 | 이유·결과·조건을 말하고 직장·온라인·사회 장면에서 관계에 맞게 제안·거절·설명함 |
| C1–C2 | 역사 가치와 현재 규범의 차이를 중재하고 책임·평판·양심·제도의 충돌을 여러 관점에서 설명함 |

높은 레벨 사용자가 낮은 공정 이미지를 자동 획득하지 않는다. 이미 아는 내용을 짧은 문화·언어 체크포인트로 증명하거나 정상 모듈을 선택해 완료하고, 그 증거가 있어야 건축 단계가 열린다.

## 10. 사랑채 12단계 시범 재구성

사랑채는 전체 시스템의 첫 가변 단계 시범이다.

| 순서 | stageId | 공정·표현 |
|---:|---|---|
| 1 | `sarangchae_site` | 자리 잡기·규준·기둥 중심 |
| 2 | `sarangchae_foundation` | 초석·세벌대 장대석 기단·중앙 계단 |
| 3 | `sarangchae_posts_floor_frame` | 전후 기둥열·고주/평주·바닥틀 |
| 4 | `sarangchae_beams_purlins` | 보·도리·대공·용마루 골조 |
| 5 | `sarangchae_rafters_sanja` | 주지붕·누마루 지붕의 서까래·추녀·산자 |
| 6 | `sarangchae_roof_bed` | 전체 지붕 면의 볏짚·진흙 바탕, 기와 없음 |
| 7 | `sarangchae_roof_tiles` | 기와·내림마루·용마루 완성, 벽·창호 미설치 |
| 8 | `sarangchae_floor_numaru` | 마루·누마루·난간·목부 마감 |
| 9 | `sarangchae_wall_infill` | 회벽·문선·벽체 설치 중 |
| 10 | `sarangchae_changho` | 빈 골조·문살만·부분 한지·완성 창호가 칸별로 보이는 설치 중 상태 |
| 11 | `sarangchae_hyeonpan` | `백세청풍`·`탁청재` 학습 후 두 현판 설치 |
| 12 | `sarangchae_complete` | byte-identical V3 정본과 승인된 현판 오버레이의 최종 합성 |

기존 8단계 후보의 재사용 원칙:

- 기존 1~5단계는 새 단계 1~5의 후보로 유지
- 사용자 승인 방향의 지붕바탕 수정본은 새 단계 6 후보
- 기와만 있고 벽체가 없는 새 단계 7은 별도 제작
- 표의 7~10단계 순서를 사랑채 시범 제작 순서로 사용한다. 도면·건축 근거가 이 순서와 충돌하면 조용히 바꾸지 않고 `planVersion`을 올린 수정안을 다시 사용자 검토에 올린다.
- 사용자 승인 방향의 부분 창호 수정본은 새 단계 10 후보
- 미설치 창호짝·한지·풀솔·풀그릇은 별도 `stage_10_work_props` 오버레이
- 완성 V3 원본은 수정하지 않고 현판을 별도 오버레이로 합성

이 출처들은 일두고택·사랑채·백세청풍·현대 한국어 검증의 출발점이다. 특정 현판의 제작자·제작 연대처럼 이 자료가 확정하지 않는 사실은 추가 근거 없이 만들지 않는다.

### 백세청풍

- 한자: `百·世·淸·風`의 음·뜻과 `백년·세대·청렴·기풍/풍토` 연결
- 역사: 사랑채의 접객·학문 공간과 집안이 드러내고자 한 절의·가풍
- 비판: 개인 기준, 가문 명예, 사회적 평판이 일치하거나 충돌하는 경우
- 2026년: 실수 은폐, 표절, 데이터·업무 보고, 온라인 평판과 정직 사이의 상황
- 한국어 행동: 사실을 공유하자는 제안, 부담을 낮춘 반대, 자신의 기준 설명

### 탁청재

- 한자: `濯·淸·齋`와 `세탁·청결/청렴·서재`의 형태 연결
- 역사: 누마루·학문·수양 공간에서 마음을 가다듬는 의미
- 비판: 자기 수양이 현실 회피가 되는 경우와 숙고가 책임 있는 행동으로 이어지는 경우
- 2026년: 댓글·단체 채팅·직장 메시지에 즉시 반응할지 잠시 정리할지 판단하는 상황
- 한국어 행동: 답변 유예, 감정 완화, 다시 설명하기, 관계에 맞는 사과·정정

학습자가 모든 필수 모듈을 완료하면 두 현판이 사랑채에 걸린다. 현판 문구를 현대 대사 안에 부자연스럽게 말하게 하지 않는다.

## 12. 현판 에셋 계약

입력 정본:

- `hyeonpan_calligraphy_baekse_cheongpung_v1.png`
- `hyeonpan_board_baekse_cheongpung_try01.png`
- `hyeonpan_calligraphy_takcheongjae_v1.png`
- `hyeonpan_board_takcheongjae_try01.png`

제작 규칙:

1. 녹색 배경은 결정론적 크로마/알파 추출로 제거한다.
2. 서예 원본을 이미지 생성 모델로 다시 쓰거나 변형하지 않는다.
3. 각 서예와 해당 목판을 결정론적으로 합성한다.
4. 실물 사진을 위치·크기·투시 참고로만 사용한다.
5. `백세청풍`은 사랑채 중앙 출입문 위, `탁청재`는 오른쪽 누마루 영역에 배치한다.
6. `stage_11_hyeonpan_overlay.png`는 사랑채 공통 캔버스·바닥 접점과 같은 좌표를 사용한다.
7. `stage_12_complete_v3_base.png`는 V3 원본과 byte-identical하게 보존하고, 최종 화면은 base와 승인 overlay를 합성한다.

정본 SHA-256 검사는 base에, 서예 SHA-256 검사는 각 입력과 합성 전 레이어에 적용한다. 현판이 포함된 합성 미리보기를 정본과 동일 파일이라고 주장하지 않는다.

## 13. 앱 진행 흐름

1. 흙바닥 정리부터 마당·바깥 담장·문·내부 박석과 통로까지 대지 공정을 완료한다.
2. 월드에서 현재 활성 건물과 다음 공정이 보인다.
3. 사용자가 공정에 연결된 Lernpfad 모듈을 연다.
4. 역사·문화·2026년 장면을 거쳐 한국어 행동을 수행한다.
5. 언어 목표와 과제 완료 증거가 저장된다.
6. 필요한 모듈을 모두 마치면 해당 건축 레이어가 설치된다.
7. 건물의 마지막 단계를 완료한 뒤 다음 건물이 열린다.

2412×2622 월드, 1206×2622 한 화면, 가로 팬 1회, 세로 이동·줌 없음 계약은 유지한다. 건물·마당·통로의 승인된 배치는 공정 시스템 때문에 축소하거나 이동하지 않는다.

건물별 플레이 시간은 공정·학습 의미에 따라 달라진다. XP를 맞추기 위해 빈 반복 문제를 넣지 않는다.

## 14. 실패·복구

- 단계 에셋이 없거나 검증에 실패하면 마지막 정상 단계를 유지하고 일반 한옥 대체물을 표시하지 않는다.
- 필수 역사 근거가 없으면 해당 문화 주장을 생성하지 않고 모듈을 검수 대기로 둔다.
- 언어 평가 서비스가 실패하면 사용자의 답안을 보존하고 재시도할 수 있게 하며 건축 진행을 잃지 않는다.
- 자유 응답의 가치 선택은 채점하지 않는다. 목표 표현·화행·관계 적합성에 대해서만 피드백한다.
- `planVersion`이 바뀌면 완료된 안정 ID를 우선 매핑하고, 자동 매핑되지 않는 항목은 완료를 삭제하지 않고 복구 큐에 둔다.

## 15. 에셋·콘텐츠 승격 게이트

모든 신규 산출물은 승인 전 `assets_unused/pending_review/personal_hanok_v3`에만 둔다.

건물 하나의 승격 조건:

1. V3 원본·도면·건물별 프로파일 확인
2. 모든 단계가 동일 캔버스·배치 각도·바닥 접점 사용
3. 기둥-보, 보-도리, 서까래-용마루/처마 연결 검증
4. 이전 단계의 누적 구조가 다음 단계에서 이동·소실되지 않음
5. 건물 고유 금지조건 통과
6. 역사 `sourceRefs`와 한자 표기 검증
7. 한국어 정본의 관계·높임·자연성 검수
8. EN/DE 독립 현지화와 삼각 감사
9. 사용자 시각 승인과 실제 월드 배치 승인

자동 검사 통과는 원어민·한국어교육·건축·문화 검수 완료를 대신하지 않는다.

## 17. 완료 조건

이 설계의 구현 완료는 다음을 모두 만족할 때만 선언한다.

- 모든 배치 대상 구조물에 도면 기반 가변 `BuildingConstructionPlan` 존재
- 각 단계의 V3 정체성·연속성·건물별 금지조건 통과
- 모든 필수 Lernpfad 모듈에 역사 근거와 2026년 한국어 행동 존재
- 사랑채 12단계와 두 현판의 시각·언어·문화 검수 완료
- Flutter 가변 단계 모델, 진행 저장, 월드 합성, 실패 복구 테스트 통과
- Android·iOS 내부 테스트 배포는 별도의 최종 승인과 운영 검증 후 수행

## 18. 구현 분해와 승인 순서

범위가 큰 전체 작업을 다음 하위 프로젝트로 분리한다. 한 단계의 승인 없이 다음 단계로 확장하지 않는다.

1. **사랑채 설계 시범** — 12단계 프로파일, 현판 합성, 백세청풍·탁청재 한국어 모듈, 자동 검증
2. **사랑채 앱 시범** — 가변 단계 데이터 모델, 한 건물 진행 저장, 2412×2622 월드 합성, 복구 테스트
3. **건물별 도면 프로파일** — 나머지 구조물의 역할·도면·고유 금지조건·단계 수만 먼저 검토
4. **건물별 에셋·Lernpfad 확대** — 승인된 프로파일 순서대로 한 구조물씩 제작·언어 검수
5. **전체 월드·내부 테스트** — 장식 연계, 전체 진행 회귀, Android·iOS 비공개 내부 배포

현재 다음 구현 계획의 범위는 1과 2까지다. 3~5는 사랑채 시각·언어·인게임 승인을 받은 뒤 별도 계획으로 진행한다.

## 19. 비목표와 현재 경계

- 현 설계 승인만으로 전체 건물 이미지를 자동 생성하지 않는다.
- 승인 전 에셋을 pubspec, 런타임 카탈로그, Firebase, 스토어 빌드에 넣지 않는다.
- 생성형 모델이 현판 한자를 다시 쓰게 하지 않는다.
- 역사적 가치를 현대인의 단일 도덕 정답으로 강요하지 않는다.
- 현재 문서 작성 단계에서는 커밋·푸시·메인 병합·배포를 수행하지 않는다.
