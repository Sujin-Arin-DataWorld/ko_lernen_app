## 2. 반복 변형이 생긴 이유와 바뀌어야 할 작업

치수를 프롬프트에 넣는 것만으로 생성기가 골격·렌즈·좌표계를 고정해 렌더하는 것은 아니다. 실제 mesh/rig/보정된 카메라가 없는 PNG 참조 재생성은 얼굴·비율·무늬·재질을 다시 그릴 수 있다. **이 한계를 알고도 원본 대조 없이 후속 화면으로 파생한 것은 이 세션의 작업/검수 실패**다.

- ‘참조 첨부’와 ‘출력의 외형 고정’을 같은 것으로 취급했다.
- 실패 장면을 다음 장면/번역의 참조로 이어 쓰며 미세 변형을 전파했다.
- 정본의 눈·부리·줄무늬 대신 갓·털색·옷색 같은 범주만 확인한 검수가 있었다.
- 태고의 크기 강조와 인물 밀집을 먼저 해결하며 긴 몸통·등·후구를 가려 종의 인식을 약화했다.
- 예쁜 연기·마법·텍스트 위치 교정을 캐릭터 동일성 합격으로 확대했다.
- 일부 승인 보조 시트와 원본 사이 차이를 해결하지 않은 채 합쳐 사용했다.

이 명세의 목표는 프롬프트를 더 길게 만드는 것이 아니다. 원본 선택·작업 범위·관찰 가능한 비교·실패 시 파생 중지를 실제 절차로 만드는 것이다.

## 4. 색상과 색관리

캐릭터별 색 토큰은 원본의 부위 역할 이름이다. 원본 PNG에는 이미 조명/그림자가 포함돼 있으므로 한 픽셀의 RGB를 ‘실물 원색’이나 셰이더 base-color로 확정하지 않는다.

- 원본의 같은 부위·같은 명암 단계·같은 배경 조건으로 대조한다. 따뜻한 key와 중립 fill의 관계를 유지하고, 노을/달빛/마법색은 장면 조명층으로 구분한다.
- 흰 털/아이보리 천/한지/피부는 모두 다른 재질이다. 밝기만 같다고 같은 흰색·같은 셰이더로 통일하지 않는다.
- 색상·명도·채도는 각각 확인한다. 어두운 컷에서도 홍채·줄무늬·청록 문장·남색 끈의 역할이 바뀌지 않도록 한다.
- 정확한 HEX/RGB/Lab·감마·ICC/OCIO·white balance·채도 허용오차는 아직 승인/측정되지 않았다. 해당 값은 U로 남긴다.
- 실제 색 샘플링이 필요하면 원본 SHA·좌표/영역·디코딩 색공간/프로파일·통계방식·조명 포함 여부를 함께 저장한다. 임의 팔레트 HEX를 정본으로 추가하지 않는다.
- 자동 대비/색온도 보정·흑백배경 제거로 털/흰 깃/광택 디테일을 지우지 않는다.
- 제작 도구의 이름/필터/스타일프리셋을 정체성 대신 쓰지 않는다. 동일한 자산·색/재질·형상 판정이 우선이다.

| 목재·하회탈 | 결·깎인 면·깊은 홈·고정된 조각 | 피부화/웃음·턱의 신축/새 수염. 실제 수종·코팅물성 미확정 |

광원은 캐릭터와 배경의 방향·색·부드러움이 일치해야 한다. 과한 AO로 흰털·옷주름을 검게 채우거나 림광으로 외곽을 새로 그리지 않는다. 신수 오라는 별도 효과이며 기본 몸 크기·무늬/깃 해부학·정체성의 대체물이 아니다. 밝은 효과가 얼굴을 가리면 얼굴은 검수 불가다.

## 6. 초상·전신·연기·장면

- 대화 초상은 얼굴/문장·화자 인지가 우선, 마당 전신은 전체 실루엣/종·체형/팔다리·접지를 확인한다. 한쪽의 통과가 다른 쪽의 자동 통과가 아니다.
- 모든 대사에 정면 카메라 응시를 반복하지 않는다. 발화자·청자·책/단서·사용자 행동 대상 중 현재 시선 목적을 기록한다.
- 시선·고개만 고치지 않고 목/몸 연결·발/손 지지·소품 접촉·화자와 사용자 관계를 함께 검사한다. [장면 연기 계약](ACTING_MECHANICS.md)의 연기표와 보류 조건을 적용한다. 외형 합격과 연기/접촉 합격은 별도다.
- 가슴 문장이나 소품을 보여주려고 몸의 반대 면에 복제하지 않는다. 가림 자체는 결함이 아닐 수 있으나 가린 부위는 미검수다.
- 태고는 해당 장면에서 수진보다 큰 성체를 유지한다는 최신 사용자 연출을 따른다. 승인 기본형/신수형 구분과 [장면 override](SESSION_FINDINGS.md)를 기록하며 피로를 아기 크기/새 몸통으로 표현하지 않는다.
- 탈선비가 잠든 책에서 돌아오는 장면은 책→첫소리 반응/종이빛→불투명 몸 귀환→다섯 동료 재회의 인과 순서다. 도깨비가 다시 잠드는 별도 사건을 만들지 않는다.
- 전환은 얼굴/학습글자의 반복 스케일·흔들림 대신 짧은 한 번의 상태 반응으로 설계한다. 실제 모션/립싱크/기기 QA는 이 문서 작성으로 완료되지 않는다.
- 도움/재시도/이야기공개/독립숙달/저장/건축소유/보상을 구분한다. 슬픔·분노/방망이 위협을 오답 처벌로 쓰지 않는다.

## 7. 투명 PNG·출력

- RGB 검정배경 파일을 투명PNG라고 부르지 않는다. RGBA 채널과 실제 알파를 검사한다.
- 검정/갈색 프리뷰가 보인다는 이유만으로 알파 실패라고 단정하지 않는다. 반대로 확장자/투명도 체크박스만으로 통과시키지도 않는다.
- 밝은/어두운/체커 배경 합성에서 모발·수염·흰털·깃끝·갓끈·반투명 천·그림자의 matte를 본다. 숨은 RGB/alpha1 먼지·색테두리·전체몸체 반투명을 따로 기록한다.
- 뿔/상투/갓·양손·방망이/부채·꼬리·네발/양발과 안티앨리어싱 여백을 보존한다. 여백 수치를 임의 ‘승인 규격’으로 만들지 않고 실제 bbox와 캔버스를 기록한다.
- 배경 제거·분리·재압축·채널 변환이 있으면 원본과 새출력 해시를 따로 저장한다. exact원본 추출/복사와 재생성 PNG는 다르다.
- 픽셀 크기, DPI메타데이터, 그림 속cm, Flutter논리dp는 서로 다르다. 독립42스프라이트가 아직 없으면 ‘시트9장’ 상태를 유지한다.

## 8. 제작·검수 단계

[QA.md](QA.md)의 입력기록과 중지 조건을 작업마다 적용한다. 정체성을 고정해야 할 때 통제된 원본 자산 배치와 전면 참조 재생성의 차이를 먼저 판단한다. 참조 재생성이 요구되는 정밀도를 충족하지 못하면 긴 프롬프트를 반복해 ‘고정 완료’로 보고하지 않는다. 보정된 기준뷰/통제 가능한 합성·모델/리그 등 후속 방식을 별도 검토하고 미해결을 기록한다. 이 문서는 새 도구 실행·앱 수정·배포 권한을 추가하지 않는다.

현재 추가: 원본 관찰·실패에서 도출한 제작 규칙이다. 기존 정본이미지/치수/승인 이력은 유지하며, 새 이미지 승인·메인 병합·실기기 합격으로 확대하지 않는다.
