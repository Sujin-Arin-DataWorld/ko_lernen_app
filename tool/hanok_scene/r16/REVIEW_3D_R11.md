# R11 사랑채 기와끝 장식 3D 디자이너 검수

작성일: 2026-10-24, Europe/Berlin. 역할: 360도 광학·조형·접합 검수. 범위: 읽기와 이 문서 작성만. 이 검수에서 Blender 실행, 렌더, 모델·이미지·스크립트 수정은 하지 않았다.

## 판정

**R9를 360도 회전·확대용 장식 완성본으로 승인할 수 없다.** 전면 얼굴이 읽히는 정지 이미지와 실제 전 방향 조형 품질은 별개다. R9에는 실제 정점 변위와 닫힌 후면이 있으므로 단순 평면이라고 부르는 것도 정확하지 않다. 문제는 깊이가 이미지의 밝기에 종속되고, 실측한 원래 cap과 설치 깊이가 다르며, 양끝 원형 기와끝에 큰 잎 모양 장식을 덧붙였다는 것이다.

사용자의 최신 요구인 **원래 Blender 기와끝 크기를 기준으로 제작**을 우선한다. 기존 cap의 실제 외곽·깊이·설치점을 먼저 고정하고 그 안에서 얼굴과 구름의 입체를 설계한다. 앞 이미지를 두껍게 밀고 옆·뒤에 다른 이미지를 투영하는 방식을 R11의 조형 기반으로 계속 사용하지 않는다.

- `sarang-stone-masonry-r10/full.png`: 사랑채와 장식 세 곳의 전체 배치는 확인했다. 전체 화면에서 얼굴은 매우 작아 세부 형태·붙임 깊이·후면 품질을 판정할 수 없다. 전체상 위치 확인을 근접 360도 품질 증거로 대체할 수 없다.

## 원래 cap 기준으로 고정할 조건

실측 파일 `original-finials-r11.json`의 값을 반올림해 정리했다. 이 값은 추출된 현재 원본 메쉬 기준이며 문화재 치수에 대한 별도 고증 주장으로 확대하지 않는다.

| 원래 부재 | 실제 위치·치수 | R11 기준 |
|---|---|---|
| main finial edge/앞면 | x 12.410..12.710, y -3.544..-3.436, z 6.660..7.090; 폭 .300m, 깊이 .108m, 높이 .430m. 앞면 10정점, -Y | 실제 10정점 외곽과 앞/뒤 위치를 사용. alpha 이미지 외곽으로 교체하지 않는다. |
| main pale base | 중심 (12.560,-3.490,6.600), 반지름 .145m, y -3.620..-3.360 | 원래 노출과 연결을 유지한다. 장식 맞춤을 위해 받침 자체를 키우거나 밀지 않는다. |
| 왼쪽 최외곽 원형 기와끝 | 중심 (9.195,-5.3875,4.865), 지름 .144m, y -5.400..-5.375, 두께 .025m | .144m 원형 cap 안의 작은 얼굴 부조. 잎 모양 추가 없음. |
| 오른쪽 최외곽 원형 기와끝 | 중심 (15.925,-5.3875,4.865), 지름 .144m, y -5.400..-5.375, 두께 .025m | 왼쪽과 같은 원형 형식으로 원래 중심에 연결. |

R9 main 전면은 y=-3.635-depth이므로 식상 약 -3.639..-3.659 범위다. 원래 앞면 -3.544보다 약 95~115mm 앞쪽에 놓일 수 있다. R9 양끝 leaf는 명목 폭 .237m, 높이 .3397m이며 원래 지름 .144m 대비 각각 약 1.65배, 2.36배다. 이는 전체상에서 장식이 작게 보이는 것과 별개인 명확한 치수/형식 불일치다.

주 담당자의 수정안인 main 원래 외곽·위치 유지 + 의미별 얕은 실제 부조, 양끝 원형 cap 유지 + 작은 얼굴 부조에 동의한다. 약 2mm 접합 겹침은 시작값으로 사용할 수 있지만 실제 단면의 틈·겹침을 검사해야 한다.

1. 각 위치마다 원래 cap 이름, 원본 파일 SHA, 원래 메쉬의 local/세계 bounds, 외곽 실루엣, 전체 깊이를 기록한다. 최상위 장식 하나와 좌우 두 개의 치수를 각각 측정한다.
2. 원래 메쉬의 원점이 실제 접점인지 확인한다. 원점이 장면 원점이거나 메쉬가 세계 좌표에 구워져 있으면 원점 숫자 대신 실제 받침 중심·능선 끝 중심·접촉면을 사용한다.
3. 각 위치의 좌우축, 위쪽축, 앞면 법선과 능선 진행방향을 정한다. 회전된 장식의 세계 AABB만으로 크기를 비교하지 않고 이 기준축에서 폭·높이·깊이를 비교한다.
4. 새 형상의 외곽과 연결부는 원래 cap 치수에서 파생한다. 얼굴의 돌출이 필요한 경우 몸체를 안쪽으로 두어 전체 envelope를 유지한다. 뿔이나 구름을 임의로 외곽 밖에 키워 크기 요구를 깨지 않는다.
5. 받침과의 접합은 정면의 아치 외곽뿐 아니라 옆 단면에서 확인한다. 틈, 과도한 관통, 이중 표면, 겹친 오래된 장식, 넓게 남은 밝은 받침 테두리가 없는지 본다. 원래 노출되어야 하는 받침은 보존한다.
6. 원본 711개 데이터·UV·공정 연결 보존은 별도로 검사한다. 세 새 장식의 visible 결과와 원본 보존 결과를 한 합격값으로 합치지 않는다.

## R11 조형 접근

바탕은 원래 cap의 외곽·평면 후면·두께를 가진 한 덩어리다. 전면의 얼굴·구름에만 부위별 곡률과 얕은 부조를 설계하고 가장자리에서 몸체로 자연스럽게 합류시킨다. 360도용이라는 이유로 완전한 머리 조각이나 새로운 후두부를 만들 필요는 없다. 조각의 중요한 높낮이는 이미지 luminance가 아니라 부위별 의도로 정한다.

- **뿔:** 곡선 중심선을 따라 가늘어지는 실제 부피. 이마와 이어지는 뿌리·휘는 방향·끝의 두께가 측면에서도 남아야 한다. 밝은 삼각형을 밀어 올린 형태로 대신하지 않는다.
- **이마·볼·코:** 넓고 낮은 연속 곡면을 먼저 만든다. 코와 볼의 3D 덩어리가 눈·입 주변을 연결하며, 미세한 주름보다 먼저 읽혀야 한다.
- **눈:** 눈썹/눈꺼풀의 돌출, 안와의 함몰, 눈알/눈 중심의 부피가 구별되어야 한다. 검은 눈동자 텍스처를 꺼도 두 눈이 보이는 구조가 기준이다.
- **입:** 입술과 입꼬리의 연속 부피, 입 안의 함몰을 구별한다. 몸체를 뚫거나 측면에서 얇은 칼날처럼 사라지지 않는 바닥 두께를 유지한다. 사용자 의도인 친근한 표정을 유지한다.
- **구름:** 굵기·높이가 변하는 곡선 리본/조각선으로 만들고 바탕 곡면을 따른다. 단일 굵기 튜브를 같은 깊이로 붙인 무늬, 옆면에 반복 투영한 무늬는 피한다. 중요한 소용돌이 간 간격을 확보한다.
- **옆·뒤:** 원래 cap의 단면·테두리·재료 두께를 보여준다. 원본의 평면 후면과 단순한 구운 기와 재질을 유지해도 된다. 정면 이미지를 뒤에 반복할 필요는 없다. 측면 장식이 필요하면 실제 조각선이 모서리를 넘어 이어지게 설계한다.

Height map 자체를 금지하는 결론은 아니다. 의미를 가진 조각에서 만든 높이/노멀은 미세 디테일 전달에 쓸 수 있다. 이번 실패 원인은 조명이 포함된 완성 그림의 밝기를 핵심 조형 깊이로 사용하고 추가 이미지를 옆·뒤에 채워 넣은 것이다.

렌더 실행은 이 문서 작성 범위 밖이다. 다음 제출에서 아래 근거를 받아 판정한다.

|---|---|---|
| 정면 clay | 모든 이미지·노멀·범프·발광을 끄고 단일 중성 재질, 일정한 광원 | 텍스처를 끄면 눈·입·볼·뿔이 사라지거나 단순 요철처럼 읽힘 |
| 좌·우 측면 clay | 원래 cap 외곽과 새 형상 중첩 또는 동일 배율 비교 | 깊이만 있는 판, 얼굴 특징의 갑작스러운 절단, 림의 칼날 두께, 지나친 돌출 |
| 후면 clay | 원래 후면 위치·외곽·테두리·접합부. 원본처럼 평면이어도 허용 | 원래 몸체와 어긋난 마개, 구멍/노멀 반전/부착물 틈 |

단일 전면 사진, `actualVertexRelief=True`, 다수의 폴리곤, 닫힌 boundary만으로 통과 처리하지 않는다. 검수표는 실제 3D 장식에 적용하며 Flutter/기기/360도 런타임 통과는 별도다. 재질 누락 상태에서도 얼굴의 구조가 유지되는 것이 핵심이다.

## 근거와 한계

- 현재 판정은 위의 기존 PNG 두 장, R9 제작 코드, 원래 cap 실측 JSON에 근거한다. 후면·측면 clay 및 R11 새 결과를 아직 직접 보지 않았다. R9의 전면 오프셋 범위는 코드식에서 계산한 범위이며 실제 최댓값 실측이라고 주장하지 않는다.
- Blender 공식 문서는 bump가 실제 메쉬를 바꾸지 않으며, 실제 변위와 결합할 때 큰 형상과 미세 디테일을 나누어 다룰 수 있다고 설명한다. R9에는 실제 정점 변위도 있으므로 단순 bump 한계만으로 평가하지 않았다. [Blender Displacement](https://docs.blender.org/manual/en/latest/render/materials/components/displacement.html), [Blender Cycles Material Settings](https://docs.blender.org/manual/en/4.5/render/cycles/material_settings.html) — 확인 2026-10-24.
