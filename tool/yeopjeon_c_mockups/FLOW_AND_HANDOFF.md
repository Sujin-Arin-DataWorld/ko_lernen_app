# Yeopjeon reward flow and implementation handoff

Current 2026-10-10 authority: `refined.html`, `refined.css`, `refined.js`, `refined-tokens.css`, the user's 71-image style reference, and `MOTION_SPEC.md`. This package is runnable design evidence. It has no account/backend connection or persistent wallet.

## Flow

Learning result saved → confirmed receipt (+20 first lesson / +10 second lesson) → Dokkaebi video or short coin response → wallet-local + / ++ and rolling final balance → continue learning or visit the Ildu house → verify learning eligibility and 40-coin balance → show before/after balance → explicit confirmation → one 40-coin spend → building feedback → next learning.

A newly eligible construction stage can produce its separate +40 receipt. It is not automatically +40 for every quest, game or free practice. The real source audit and shared daily allowance are in `AUDIT.md`. Dancheong, XP and decorative quest chests remain distinct systems.

Fixtures: first lesson 20+20=40; second lesson 20+10=30; building support 70+40=110; building confirmation 110−40=70. These are separate examples, not one lesson that always awards +60. Pending, daily limit, insufficient coins and learning-incomplete states do not manufacture a new receipt.

The wallet balance is authoritative before its motion. Presentation, replay and coin taps never mutate a credit. Navigation or interruption lands at the final balance. Construction is guarded by eligible + sufficient balance + confirmation state; repeated clicks spend once. The prototype's values must be replaced by confirmed YeopjeonService receipt data during native integration.

`INTEGRATION_CONTRACT.md` records ownership, the proposed confirmed-receipt input and presentation completion boundary for other design sessions. It distinguishes the implemented internal JavaScript functions from an unimplemented native adapter.

## Geometry

The iPhone 16 Pro review canvas is 402×874 CSS px, derived from Apple's 1206×2622 specification at 3×: [Apple specifications](https://support.apple.com/en-am/121031). Reserved system spaces are a conservative 62px top and 34px bottom in this HTML review, not a measured UIKit safe-area result.

App grid: 62px system area / 52px brand-wallet header / remaining paper sheet / 34px home area. Paper sheet has a 12px side inset and an 8px bottom margin. Main content has 12px top and 18px side padding. The reward picture slot is 316×316 with a separate 44px control row. The full original video fits the square; no negative offsets, crop, cover or playing-video transform.

Normal DE/EN content fits one screen with readable text and both CTAs. 200% text is deliberately allowed vertical scrolling, with no horizontal clipping or reduced font size. Small 375×812 and landscape layouts have separate responsive slots; their video remains contain. `WIREFRAME_SPEC.md` records the information hierarchy.
