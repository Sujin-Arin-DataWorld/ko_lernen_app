# Reward-suite motion contract

Design specification for the selected C family, not implemented new-screen motion.

| Surface | Start trigger | Finite timeline | State owner |
|---|---|---|---|
| Second lesson receipt | A newly confirmed positive receipt with earned10 and walletAfter30 |180ms scene entrance; one840ms clock animates earned0→10 and wallet20→30;200ms brass-light settle |Saved receipt and validated wallet |
| Construction milestone receipt | Actual new milestone claim40 with walletAfter70 |Same180/840/200 sequence, earned0→40 and wallet30→70; one readiness reveal after confirmed eligibility |New claim identities; not a scene replay |
| Wallet summary |Read existing wallet |180ms paper entrance; all numbers immediately actual, no award roll/shower |Wallet sum of claims and actual construction spend |
| Construction confirmation |Show eligible spend proposal |CTA scale.988 in80ms,1.5dp press depth;240ms return. Current balance remains70 while save is unresolved |buildNext and durable stored result |
| Build success |Service confirms built |Settle to the saved balance30 and present saved-state copy; no new positive award |Service/storage, not animation completion |

Before a wallet count roll, validate before>=0 and before+earned==after. A valid positive receipt without a consistent before/after pair shows its confirmed after balance directly; it does not invent a starting value. Awards20/10 and milestone40 are separate claims and can coexist; actual receipt totals drive the animation, never a hardcoded amount.

Coin_face is a shared currency symbol. The two receipts can use a finite yupjeon hero effect contained at its original aspect ratio. Wallet and construction use calm coins. At the user's later direction, the selected original wallet composition gains exactly one independent blue Dokkaebi flame beside the central coin; it may react once for500–620ms, then rest, without changing the wallet. There are no coins travelling into the wallet. All generated images represent the final static frame.

Navigation stays available during receipt animation. Leaving, app backgrounding or reduced-motion mode settles visual numbers to the confirmed result and cancels decorative work, without granting money again. NoReward/alreadyClaimed/unverified/failed/unknown/stale do not start a reward roll. unknown is unresolved storage outcome, not proof of zero credited funds. Retrying reads/checks the stored transaction, not a blind duplicate grant.

Render foreground coin art, contact shadow, number text and surfaces as separate layers. Keep numeral text real and accessible. Cache material images; animate only local transform/opacity and the numeral glyphs rather than rebuilding the scene. One timeline controls both amount and wallet. Avoid full-screen blur and perpetual sparkle. Artwork stays still while reading or selecting a construction action.

Layout requirements remain402×874 normal text, source art full containment, shared C button internals and safe areas. At actual accessibility enlargement, adapt text rather than rasterizing user-facing information. Device FPS, semantics, touch targets, lifecycle behavior and completed save flows require future Flutter checks.
