# 엽전 보상 확장 화면 제작 계획

문서 유형: 제품 디자인 사양·제작 순서. 기준일: 2026-10-10. 새 영상 제작은 사용자 요청에 따라 후속 단계로 둔다.

## 1. 승인 기준과 목표

승인된 **C 도깨비 보상 화면**과 **70엽전 지갑 화면**을 공통 시각 기준으로 사용한다. 지갑에 요청한 푸른 도깨비불 한 개를 더한 버전도 참조한다. 두 원본은 보관하고, 확장 상태는 별도 시안으로 제작한다.

첨부한 금빛 문·마당 이미지에서는 **엽전을 쓰면 내 공간이 자란다는 기대감과 터치 반응**을 참고한다. 현재 미공개 한옥 단계의 문·마당·실루엣을 새로 추정해 그리거나, 그 이미지의 장식 밀도를 승인 C 화면 전체에 덧붙이지 않는다. 첨부한 70−40=30 화면은 비용 확인 참고이며, 상시 목표 설명을 대신하지 않는다.

이번 확장의 핵심은 네 질문에 바로 답하는 것이다.

1. 엽전은 어디에 쓰는가?
2. 지금 내 일두고택은 어디까지 진행됐는가?
3. 다음 건설을 위해 무엇이 남았는가?
4. 지금 누르면 어디에서 무엇을 할 수 있는가?

**상시 목표는 승인 지갑의 확장형으로 구성한다.** 같은 GoalCard를 Heute·Lernen·완료 보상·지갑·한옥 진입에서 재사용한다. 새로운 상위 탭을 늘리지 않는다. 일반 지갑 요약과 목표 보기의 진입은 구분하되 비취·황동·한지·CTA 구성 요소를 공유한다.

## 2. 현재 코드가 뒷받침하는 경제

아래는 이 작업트리의 현재 파일에서 확인한 규칙이며, 새 정책 제안과 구분한다.

| 항목 | 현재 규칙 | 디자인에 주는 의미 |
|---|---|---|
| 새로운 학습 완료 | 하루 첫 20, 둘째 10, 이후 일일 완료 보너스 0 | 콘텐츠 lesson과 정규 course unit이 같은 일일 예산을 공유한다 |
| 건설 자격 | 새 자격마다 지원금 40 | 여러 자격을 한 번에 확인하면 40의 배수로 지급될 수 있다 |
| 합산 지급 | 같은 관측 구간에 생긴 신규 claim의 합 | 20+40=60, 10+40=50, 더 큰 합계도 한 번 표시한다 |
| 엽전 사용처 | 다음 건설 한 단계에 40 사용 | 현재 생산 lib의 소비 API는 건설뿐이다. 장식·상점·현금 교환을 임의로 추가하지 않는다 |
| 건설 조건 | 실제 미건설 자격 + 잔액 40 이상 | 돈만 충분하다고 건설 자격이 생기지 않는다 |
| 복습 10 | 검증 API가 있으나 생산 UI 호출 없음 | 지금 획득 안내와 목업에서는 활성 보상으로 광고하지 않는다 |
| XP·퀘스트·단청 | 별도의 상태·보상 | 엽전으로 자동 환산하지 않는다 |
| 기존 학습·건설 | 경제 도입 전 진도는 baseline으로 보존 | 잔액0이어도 이미 지은 단계가 있을 수 있다 |

정상 지갑은 다음 관계를 지킨다.

`잔액 = 40 × 미건설 자격 수 + 누적 일일 보상`

현재 규칙에서는 **건설 자격이 있는데 40엽전이 부족한 정상 상태가 발생하지 않는다.** 자금 부족 화면은 방어 분기·향후 정책 변경용 QA로만 관리한다. 상시 동기는 주로 “실제 다음 코스 학습 → 새 자격과 지원금 → 내가 확인해 건설 → 다음 목표”로 이어진다. 엽전이 충분해도 코스 자격이 없으면 학습 목표를 안내한다.

콘텐츠 lesson 완료로 엽전을 받는 것과 정규 course unit 증명으로 건설 자격이 늘어나는 것은 별개다. 현재 자격 집계는 A1·A2·B1·B2의 검증된 단위이며, C1·C2 콘텐츠는 그대로 유지한다. 아무 추천 과제나 완료하면 건설이 열린다고 표시하지 않는다.

또한 “현재 열린 단계들을 모두 지음”과 “현재 제공되는 모든 건설 단계가 완료됨”은 다르다. 전자는 다음 코스 학습을 안내하고, 후자는 남은 잔액과 학습을 유지하며 미정인 다음 건설·새 소비처를 약속하지 않는다.

## 3. 우선 제작할 상시 목표 화면

### W03 — 다음 학습 조건 대기

승인 지갑의 비취 무대·금색 엽전·불꽃 한 개를 이어받는다. 아래 한지 GoalCard가 현재 진행과 다음 행동을 설명한다.

- 현재 진행: 저장된 **실제 소유 단계 수**. 필요하면 이미 공개된 최근 진행과 다음 비공개 표시 한 개만 사용한다.
- 자금: 현재 잔액과 단계당 비용40. 충분하면 “자금 준비”로 표시한다.
- 학습: 실제 다음 코스 목표와 아직 남은 평가·학습 조건을 짧게 표시한다.
- 기본 행동: **Lernziel fortsetzen / Continue learning goal**.
- 보조 행동: 명확한 이전 화면 복귀. 실제 이동이 pop뿐이면 “Weiterlernen”이라는 새 과제 시작 레이블을 붙이지 않는다.
- 추가 설명: 학습 조건 행을 누르면 I03에서 실제 조건을 확인한다.

70엽전이 있어도 미건설 자격이 없다면 “돈은 준비됐고, 다음 학습 목표가 남았다”는 상태다. “한 강의만 더”·“몇 분만 더”는 실제 코스 조건으로 증명된 경우에만 사용한다.

### W04 — 건설 가능

같은 화면에서 학습 조건은 충족, 자금은 준비로 표시한다. 열린 미건설 자격이 여러 개면 실제 수만 안내한다.

- 기본 행동: **Für 40 bauen / Build for 40** → B01 사용 확인.
- 코인 터치: 짧은 입체 눌림과 I01/I03 설명. 코인 터치만으로 지급하거나 건설하지 않는다.
- 진행 표시: 미건설 자격은 학습으로 열린 상태이며, 실제 소유 단계로 계산하지 않는다.
- 다음 한옥 외형·건물 이름·지붕·전체 미래 단계 목록은 공개하지 않는다.

### B01 → B03 → W05 — 사용 후에도 목표가 이어짐

B01에서 현재70·사용40·성공 후 예상30을 구분한다. 취소 시 지출은 없다. B02 저장 중을 거쳐 실제 저장 성공 시 B03의 **Baufortschritt gespeichert / Build progress saved**를 보여준다.

W05는 갱신된 지갑과 소유 상태에서 다음 행동을 선택한다.

- 아직 미건설 자격이 있으면 다음 건설의 새 확인을 안내한다.
- 열린 자격을 모두 사용했지만 현재 건설 상한 전이면 실제 다음 학습 목표를 안내한다.
- 현재 제공되는 건설 상한을 모두 채웠다면 W06으로 전환한다.

한옥 정본이 바뀌는 동안에도 이 거래·진척 화면은 제작할 수 있다. 장면은 승인 엽전과 진행 표시를 사용하고, 새 미승인 건물이 곧 나타난다고 약속하지 않는다.

3개 주요 화면 계열과 공통 정보 패널 하나를 사용한다. 아래 **27개는 검수할 시각 상태**이며 27개의 새 레이아웃·새 route를 뜻하지 않는다. 승인2개 외 추가25개를 관리하고, 그중 W09 한 개는 정상 여정이 아닌 방어 QA 전용이다. 금액·언어·건물 자격 수의 데이터 변형은 추가 화면 수로 부풀리지 않는다.

화면 목록 JSON의 `statuses`는 API 상태를 빠뜨리지 않았는지 확인하는 참고 분류이며 표시 조건이 아니다. 화면 진입은 동일 계정·수명주기의 검증된 전후 지갑과 확정 신규 claim 합계로 결정한다. 서비스가 건설 지원금을 저장한 뒤 일일 거래 `noReward(amount0)`를 반환해도 지원금의 양수 영수증이 우선한다.

R05는 **영수증의 전체 신규 엽전이0인 경우**에만 적용한다. 일일 완료 보너스0이어도 신규 건설 지원금이 있으면 R03/R04이다. R10은 별도 route 없이 보상 템플릿을 재사용하며 **Nachträglich gutgeschrieben / Previously earned, now credited**로 이유를 구분한다. 현재 앱 시작 복구가 곧바로 성공 팝업을 뜻하지 않으므로 연결 작업이 필요하다.

I02는 현재 데이터로 만들 수 있는 **확정 내역 요약**이다. 지갑 claim에는 모든 거래의 발생 시각이 저장되어 있지 않으므로 임의의 “방금·어제·시간순 거래명세”를 만들지 않는다. 정확한 거래 타임라인이 필요하면 별도 데이터 계약과 마이그레이션을 먼저 계획한다. 한 화면 최대4행과 이전/다음 페이지를 사용한다.

## 6. 필요한 앱 연결 작업

목업과 별개로 아래 구현이 있어야 이 흐름이 실제로 이어진다.

1. **ConstructionGoalPresenter 제안:** 확정 YeopjeonWallet, HanokCompetenceProjection, durable CourseMasterySnapshot, canonical course unit·링크를 합쳐 실제 다음 목표를 만드는 읽기 전용 계층. LearningFocus의 추천 목적지를 재사용하되 건설 자격에 기여하는지 확인한다. 미확인 목표는 “학습 계속”으로 안내하며 해금·금액을 보장하지 않는다.
2. **지갑 읽기와 경제 정산 분리:** `loadCurrent()`도 지원금을 정산·저장할 수 있다. 화면 진입을 지급 이벤트로 해석하지 않는다. 순수 요약은 엄격한 저장 읽기·decode 경계를 사용하고, 정산 뒤의 신규 보상은 독립된 영수증 owner가 확인한다.
3. **실제 거래 상태 전달:** 현재 receipt capture는 양의 변화가 없거나 관측 실패면 null을 반환할 수 있다. null만으로 noReward·중복·실패를 구분하지 않는다. 거래 결과와 확정 snapshot, 필요하면 원본 claim identity를 함께 전달한다.
4. **공통 학습 완료 관측:** 목표 카드의 새 CTA는 기존 학습 경로와 course context를 보존하면서 공통 capture owner를 거치게 한다. 직접 CourseMissionScreen을 여는 것만으로 항상 완료 즉시 보상 화면이 뜬다고 가정하지 않는다.
5. **상시 GoalCard와 목표 보기:** 기존 지갑 진입과 한옥 진입을 유지하면서 승인 지갑의 목표 변형을 연결한다. 정보 시트는 추가 상위 탭 없이 연다.
6. **건설 거래 재시도 대상 고정:** 요청의 building·`targetStage=ownedBefore+1`·계정 수명·잔액을 기억한다. unknown 뒤 그 원래 단계가 이미 저장됐다면 완료로 끝낸다. 현재 buildNext에는 예상 대상 인자가 없으므로 writer 내부에서도 같은 대상을 보장하는 계약이 필요하다.
7. **복구 성공 영수증 연결:** startup 복구와 foreground 복구를 실제 새 claim 합계로 보여준다. 과거 날짜의 daily claim을 “오늘 첫/두 번째”로 레이블하지 않는다.
8. **현재 건설 완료 분기:** owned==eligible인 학습 대기와 양쪽 설정 상한을 채운 현재 건설 완료를 구분한다. 미정 한옥 자산·새 소비처·미래 정책은 앱 상태처럼 표시하지 않는다.
9. **번역·상태 접근성:** DE/EN ARB와 semantic status를 연결한다. 숫자 증가 매 틱을 음성으로 읽지 않고, 확정 결과를 한 번 안내한다.

## 7. C안 재질·모션·모바일 공통 사양

### 재질과 배치

- 비취 옻칠 바탕, 가장자리의 입체 구름, 오래된 황동 엽전, 따뜻한 한지, 왼쪽 위 광원을 유지한다.
- 한지 카드의 면·얇은 옆면·접촉 그림자, 황동 CTA의 윗면·받침·눌림 깊이를 공통 요소로 구현한다.
- 금색 기본 CTA는 다음 행동 하나를 맡고, 비취 보조 CTA는 복귀/학습 등 실제 역할을 명확하게 표시한다. 카드 안에 같은 CTA를 중복 배치하지 않는다.
- 숫자는 실제 텍스트다. 배경 그림 속 가짜 잔액·카피와 겹치지 않는다. 이미지에서 CTA 테두리·구름·화살표 조각을 중복 잘라 붙이지 않는다.
- 목표 진척은 C 재질의 충분한 두께를 가진 트랙/진행 점으로 표현한다. 얇은 한 줄로 처리하지 않는다. 트랙12–14dp는 시안 기준이며 native capture로 재검토한다.
- 미래 한옥 외형·흰 배경 에셋·옷감 placeholder·전체 미래 단계열·고정 사랑채 이름을 새 목표 아트에 넣지 않는다. 공개 가능한 현재 canonical 자산은 해당 소유 단계와 검토 상태를 확인한 경우만 사용한다.

### 숫자·빛·조작 반응

| 상태 | 계획한 반응 | 종료·축소 동작 |
|---|---|---|
| 확정 보상 | 180ms 진입 → 획득0→실제 합계와 잔액 before→after를 같은840ms 시계 → 황동 빛200ms | 끝나면 정지. 지갑으로 날아가는 동전 없음 |
| 지갑·목표 진입 | 확정 잔액은 그대로. 기존 푸른 불꽃 한 개의 500–620ms 반응 | 이후 정지. 새 지급처럼 count-up하지 않음 |
| 코인/CTA 터치 | 분리 레이어의 깊이·접촉 그림자 변화, 설명 또는 실제 다음 행동 | 손을 떼면 복귀. 지급/차감 owner가 아님 |
| 실제 학습 진척 변경 | 변경된 진행 점·조건 표시만 짧게 반응 | 반복 움직임으로 읽기를 방해하지 않음 |
| 건설 저장 성공 | 확정된 진행 점480ms 반응, 실제 잔액과 다음 목표 갱신 | 미래 자산 공개는 별도 canonical 검증 후 |
| pending/unknown | 같은 정보 영역의 확인 상태 | 성공 숫자·체크·지급 햅틱 대기 |
| 동작 줄이기 | 확정 결과 즉시, 필요하면 최대200ms 페이드 | 동일한 행동·저장 결과 유지 |
| 화면 밖·백그라운드·계정 변경 | 장식과 이전 계정 모션 중단 | 미확정 거래를 성공/실패로 추측하지 않음 |

숫자는 `delta=floor(earned × easing(progress))`, `displayedBalance=before+delta`처럼 같은 증분에서 파생한다. `before+earned!=after`이거나 before가 없으면 시작값을 꾸미지 않고 확정 결과를 표시한다. 복구·재진입·재생은 지급을 다시 실행하지 않는다.

새 영상이 없는 동안에는 승인 도깨비 인물은 정지 아트로 유지하고 분리된 동전·빛·그림자·숫자·CTA의 2.5D 반응을 계획한다. 전체 UI PNG를 흔들어 글과 버튼까지 움직이지 않는다. 새 팔·표정 연기를 구현했다고 보고하지 않는다. 기존 영상을 비교할 때는 원색·전체 프레임을 보존한다. 새 영상 제작·캐릭터 리깅은 후속 단계다.

### 화면 높이와 접근성

- 기준: iPhone16Pro **402×874 논리 크기**, DE/EN, 100% 글자 크기.
- 설계 safe area: 상단62·하단34. 실제 기기 inset은 Flutter에서 읽는다.
- 참고 세로 구간: 헤더62–114, 제목122–186, 핵심 내용194–702, 기본 CTA714–770, 보조 CTA778–826.
- 관련 요소4–8dp, 묶음12–16dp, CTA 사이8dp. 터치48dp 이상.
- 정상100%에서는 내용·카드·CTA가 한 화면에 들어오게 검수한다. 긴 안내와 내역은 한 화면짜리 정보 페이지로 나눈다.
