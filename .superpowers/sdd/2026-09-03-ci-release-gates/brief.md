## W2 — symbol-evidence gate in `play_closed.yml` (commit 2)

Design constraints from `tool/android_release_evidence.py` (read its module docstring + `_validate_tool` + `upload_symbols`): every executable/JAR/JS in a tool command needs a reviewed SHA-256 (no trust-on-first-use); `GOOGLE_APPLICATION_CREDENTIALS` must be a file path; `FIREBASE_TOKEN` must be absent; symbols dir must contain only `app.android-arm.symbols`/`app.android-arm64.symbols`/`app.android-x64.symbols`; `--expected-aab-sha256`, `--git-sha`, `--run-id`, `--run-attempt`, `--version-code`, `--firebase-app-id` are required; `verify` is the read-only gate (exit 1 unless a `success` receipt matches).

1. New reviewed config `tool/android_release_tools.json` (committed, no secrets): pins `bundletool` (`version`, GitHub release `url`, `sha256` of the jar), `firebase-tools` (npm `version` and the `sha256` of `lib/bin/firebase.js` for that version), and the runner toolchain (`java`: Temurin exact version + `sha256` of `bin/java`; `node`: exact version + `sha256` of `bin/node`). Use `"<fill from harvest step>"` placeholders for every sha256 you cannot compute offline. Put the documentation in `docs/runbooks/android-symbol-evidence.md` (new, ≤60 lines: what the gate does, how to run the harvest, which secrets/variables Jin must set, how to flip the variable, how to roll back = set the variable to `false`).
2. In `play_closed.yml`, after "Record bundle identity" and BEFORE "Preserve AAB and Dart symbols", add steps guarded by `if: vars.ANDROID_SYMBOL_EVIDENCE_GATE == 'true'`:
   a. "Pin release toolchain": `actions/setup-java` and `actions/setup-node` with the EXACT versions from `android_release_tools.json` (read them with `jq`/python into step outputs), download `bundletool-all-<version>.jar` from the pinned URL and verify `sha256sum -c`, `npm install --no-save firebase-tools@<version>` into a scratch dir under `$RUNNER_TEMP` (no global install), verify `sha256sum` of `lib/bin/firebase.js` against the pinned value, and write the `--tools-json` file the tool expects (absolute paths + sha256 map for java, bundletool.jar, node, firebase.js).
   b. "Materialise Firebase credentials": write `${{ secrets.FIREBASE_SYMBOLS_SA_JSON }}` to `$RUNNER_TEMP/firebase-sa.json` with `umask 077`, fail with a clear `::error::` if the secret is empty; export `GOOGLE_APPLICATION_CREDENTIALS`; ensure `FIREBASE_TOKEN` is not set.
   c. "Upload and verify Crashlytics symbol evidence": `python tool/android_release_evidence.py upload --aab build/app/outputs/bundle/release/app-release.aab --symbols build/app/outputs/symbols --google-services android/app/google-services.json --receipt $RUNNER_TEMP/symbol-receipt.json --tools-json <file> --git-sha ${{ github.sha }} --run-id ${{ github.run_id }} --run-attempt ${{ github.run_attempt }} --version-code <release-meta output> --firebase-app-id ${{ vars.FIREBASE_ANDROID_APP_ID }} --expected-aab-sha256 <from the sha256 file>` then `... verify ...` with the same identity. Any non-zero exit fails the job → the Play upload step never runs (it is later in the same job). Print only the tool's JSON stdout/stderr (it never leaks secrets by design).
   d. "Archive symbol evidence": `... archive --archive-dir $RUNNER_TEMP/symbol-evidence ...` and upload it as a sibling artifact `android-symbol-evidence-v<version-code>-<sha>` with `retention-days: 90` (the Codex plan asked for 90-day retention).
   e. Add one always-on step "Symbol evidence gate status" (no `if`) that prints whether the gate is enabled and, if disabled, prints the sha256 of the runner's `java` and `node` binaries already installed by the existing setup steps — this is the harvest Jin uses to fill the JSON once. It must not download anything.
3. Verify `android/app/google-services.json` contains the package `com.sujinarin.ko_lernen_app` (the tool cross-checks `mobilesdk_app_id`); do not commit any app id — it comes from `vars.FIREBASE_ANDROID_APP_ID`.
4. Tests: `tool/test_android_release_evidence.py` unchanged; add `tool/test_android_release_tools_config.py` (stdlib unittest) that loads `tool/android_release_tools.json`, asserts the schema (keys, version strings, url host = `github.com` path prefix `/google/bundletool/releases/download/`, sha256 values are either 64-hex or the literal placeholder) — so a half-filled config fails fast in CI's tool discover. YAML-parse `play_closed.yml`; run `python tool/release_integrity.py actions .github/workflows/play_closed.yml` (must still pass — any new `uses:` you add must be pinned via the manifest).
