폴더별 CANONICAL_LOCK.json과 STYLE_LOCK.json이 위 파일을 완성 외관의 정본으로 등록한다. 투명 PNG를 재인코딩하지 않고 복사했다. 원본 알파·색·크기·시점·캔버스 여백을 유지한다. 앱 최종 단계는 assets/illustrations/personal_hanok_v3/construction/ 아래에 같은 바이트로 복사한 PNG를 사용한다.

중간 공정 31장을 실제 채색 PNG로 제작하고 완성 정본 3장과 함께 Flutter 앱에 연결했다. 안사랑채 14·사당문 8·사당 12단계 모두 투명 배경이다. PNG 생성에는 image_gen을 사용하고 임시 배경 제거는 알파만 수정했다(RGB 변경 0픽셀). 완성 원본은 재생성하지 않았다. 기존 SVG 화면은 역사적인 구조 가이드이며 앱에 사용하지 않는다. 앱은 IlDuConstructionArtCatalog, IlDuConstructionScreen과 단원 완료 SoriStageRewardReceiptSheet에서 실제 PNG를 읽는다. 중간 원화의 검토 주체는 에이전트이고 세 완성 정본의 승인자는 Jin이다.

## 앱 진행 연결

기존 B2 단원 중 검증된 최초 완료 비율로 34공정을 계산한다: floor(B2 완료 비율 × 34). 현재 실제 B2 6단원에서는 0→5→11→17→22→28→34이며, 한 단원이 여러 세부 공정을 진행할 수 있다. 1–14는 안사랑채, 15–22는 사당문, 23–34는 사당이다. 건물 경계를 넘으면 각 건물의 전후 이미지를 나누어 보여준다. 우회 완료와 다시 보기는 진행을 만들지 않는다. 상세에서는 34공정을 개별로 다시 보고 한·영·독 설명을 읽는다.

사용자가 지정한 솟대울문 보관본의 HTML과 12개 실제 PNG 제작 기록을 파일에서 확인했다. 그 HTML은 검토용이며, 여기서는 같은 실제 원화 제작 방식을 Flutter 소비 경로에 적용한다.

## 참고 화면에서 가져온 것

사용자가 제시한 [아래채 공정 6단계](http://127.0.0.1:8879/docs/mockups/four-buildings-construction-29/index.html?building=araechae&stage=6&lang=en)의 5·6단계를 확인했다. 건물 탭, 단계 목록, 완성본 겹쳐 보기, 한국어 한 문장과 선택 언어 설명, 공간을 관찰하는 짧은 글을 참고했다.

참고 묶음의 29도 목표 시점은 이 세 정본의 카메라를 바꾸는 지시가 아니다. 각 승인 PNG의 현재 투영과 캔버스를 유지한다. 참고 화면에서도 지적된 기둥 축과 기단 깊이 변화를 막기 위해 단계별 별도 좌표를 허용하지 않는다.

## 부재가 어긋나지 않는 구조

구조 설계 가이드는 건물마다 하나의 geometry.nodes와 geometry.members를 공유한다. 실제 PNG는 승인 원본과 해당 건물의 앞선 공정을 참조해 같은 해상도·캔버스에서 생성했다. 앞쪽 기둥 수, 지붕 형식, 설치 순서와 생활 공간은 육안 대조했다. 생성 이미지 사이에는 미세한 부재 차이가 있으므로 가이드 좌표 검증을 실제 PNG의 0px 정렬 증거로 제시하지 않는다.

| 연결 | 같은 점·경계로 고정하는 관계 | 제작 시 확인할 내용 |
|---|---|---|
| 기단 → 초석 → 기둥 | 초석 접점 = 기둥 발 | 기둥 밑면이 초석에서 뜨거나 돌 안으로 파고들지 않는다. |
| 기둥 → 보 | 기둥 머리 = 보 끝 | 앞뒤 열의 높이와 기둥 굵기를 유지하고 보가 실제 지지점에 닿는다. |
| 보 → 도리 | 기둥머리·보 중앙에서 도리·마루도리로 이어지는 지지 관계 | 가려진 동자주·대공 등의 구체 형식은 도면 근거를 확인한 뒤 그린다. |
| 도리 → 서까래 | 서까래의 지지점 = 도리의 선상 점 | 서까래가 뜨거나 도리를 통과하지 않는다. |
| 앞·뒤 지붕 | 같은 용마루 절점 | 앞뒤 지붕이 서로 다른 중심선을 갖지 않는다. |
| 서까래 → 지붕 바탕 → 기와 | 같은 곡면과 처마 경계 | 부재 위로 실제 두께를 쌓는다. 기와를 깔면서 처마를 옮기지 않는다. |
| 문틀 → 문짝 | 같은 문짝 회전축·두께 | 문을 열었을 때 벽·기둥을 관통하거나 통행 공간을 막지 않는다. |
| 마루틀 → 청판 | 같은 바닥 높이·귀틀 끝·받침 | 마루 아래 빈 공간과 옆면 두께가 살아 있어야 한다. |

현재 JSON의 지붕 앞뒤 각 9개 선은 정렬을 검사하는 단면 위치다. 역사적 서까래 수가 9개라는 뜻이 아니다. 실제 공정 원화에서는 정본의 촘촘한 서까래 리듬을 복원하고 같은 곡면 안에서 배치한다. 가려진 뒤 기둥·도리 지지·벽 두께·문 회전은 학습용 재구성이고 실측 좌표가 아니다.

가시 기준점은 원본 픽셀 좌표에 작성했고 자동 검증은 그 좌표의 공유·범위·연결을 검사한다. 초기 설계의 2px 정렬 목표는 실제 PNG에서 계측 완료한 결과가 아니다. design_validation은 공유 설계 관계를 검사하고 ART_MANIFEST는 실제 파일·해시·알파·원본 RGB 보존을 검사한다.

## 2.5D와 사람이 쓰는 공간

안사랑채는 정면 4칸과 앞뒤 기둥열 사이에 생활 공간을 둔다. 왼쪽 닫힌 칸, 뒤로 물러난 창호, 대청과 앞·옆 툇마루를 같은 앞면에 붙이지 않는다. 오른쪽 열린 툇공간과 마루 아래는 투명하게 남긴다. 승인 정본의 (1330,590), (1419,759) 알파가 0인지 검사한다.

사당문은 실제 문기둥 두 개를 사용한다. 앞·뒤 면은 그 두 기둥의 두께를 표시하며 뒤 기둥 두 개를 추가하는 근거가 아니다. 얕은 지붕·문틀·문짝과 낮은 돌받침 사이로 사람이 지나갈 공간을 둔다. 안방·온돌·대청을 이 문에 복제하지 않는다.

사당은 정면 3칸과 둥근 앞 기둥 네 개, 뒤쪽 구조, 후퇴한 창호, 마루, 공포와 맞배지붕을 유지한다. 안사랑채의 팔작 모서리 지붕을 옮겨 붙이지 않는다. 사람이 들어가 조상을 기리던 실내 공간으로 설명하되 특정 제기·신주 위치와 의례 동선은 추가 자료 없이 만들지 않는다.

앞쪽 기둥은 뒤의 벽과 마루를 가리고, 처마는 기둥 윗부분에 그늘을 드리우며, 벽은 방 안을 가린다. 지붕을 열거나 벽을 걷어 보는 동작은 별도 설명 보기다. 기본 공정 원화의 건물을 평면으로 펼치지 않는다. 마루·벽·창호를 더할 때 앞뒤 깊이를 압축하거나 그림 전체를 확대하지 않는다.

## 원화 제작 순서와 검수

1. 완성 원본 세 장을 잠근다. 변경된 원본은 도구가 거부한다. 기존 원본 알파 추출 스크립트도 승인 잠금이 있으면 실행을 중단한다.
2. 각 건물의 기단 모서리·초석·기둥 머리·지붕 곡선과 공간 구획을 같은 캔버스에 놓는다. 가려진 부재는 단면과 도면으로 확인한다. 이 등록 설계 자체를 3D 실측값으로 취급하지 않는다.
3. 기둥·보·도리·서까래가 함께 연결된 구조 공정을 먼저 제작·대조한다. 집 두 채는 앞뒤 기둥열과 방 높이를, 사당문은 두 기둥과 문틀 두께를 확인한다.
4. 통과한 구조와 완성 정본을 기준으로 나머지 공정을 파생한다. 이미 설치된 부재는 같은 위치·굵기·재질로 유지한다. 새 부재에 가려질 때만 가시 영역이 바뀐다.
5. 기와와 벽으로 덮기 전 구조를 점검한다. 방, 마루 아래, 옆 통로, 문 회전 공간을 확대해서 본다. 승인된 건강한 목재·온전한 기와·정돈된 창호·단청을 유지한다.
6. 각 단계와 직전 단계의 기둥·기단·처마를 같은 캔버스에서 대조한다. 서까래가 너무 일찍 나타난 결과와 기둥을 늘린 사당문 결과는 폐기했고, 지붕 바탕 위에 목재가 잘못 놓인 결과도 다시 수정했다. 픽셀 단위 정렬 오차 계측은 이 검사의 범위가 아니다.
7. 마지막 단계는 원본 PNG를 직접 사용하고 SHA-256을 비교한다. 완성 단계용 이미지를 새로 생성하지 않는다. 중간 원화가 완성된 뒤에만 런타임 소비 경로와 묶음 등록을 진행한다.

이미지 수정·드로잉은 이미지 생성 도구로 진행한다. 승인된 Python 알파 작업을 RGB 채색이나 건물 재작성으로 확대하지 않는다. 정본의 새 버전이 필요하면 별도 경로에서 생성하며 기존 파일을 덮어쓰지 않는다.

## 학습 동작

단원 최초 완료 때 직전 공정과 다음 공정을 보여준 뒤 한국어 용어, 짧은 문장을 읽는다. 상세 설명은 한국어·영어·독일어로 다시 볼 수 있다. 관람·재생·언어 전환·상세 다시 보기는 XP, 학습 진도, 다음 건물 승인을 만들지 않는다. 데이터의 observe는 학습자가 공간을 살펴보는 글이고 productionNote는 제작자의 정렬·원본 고정 기준이다. 아래 표의 마지막 열은 제작 기준이며 학습자용 문장은 설계 화면과 데이터에서 확인한다.

중간 상태를 특정 문화재의 실제 시공 일지로 소개하지 않는다. 학습을 위한 묶음이며 온돌 단면·문 여닫힘·생활 모습은 구조를 이해하는 별도 설명이다. 문장은 한국어 의미를 먼저 고정하고 영어·독일어의 화행과 기술 의미를 맞췄다. 이 검토는 MODEL_QA_PASS 범위이며 원어민 사용자 검수 완료를 뜻하지 않는다.

## 검증

실제 번들, 9개 건물 시리즈, B2 최초 완료와 건물 경계, 리시트, 학습 언어 전환, 스크롤 유지, 데모의 무저장 동작을 포함한 Flutter 테스트 59개가 통과했다. 전체 Flutter 정적 분석도 통과했다. PNG 등록 계약 테스트 3개와 STYLE_LOCK 테스트 10개가 통과했으며, 마지막 관찰 문구 수정 뒤 관련 Flutter 테스트 11개를 다시 실행했다(59개에 포함).
