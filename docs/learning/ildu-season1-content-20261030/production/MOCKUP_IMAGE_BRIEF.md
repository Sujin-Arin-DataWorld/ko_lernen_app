## 1. 고정할 이야기와 디자인

- 첫 장은 `F0.1.sound-signs → F0.1.above-below → F0.1.straight-lines`다. `아·어 → 오·우 → 으·이`를 순서대로 다루며, 같은 연습 보드에 실제 문항을 교체한다. 첫 아 조립은 도움 연습이고, 그 뒤 아바타의 극중 낭독으로 탈선비가 깨어난다. 사용자의 발음 점수·녹음 제출이 각성 조건이 아니다.
- 문지기 `LQ-05`는 **중문간채 중간**에 있다. 이미 아는 도깨비와의 역할 놀이이며, 실명·출신 공개나 여섯 단원 만점이 통과 조건이 아니다. 실제 본편 준비 상태가 아직 없으면 대화 연습으로만 제공한다. 문지기 결과에 완공 `S1-E04`, 폭풍, 기억30%, 12공정 완료, 엽전 지급을 합치지 않는다.

준비 확인은 해당 목표의 선행 시범·P, 설명 언어의 안내, 조각 선택→자리 선택 조작 경험과 실제 음성 가용성을 확인한다. 부족하면 해당 T/P로 돌아가고, 음성이 없으면 듣기 평가를 제외한 글자 연습·이야기 경로를 제공한다. 도움·정답 노출과 첫 응답을 별도로 보존한다. **24장은 전체 흐름을 검토하는 대표 상태 캡처 수**로, 모든 가르치기/P/준비/문항 전환을 각각 24장 안의 새 전면 화면으로 세거나 필요한 학습 활동을 삭제한다는 뜻이 아니다. 화면 틀 10종·상태 캡처 24장 수는 유지한다.

## 3. 먼저 만들 두 장면의 조합 명세

### 1순위 M02 — 공부책의 첫 장

의도: “한국어를 모르니 시험을 치러야 한다”보다 “동료와 책을 열고 첫 소리를 함께 만든다”가 먼저 읽혀야 한다.

- 390×844 기준 상단에는 작은 위치·돌아가기, 중앙에는 펼친 공부책의 빈 첫 장과 **ㅇ·ㅏ만** 둔다. 하단은 선택 언어의 짧은 안내와 금색 `시작해요 / Start / Starten`, 보조 `소리 듣기 / Listen / Anhören`다. 본문은 UI 텍스트로 얹고 생성 이미지 안에 구워 넣지 않는다.
- 수진은 검증한 `Persona/sujin1.png` 원본을 같은 비율로 사용한다. 이 포즈는 책을 들고 한 손을 턱에 댄 자세다. 새 손동작·얼굴·의상을 그리지 않는다. 인물의 한쪽과 책 사이에 실제 접촉 그림자를 두되 글자 슬롯·안내·CTA를 가리지 않는다.
- 배경은 책·한지·목재의 가까운 장면으로 새로 조합한다. **완공 사랑채 외관을 착공 전 배경으로 사용하지 않는다.** 승인된 내부/서안의 정확한 원본을 다음 제작에서 확인하기 전에는 특정 실내가 정본이라고 쓰지 않는다. 필요한 신규 제작은 캐릭터 없는 공부책·페이지 소품이다.
- 탈선비는 아직 등장하거나 말하지 않는다. 조이의 책 발견은 원고에서 왔지만 현재 이 장면용 정확한 조이 포즈는 미매핑이므로, 임의 까치 그림을 선택해 대신 넣지 않는다.
- 비교할 상태는 시범 전 M02와 M03의 도움 조립이다. 올바른 음절은 P 시범에만 제공한다. I 첫 응답 화면에 완성 정답·뜻풀이가 먼저 노출되지 않게 한다.

향후 제작 입력: `M02 + source A01 + prop P01 + text U1-D01/U1-D04 + C-START/C-LISTEN`. 캐릭터는 합성 단계에서 원본을 배치하며, 새 책 소품 생성에 인물·건축 재생성을 섞지 않는다.

### 2순위 M08 — 중문간채 중간의 문지기

의도: 친한 동료 도깨비의 작은 장난에 자기소개와 되묻기가 필요해지는 장면이다. 거절하면 막히는 신원 확인 화면으로 보이지 않아야 한다.

- 장면 기준은 R16 `jung/stages/06.png`의 **터·기단·목구조·지붕 바탕 상태**다. 원본은 800×533 RGB 검토 렌더로, 회색 검토 배경과 현재 카메라를 갖는다. 이미지를 그대로 확대해 전면 게임 배경으로 쓰기보다 같은 native geometry·같은 공정을 유지한 카메라/배경 조합이 필요하다. 렌더 작업은 이번에 하지 않았다. numeric sequence6와 이야기 중간 훅의 결합은 원고의 제안이므로 실제 트리거를 확정하지 않는다.
- 도깨비는 검증한 `도깨비확정/1.도깨비다른포즈.png`를 사용한다. 현재 검증 포즈는 방망이에 한 손을 얹고 다른 손을 턱에 댄 자세다. 원고의 ‘팔을 벌림’과 일치하는 기존 포즈는 미매핑이다. 첫 검토에는 원본 포즈 그대로 배치하고 이 간극을 주석으로 표시하며, 팔을 새로 그리지 않는다.
- 위쪽 장면에는 도깨비와 여유 있는 통로, 아래 한지에는 “오늘은 내가 문지기다. 누가 왔는지 들어 볼까?”의 선택 언어 자막을 둔다. 수진은 작은 도움 호출부에 원본 portrait를 사용한다. 주요 행동은 `연습 카드로 시작 / Use a practice card / Mit Übungskarte starten`, 보조는 `도움받고 계속하기 / Continue with help / Mit Hilfe weiter`다. CTA는 인터페이스 후보 문구이며 사람 현지화 검수 전이다.
- 역할 카드 `하린`은 원고의 임시 연습 이름이다. 실제 이름 입력·출신·녹음 권한 요청 없이 진행 가능하다. 수진 대리 소개에서는 “제 친구예요. 같이 왔어요.”를 쓰고 독립 자기소개는 미평가로 남긴다.
- 본편이 준비되지 않았을 때는 중간 상태를 실제 소유한 것처럼 전시하지 않는다. 같은 기능의 대화 연습 카드와 `지금은 대화 연습이에요` 안내를 보여 주는 M08-B를 별도 검토한다. 폭풍·인영·연이 이름·기억30%·완공·보상은 이 장면에 없다.

향후 제작 입력: `M08 + A01/A03/A05 + prop P02 + LQ-05 차례1–3`. 건축은 기존 native/render 재조합 대상이고, 일반 이미지 생성으로 새 중문을 그리는 대상이 아니다.

## 7. 확인한 근거와 제작 완료 판정

현재 소스 조사 범위는 `c-app-integration-20261012` HEAD `2d68784d3b642a14fe174de26d55b0c82209a694`, `lernpfad-v2-20261023` HEAD `6fadd838e2a8ad378b92b38d06d86541782a7db8`의 관련 파일이다. 좁은 읽기와 원본5개 픽셀·해시 점검만 수행했다. 타 체크아웃 WIP를 변경하지 않았다.

- `lernpfad-v2`의 `main.dart:1403`에는 `/path`·`/path/v2`·`/path/foundation`이 있고 `FoundationLessonScreen`은 실제 저장 대기·실패·복귀를 처리한다. 본 브리프의 M02–M10 이야기 구성이 그 화면에 이미 구현되었다는 뜻이 아니다.
- `c-app`의 `/hanok/construction`은 `IlDuConstructionScreen`, `ildu_construction_art.dart`는 `assets/data/ildu_construction_art_v1.json`을 읽는다. 이 자료는 협문·창고의 단일 뷰 건축 학습이며 R16 11동 전체·시즌 퀘스트 UI와 동일하지 않다.
- 수진 runtime `assets/illustrations/personas/v3/sujin.png`는 선택 원본과 같은 SHA다. 현재 tactile 탈선비·도깨비 파일은 이번에 선택한 정본 portrait와 SHA가 다르다. 다른 파일을 같은 원본이라고 부르거나 이 계획으로 교체하지 않았다.
- 오래된 `CANONICAL_SOURCES.json`의 `TalSunbi`, `도깨비` 경로는 현재 각각 `탈선비확정`, `도깨비확정`으로 확인되었다. 선택한 두 파일은 기존 기록 SHA와 같았다. R16 계약의 `review/…` 경로는 로컬 보존본 `family-r16/…`에서 같은 SHA로 확인했다. 과거 인벤토리를 현재 경로의 증거로 그대로 사용하지 않았다.

2026-10-30 확인한 공식 기준은 [Android 접근성 가이드](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility)의 48dp 터치 영역, 제스처 외 조작 대안, 본문 대비 기준이다. 해당 페이지 갱신일은 2023-05-08이며 ‘2026년 새 표준’으로 부르지 않는다. 적용 판단은 드래그 전용 대신 탭 조립, 그림자만으로 상태 전달 금지, 48dp 도움/재생/다음 버튼이다. Apple Motion 문서는 이 작업에서 내용을 확인하지 못했으므로 읽었다고 기록하지 않는다.

읽고 적용한 스킬은 `microinteractions`(트리거·규칙·피드백·반복/모드 명세)와 `mobile-native`(작은 화면·safe area·키보드·실기기 판정의 분리)다. 웹 CSS 예시를 Flutter 코드에 적용했다고 주장하지 않는다. **Microinteractions 현재 점수는 미평가(N/A)**다. 화면/프로토타입이 없으므로 8개 진단의 통과·실패나 10/10을 꾸며 내지 않는다. 다음 검토에서 ①발견 가능한 트리거 ②상태 표시 ③예측 가능한 규칙 ④즉시 피드백 ⑤반응 크기 ⑥복귀/장기 변화 ⑦모드 가시성 ⑧첫 사용 이해를 실제 조작으로 확인하고, 실패한 항목과 수정안을 기록한다.

다음 단계의 완료 근거는 순서대로 **원본/상태 매핑 → 연결된 Figma 정지·인터랙션 검토 → 같은 뷰포트 실제 Flutter 렌더 비교 → 조작·저장·TTS/영상·기기 검증 → 사용자 승인**이다. 현재 문서는 그 첫 단계의 제작 브리프다. C안 100% 일치, native 통합, 학습 효과, 릴리스 완료를 판정하지 않는다.
