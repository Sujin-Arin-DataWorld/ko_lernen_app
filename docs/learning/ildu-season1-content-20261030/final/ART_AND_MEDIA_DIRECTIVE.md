# 이미지·에셋·영상 제작 지침

[최종 결정](FINAL_DECISIONS.md) · [기존 에셋 상세 목록](../production/asset-lock/ASSET_LOCK_LIST.md) · [영상 제작 전문](../production/VIDEO_PRODUCTION_PLAN.md).

## 1. 현재의 제작 순서

**이미지 생성 스킬/도구로 완성 앱 화면 이미지 → 이미지 전체 검토 → 편집 가능한 Figma → 후속 앱 코드.**

사용자는 HTML 선행 작업과 낮은 품질의 조합식 화면을 여러 번 거절했다. HTML·CSS·Flutter 배치부터 다시 만들지 않는다. 단색 배경 위에 인물과 건물을 따로 세워 둔 화면, 빈 배경·부분 소품·빈 대화창만 생성한 것은 완성 목업으로 세지 않는다.

한 장에서 **살아 있는 장소·고정 인물·현재 사물·한 차례 대화·다음 행동**이 같이 읽혀야 한다. 배경 없는 카드 전시를 RPG 장면으로 대신하지 않는다. 각 화면의 인과와 보조 상태는 원고/상태표에 연결한다.

## 2. 승인 C안의 미술 기준

청록의 안정된 헤더, 크림 한지, 오래된 목재, 절제된 금색, 실제 물건처럼 느껴지는 두께·접촉 그림자·조명이 중심이다. 전경 사물, 중경 인물, 원경 마당/산/경계가 같은 카메라와 광원을 공유해야 한다. 책과 손의 거리, 발과 바닥, 서안 다리의 접지를 확인한다.

상단 표제보다 장소와 행동이 먼저 읽혀야 한다. 출발 제안은 장면 약60~65%, 대화/행동 약30~35%지만 고정 비율은 아니다. 독일어가 길면 줄바꿈과 패널 공간을 조정한다. 화면을 채우려고 글자를 작게 하거나 가로 압축하지 않는다.

정규 검토는100% 글자 크기다. 작은 화면·큰 글자는 별도 QA로 표시한다. 48dp 조작, safe area, 본문 대비, 키보드가 가리지 않는 확정 행동은 후속 편집/구현의 검토 조건이다. 정지 이미지에서 터치·접근성 동작을 통과했다고 쓰지 않는다.

‘2026년 최신’은 새 유행으로 브랜드를 바꾸는 뜻이 아니다. 공식 플랫폼의 현재 가독성·재료·반응 지침을 C안에 맞게 해석한다. 기존 계획의 확인일/출처를 보존하되, 과거 확인을 모든 미래 서비스 기능·요금·플랫폼 동작의 현재 검증으로 쓰지 않는다.

## 3. 캐릭터와 소품 고정

정확한 파일/해시는 [CHARACTER_LOCK](../production/asset-lock/CHARACTER_LOCK.json), [ASSET_LOCK_MANIFEST](../production/asset-lock/ASSET_LOCK_MANIFEST.json), [후속 source manifest](SOURCE_MANIFEST.json)로 찾는다. 이미지가 폴더에 있다는 사실만으로 정본 역할·표정 승인이 되지 않는다.

- 얼굴·헤어·의복·모자·탈·몸 비율·소품 문양과 재질을 고정한다. 원본은 덮어쓰지 않는다.
- 새 표정·자세는 최신 사용자 허용 범위에서 **별도 후보**로 만들고 정체성 일치를 검토한다.
- 탈선비의 하회탈을 일반 살색 얼굴로 바꾸지 않는다. 조이의 갓·두 날개를 보존한다. 도깨비 머리띠·의상·방망이의 구름 디테일을 임의로 바꾸지 않는다.
- 첫 공부책은 낡은 한지책 한 권이다. 현대 양장 책 더미는 reference-only 자료이며 연이의 공부책으로 승격하지 않는다.
- 사용자 제공 열린 책 이미지와 지도는 물성·장면 깊이의 참고다. 이미지를 참고했다는 이유로 현재 진도·잔액·공정 상태까지 복사하지 않는다.
- 신수 구름 배지, 건축 수호기와, UI 구름, 연이의 사적 살림 물건을 분리한다. 동일 소용돌이를 모두에 찍지 않는다.

생성 도구의 참조 입력은 출력의 픽셀 동일성 보증이 아니다. 원본을 참조해 전체 화면을 생성하되, 건축/인물 디테일이 달라진 후보는 승인 정본을 바꾸는 근거로 쓰지 않는다. 나중 Figma에서 원본 층과 실제 글자로 복원하는 단계 역시 별도 검수한다.

## 4. R16 사용 계약

제작 정본은 현재 main의 [R16 등록](../../../hanok_r16/CANONICAL_PROMOTION_R16.json)과 [투명 표시·보존 안내](../../../hanok_r16/presentation/README.md), 이 패키지의 [BUILDING_LOCK](../production/asset-lock/BUILDING_LOCK.md), [최신 source lock 사본](sources/season1-r16-source-update-20261031/R16_PRESENTATION_SOURCE_LOCK.json)을 함께 확인한다. 경로 변경은 현재 저장소에서 다시 조회한다.

확인된 집계는11동128공정과 고유 원본 이미지135개다. 이미지 수와 공정 수가 다른 것은 완성/전체 뷰·참조 중복 등을 구별하기 때문이다. 새 투명 foreground/shadow는 **사랑채16공정** 범위가 확인됐다. 다른10동까지 투명본이 준비됐다고 쓰지 않는다.

사랑채 보유0·1에는 건물과 건물 스튜디오 그림자를 표시하지 않는다. 다른 동의 첫 공정에 실제 기단이 있다면 그 원본을 보존한다. 첫 공부책은 착공 전이므로 완공 사랑채·실내·처마·등불을 앞당겨 놓지 않는다. 경계 대문·담장을 임의 재설계하지 않는다.

사랑채 foreground/shadow는 같은1800×1200 전체 캔버스·contain 사각형·정렬로, **그림자 multiply → 전경 source-over** 순서로 표시한다. 각각 잘라 맞추거나 새 색조/톤매핑·UV/기하 변경을 하지 않는다. 다른 동의 RGB 원본을 잘라 새 투명 정본이라고 부르지 않는다. 원본 스튜디오 이미지의 상세 보기와 자연스러운 현장 합성은 다른 제작 조건이다.

중문06은 실제 R16 구조 참고이며 문지기 이벤트의 확정 번호가 아니다. 공정별 실제 이야기 트리거와 현재 누적 코스 요구는 별도 연결 과제다. 시안의0/36·코인0·임의40엽전 버튼을 사용자 실제 장부로 복제하지 않는다.

## 5. EN/DE와 서체

현재 기본 방향은 **영어/독일어 제목 Lora Medium500, 본문 Source Sans3 400, 버튼/화자 Source Sans3 600**이다. 한국어 학습 문자는 Noto Sans KR, 한국어 서체 검토용 제목은 마루부리 계열이다. 한국어 비교판은 앱 지원 언어를 추가하는 작업이 아니다.

영어와 독일어는 같은 서체를 쓰되 언어별 줄바꿈을 따로 잡는다. 설명은 기본 왼쪽 정렬, 장식적 제목은 한 화면의 핵심 한 곳에 사용한다. 참고 기준은 EN/DE 제목24px/1.3, 본문17px/1.45, 버튼17px, 보조 정보 최소14px다. 실제 화면에 따라 검토할 값이지 생성 이미지가 이 수치를 정확히 준수했다는 측정 결과가 아니다.

**완성 화면을 이미지 생성기로 만들 때 그려진 글씨는 실제 TTF 사용 증거가 아니다.** 생성 단계는 분위기·전체 UI·짧은 문구의 후보를 보여 준다. 이후 확정 이미지/Figma의 실제 텍스트 층에서 지정 TTF·독일어 움라우트/ß/ẞ·한글 자모/받침·잘림·줄바꿈을 확인한다. 이 이유로 HTML 선행 제작을 다시 시작하지 않는다.

## 6. 짧은 연출을 넣을 곳

| 사건 | 필요한 반응 | 읽기/학습 중 안정시킬 것 |
|---|---|---|
| 책 발견/열기 | 책장·시선·짧은 카메라 접근 | 글자·응답·도움 위치 |
| 첫 아 복원 | 먹빛/책의 짧은 반응 → 탈선비 등장 | 조립 입력 중 글자 흔들림/스케일 변화 없음 |
| 동료 재회 | 놀람·익숙한 농담·잠깐의 침묵 | 한 화자 한 차례, 즉시 전체 표시 |
| 문지기 재요청 | 같은 내용 재생 → 도깨비가 비켜 섬 | 대사·이름 카드·질문 유지 |
| 기억 공개/폭풍 | 제한된 시점의 짧은 기억 겹침 | 다음 단서 선공개 없음 |
| 첫 등불·신수 구조 | 실제 사건이 달라지는 키프레임 | 반복 정답 이펙트로 남용하지 않음 |
| 마지막 편지·빗장 | 침묵·첫 대답·문 수리·귀가 | 대사 완문과 두 대답의 구분 |

읽는 동안 계속 떠다니는 장식, 오답 흔들림·벌점 진동·경쟁 효과음은 피한다. 오프스크린/백그라운드에서는 멈추고, 동작 줄이기·무음·스킵·영상 실패에서도 같은 사건과 다음 행동을 전달한다. 효과를 건너뛰는 것과 필수 대사를 없애는 것은 다르다.

## 7. 어디서 어떻게 영상으로 만들 것인가

제안된 역할 분담은 **정확한 건물·문·빗장은 승인 Blender/R16 장면**, **인물의 제한된 반응은 정본/검토 포즈**, **바람·안개 등은 참조 이미지 기반 짧은 생성 영상 시험**, **컷·소리·자막·10초 길이는 편집 프로젝트**다. Google Flow/Runway 등은 비교 후보이며 계정·현행 기능·요금은 실제 생성 직전에 확인한다. DaVinci Resolve 등에서 최종 편집하는 방안은 [기존 전문](../production/VIDEO_PRODUCTION_PLAN.md)에 있다.

한 번의 생성에 정확한 건축·손 접촉·긴 대사·자막·3컷·10초를 모두 맡겨 일관성을 보장하지 않는다. KO 음성에 선택 언어 자막 한 층, 포스터 프레임, 무음 설명을 준비한다. 정지 키프레임이 생성됐다는 이유로 실제 애니메이션 파일과 재생 검수를 완료했다고 쓰지 않는다.

본편 A와 쿠키 B는 각각 **편집 마스터10초 제안**이다. 긴 완문은 전문 부록에 보존하고, 첫 대답과 태고/조이의 연결 대사는 A 직전 본편에서 끝까지 전달한다. 아직 녹음·렌더·사람 감수 타이밍이 검증된 완성 영상은 아니다.

## 8. 다음 단계의 완료 증거

이미지는 장면·언어·이야기 상태·원본 참조·후보 지위를 기록한다. Figma는 편집 가능한 아트 층/실제 텍스트/행동/오류·복귀 상태가 있어야 한다. PNG 한 장 배치만으로 image-to-code가 끝난 것이 아니다. Flutter에서는 실제 콘텐츠·저장·오디오·평가·보상 소유권과 연결된 조작을 확인한다. 이미지 승인·Figma·앱·실기기·main CI·스토어 배포는 각각 따로 판정한다.
