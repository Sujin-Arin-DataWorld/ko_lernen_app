# 최종 결정과 이전 문서의 수정 우선순위

기준일: 2026-10-31. [전체 색인](README.md).

우선순위는 **최신 사용자 직접 지시 → 현재 확인 가능한 파일/계약 → v3.5 서사 정본 → 후속 집필/편집 제안 → 과거 탐색본**이다. 제작 범위를 바꾼 지시와 서사 사실을 바꾼 지시는 구별한다. 새 인물·반전·경제 규칙을 임의로 정본에 추가하지 않는다.

## 1. 사용자가 직접 정한 방향

| 결정 | 구체적인 뜻 | 대체/제한하는 이전 방향 |
|---|---|---|
| 플레이어가 주인공 | 처음 정한 이야기 이름이 화자·호칭·후속 NPC 대화에 이어진다 | 크리스티안을 모든 사용자 대신 고정 주인공으로 두지 않음 |
| 첫 제작은 이름부터 | 외형 생성은 완성 시간을 고려해 뒤로 미룬다 | v3.5의 풍부한 아바타 설정은 장기 구상으로 보존 |
| 테일즈위버에서 원하는 것은 이어지는 인물 중심 챕터 | 개별 부탁이 하나의 본편으로 합류하고, 짧은 연출과 대화로 내 행동의 결과를 경험한다 | 2006년 UI·도트·전투·MMO를 그대로 복제하는 전면 전환이 아님 |
| 대화가 실제로 이어지는 느낌 | NPC가 이미 만난 나와 공개된 사건을 기억하고, 도움/재요청/상황 사용에 구체적으로 반응한다 | 이름만 바뀌는 독립 카드·모든 답에 같은 감사 한 줄 |
| 안내 언어 EN/DE | 한국어는 학습 글자·목표 표현·극중 KO 음성으로 사용한다 | 참고 이미지의 한국어 제목/설명을 그대로 앱 UI로 쓰지 않음 |
| 승인된 C안 유지 | 한지·목재·청록·금색, 촉각적 깊이·조명·접촉 그림자·읽을 수 있는 위계 | 평면 웹 카드나 유행 테마로 전면 대체하지 않음 |
| 기존 캐릭터와 건물 고정 | 얼굴·헤어·의복·탈·모자·소품·체형·건축 기하/배치를 유지하고 원본을 덮어쓰지 않음 | 폴더의 다른 후보를 정본으로 임의 교체하지 않음 |
| 새로운 표정·자세 허용 | 정체성을 보존한 별도 후보로 제작할 수 있다 | 과거 PLAN의 ‘새 포즈/표정 자체 금지’보다 최신 허용이 우선 |
| 완성 앱 목업을 이미지 생성 도구로 먼저 제작 | 배경·인물·책·대화 UI가 함께 보이는 완성 화면 이미지가 우선 산출물이다 | HTML/CSS 배치 선행, 부분 에셋/PIL 조합을 요구한 완성 목업 대신 납품하는 방식은 거절됨 |
| 순서: 이미지 → Figma → 코드 | 이미지 전체 검토 뒤 편집 가능한 Figma와 실제 텍스트·상태를 만들고 이후 앱에 연결한다 | HTML을 이미지 제작의 선행 단계로 삼지 않음. 현 단계 앱 코드 변경 보류 |
| 필요한 화면을 넓게 포함 | 입문·일두고택·본편과 도움/실패/복귀 등 필요한 상태를 함께 계획한다 | 초기 첫 공부책 20상태×2언어=40장 계획은 첫 구간의 목록이며 전체 범위 상한이 아님 |

위 방향의 확정과 개별 생성 이미지의 품질 승인은 별개다. 마지막 완성 화면 후보가 생성됐다는 사실만으로 나머지 전체 이미지·Figma·앱 작업이 끝났다고 기록하지 않는다.

## 3. 제작 자료에서 바로잡을 충돌

| 과거 기록/오해 | 최신 정리 |
|---|---|
| 과거 PLAN 머리말의 ‘사용자 미확정’ | 이후 사용자가 제작 진행을 요청했다. 목적/이미지 우선 방향은 채택됐으나 구형 합성 방법과 모든 세부 수량까지 최종 승인된 것은 아니다 |
| PLAN §5의 ‘배경만 생성하고 전체는 래스터 합성’ | 최신 사용자는 이미지 생성기로 **완성 앱 목업 화면 자체**를 만들라고 재차 수정했다. 이 방법을 현재 제작 기준으로 둔다 |
| 생성기에 Lora/Source Sans 3를 요청했으므로 실제 해당 폰트 | 생성 글씨는 유사 형태일 수 있다. 실제 TTF 조판·문자 검사는 별도이며 생성 이미지에 정확한 폰트 사용을 보증하지 않는다 |
| 고정 에셋을 참조했으므로 출력 픽셀/세부도 완전히 동일 | 참조 기반 생성은 재해석 위험이 있다. 원본 해시 보존과 출력의 시각 동일성 검토를 따로 기록하고 자동 승인하지 않는다 |
| 모든 건물 공정 1에 건물·그림자 없음 | 현재 확인한 숨김 계약은 **사랑채 보유 0·1**에 적용한다. 다른 동의 실제 첫 공정 기단을 임의로 숨기지 않는다 |
| 새 투명 묶음이 11동 전체 | 확인된 별도 foreground/shadow 카탈로그는 사랑채 16공정 범위다. 다른 10동 투명 전달 완료로 확대하지 않는다 |
| 지도 0/36 = 전체 시즌 공정 수 또는 사용자 현재 진도 | 36은 1막 공정 수와 구별해 읽으며, 첨부 0/36·코인 0은 시안 값이다. 현재 계정값으로 복제하지 않는다 |
| 중문06 이미지 = 문지기 이벤트의 확정 트리거 | 원본 공정의 구조 참고다. ‘중간’ 접점의 실제 processId는 구현 연결 과제로 남아 있다 |
| v3.5의 V2 맵 표현 | 과거 미술 구상 용어다. 현재 제작은 R16과 보존 계약을 사용하며 퇴역 V2 폴더를 재생성하지 않는다 |
| 첫 책에서 완공 실내·등불·탈선비를 동시에 표시 | 첫 아 복원 전은 착공 전 마당/책 상태다. 탈선비는 복원과 극중 낭독 뒤 등장한다 |
| 쿠키 B가 v3.5 원문 그대로 | 빈 새 쪽·두 번 빛나는 배지·먼 지붕은 요청받은 변주다. 원래 수첩/현대 연락 한 컷을 별도로 보존한다 |

## 4. 확정하지 않은 것

- 신규 대사의 최종 사람 언어 감수, 성우 녹음, 정확한 10초 발화 타이밍.
- 이름 건너뛰기의 기본 호칭, 입력 길이/문자 정책, 실시간 이름 TTS 등 구체 UX/데이터 정책. 이름만 받는 방향과 이런 구현 세부의 승인을 혼동하지 않는다.
- 챕터 사실과 현재 공정·코스 요구량의 정확한 런타임 연결. 기존 누적 A1 요구와 새 입문 흐름의 충돌을 임의 패치하지 않는다.
- 후속 장면 전체의 완성 이미지, 편집 가능한 Figma, Flutter 상태 저장/보상/오디오/모션/실기기·릴리스 검증.
- 시즌 2 목적지의 이름, 노인의 더 깊은 정체, 배지 기원의 답. 열린 훅에 새 정답을 발명하지 않는다.

## 5. 보존하되 사용하지 않을 기준

거절된 HTML 탐색본은 [거절 기록 사본](sources/season1-rpg-prototype-20261031/REJECTED.md)으로 지위를 남긴다. HTML·JS·CSS 실행물을 이 문서 패키지의 디자인 기준으로 발행하지 않는다. 조합식 탐색 이미지·부분 배경·빈 UI 판도 완성 앱 화면으로 세지 않는다. 원본 파일을 파괴하거나 과거 문서를 고쳐 승인 이력을 꾸미지 않는다.

후속 문서에는 작성 당시 제안/현황이 그대로 남아 있으므로, 충돌할 때는 이 결정표와 최신 사용자 지시를 먼저 적용한다.
