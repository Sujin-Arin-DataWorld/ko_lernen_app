# 시즌1 이미지 제작·Figma 전달 파이프라인 검토

2026-10-31. 현재 범위는 계획뿐이다. 이미지 생성, HTML, Flutter, Figma 쓰기, 커밋은 실행하지 않았다.

권장 순서는 **장면·상태 설계 확정 → 대표 기준 컷 → 이름 입력·첫 책 복원·탈선비 각성 전체 화면의 EN/DE 이미지 → Figma 편집 레이어 복원 → 별도 Flutter 구현**이다. 현재 `book-de.png`는 질감·조명·폰트 참고로 읽었으며, 보이는 책 더미나 모든 구성을 신규 승인으로 승계하지 않는다.

1. **그려도 되는 영역과 보존할 영역을 먼저 분리한다.** `REFERENCE_FILES.json`의 수진·탈선비는 `IDENTITY_ONLY_POSE_SELECTION_SEPARATE`다. 정체성 참조를 새로운 포즈 승인으로 확대하지 않는다. 생성 모델에는 배경 공간·광원·빈 서안·효과판을 맡기고, 고정 캐릭터와 R16을 다시 그리도록 요청하지 않는다. 고정 PNG는 원본 레이어로 얹으며 위치·균일 배율·가림 순서를 기록한다. 원본 파일 해시 일치와 최종 합성 화면의 픽셀 동일성은 별개다. 배율 변경이 있으면 원본에 같은 변환을 적용한 기준과 비교한다.

2. **C안의 입체감을 공간으로 만든다.** 단색 면 위에 물체를 나열하는 구도를 피하고, 앞쪽 서안·책, 중간 캐릭터, 뒤쪽 착공 전 빈 사랑마당의 지면·원경·출처가 확인된 기존 경계 담장/대문의 깊이를 설계한다. 사랑채 벽·기둥·처마를 새로 만들지 않으며, 외부 경계 담장/대문의 기하도 생성 모델로 재생성하거나 바꾸지 않는다. 캐릭터 원본의 시선 높이·광원 방향에 배경을 맞추고 발·손·서안의 접촉과 가림을 연결한다. 수진 원본은 투명 PNG지만 주변에 부드러운 스튜디오 헤일로가 보여, 배경에 놓은 가장자리를 200%에서 확인해야 한다. 이를 없애려고 정본을 덮어쓰지 않는다. 마스크 파생본이 필요하면 별도 산출물로 표시한다. 원본에 없는 책 더미·장식·완공 건물을 자동으로 추가하지 않는다.

3. **대표 컷을 고정한 뒤 상태를 파생한다.** 첫 책 장면을 재질·카메라·주인공 비율의 대표 컷으로 먼저 제작한다. 같은 장소의 빈 배경판, 원본 캐릭터, 단일 책/서안, 전경 가림, 그림자, UI 재질, 글자를 분리한다. 같은 장면의 입력·복원 전/후·등장 상태에서는 배경을 다시 생성하지 않고 해당 레이어만 바꾼다. 이름 입력과 각성 장면도 이 카메라·광원·색 기준을 공유한다. 장소 전환이 필요하면 별도 배경판으로 명시한다. 이름 입력의 빈칸·입력 중·확인 가능·오류, 책의 복원 전·진행·복원 후, 각성 전·등장·첫 대사는 루트의 스토리/상태 계약과 대조해 제작 목록을 확정한다. 시각 효과가 학습 완료·보상 지급·건축 소유를 대신하지 않는다.

4. **생성 아트와 실제 TTF 조판을 나눈다.** 배경판에는 UI 글자를 만들지 않는다. 로컬 래스터 조판으로 전체 앱 화면 PNG를 완성하고, HTML은 만들지 않는다. 제목은 실제 Lora 500, 본문과 CTA는 Source Sans 3 400/600을 사용한다. 390×844dp를 제작 좌표의 제안값으로 두고 기존 뷰포트 결정과 대조한 뒤 고정한다. EN과 DE는 같은 아트 레이어·좌표를 공유하되 문장 줄바꿈과 필요한 텍스트 높이는 각각 조판한다. 독일어를 좁히거나 글자 크기를 낮춰 맞추지 않는다. 현재 TTF의 weight와 독일어 글리프는 확인했지만 내부 폰트 이름에 Regular/ExtraLight가 남아 있으므로 Figma에서는 이름만 믿지 말고 실제 굵기·줄폭을 검증한다.

5. **R16은 계약대로만 합성한다.** `R16_PRESENTATION_SOURCE_LOCK.json`의 사랑채 foreground/shadow는 1800×1200 같은 캔버스·동일 contain rect/alignment를 사용한다. shadow multiply 다음 foreground source-over이며 별도 크롭·색조 보정은 없다. 소유 0/1에서는 건축과 스튜디오 그림자를 그리지 않는다. 첫 책의 이른 시점에 완공 사랑채를 넣지 않는다. 사랑채 투명 묶음을 중문으로 대신하지 않으며, 중문 stage06은 구성 참고이고 런타임 트리거 증거가 아니다.

6. **검수는 통과 조건으로 기록한다.** 캐릭터·건물 재생성/변형, 승인 없는 소품, 앞당긴 이야기·진도·보상은 즉시 재작업한다. 100% 화면에서 얼굴·책·CTA의 우선순위, 텍스트 가림, 한 화면의 다음 행동을 확인한다. 200%에서는 헤일로·흰 테두리·접지·중복 테두리를 검사한다. EN/DE 아트 보호영역의 차이는 0이어야 하며 텍스트 누락·독일어 특수문자 누락·잘림도 0이어야 한다. 320dp와 큰 글자는 별도 QA 이미지로 만들고 일반 검토 화면과 섞지 않는다. 이 단계는 정지 이미지 검수이며 키보드·TTS·모션·저장·기기 QA 통과를 뜻하지 않는다.

7. **Figma에는 결과와 구조를 함께 전달한다.** 확정 PNG를 비교용 잠금 레이어로 두고, 별도의 편집 프레임에 배경/캐릭터/전경/카드 재질을 이미지 fill로, 제목·본문·입력·CTA를 실제 텍스트와 컴포넌트로 복원한다. 텍스트와 CTA 묶음에는 Auto Layout을 사용하고 장면 아트의 가림 순서는 별도 유지한다. PNG 한 장을 붙이면 이미지 fill이 생길 뿐 텍스트·상태·Auto Layout이 복원되지는 않는다. 현재 direct Figma 도구는 없고 Document Control 연결 세션도 0개여서, 이 단계는 연결과 실제 schema 확인 후 진행하는 후속 계획이다. `image-to-code` 스킬은 선택 이미지를 웹 프런트엔드로 구현하는 절차이며 Flutter 자동 변환 보증이 아니다. Flutter는 실제 앱의 컴포넌트·콘텐츠·상태 소유권에 맞춰 별도 구현하고 동일 뷰포트 캡처와 조작으로 검증한다.

최종 전달 묶음은 원본/SHA·폰트 manifest, 장면 기준표, 상태/복사문구표, 텍스트 없는 아트 레이어, EN/DE 전체 화면 PNG와 비교판, 320dp/큰 글자 QA, 보호영역·문자 검증 기록, Figma 레이어/컴포넌트 매핑표다. Figma node URL과 스크린샷은 실제 복원 이후에만 추가한다.

현재 직접 확인: 선택한 원본 8개 해시 일치, R16 16 foreground+16 shadow 해시 일치, 실제 TTF weight 500/400/600 및 ÄÖÜäöüß 누락 0. 전체 참고팩 59개나 앱 런타임 전체를 재검증했다는 뜻은 아니다. 루트의 증분 조사 결과는 `season1-rpg-direction-20261031/artifact-changes.json`을 사용한다.

공식 자료 확인일 2026-10-31: [Figma Image API](https://developers.figma.com/docs/plugins/api/Image/), [Auto Layout](https://help.figma.com/hc/en-us/articles/360040451373-Guide-to-auto-layout-in-Figma), [Code Connect](https://developers.figma.com/docs/code-connect/). Code Connect는 기존 코드와 디자인 컴포넌트를 연결하고 코드 문맥을 제공하는 기능으로 읽었으며, 전체 Flutter 앱 생성 완료로 해석하지 않는다.
