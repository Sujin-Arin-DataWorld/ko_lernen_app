# 일두 시즌 1 · RPG 앱 목업 이미지 제작 계획

2026-10-31 · **검토용 계획, 사용자 미확정**. 현재 단계는 브레인스토밍과 제작 설계다. 새 이미지·HTML·Figma·Flutter를 만들지 않는다. 이전 `season1-rpg-prototype-20261031`은 거절된 탐색본이며 구현 기준으로 사용하지 않는다. 삭제하거나 덮어쓰지는 않는다.

## 1. 목적과 순서

이름을 정한 사용자가 일두 이야기의 주인공이 되고, 자신의 작은 학습 행동으로 탈선비와 도깨비의 재회를 이끄는 순간을 보여 준다. 사용자가 정한 순서는 **계획 → 해당 흐름의 앱 목업 이미지 전체 → Figma의 편집 가능한 디자인 → 후속 코드**다. 이미지 이전의 HTML 배치, CSS 화면, Flutter 구현을 하지 않는다.

이번 필수 범위는 **이름 입력 → 첫 공부책 만남 → 도움받은 첫 `아` 복원 → 극중 낭독 → 탈선비 각성 → 도깨비와 첫 재회**다. 전체 앱·100단원·16레벨의 재설계로 확대하지 않는다. 원안의 산길·노인·배지 공명·신수 초대·대문 재회·비행(P1~P6)은 지우거나 새 설정으로 바꾸지 않는다. 이 여섯 사건의 신규 화면 전체 제작은 별도 확장 배치이며 이번 40장에 포함하지 않는다. 이 목업은 첫 책 구간 발췌이며 완성 프롤로그로 표시하지 않는다.

## 2. 무엇을 바꿔야 하는가

거절 화면의 문제는 단색 마당, 바닥·원경·접촉 관계가 부족한 인물과 서안, 지나치게 큰 책, 교재 카드처럼 분리된 학습판이다. 동작 검사가 통과해도 이 문제는 해결되지 않는다.

기존 `season1-scene-final-20261031/book-de.png`에서 계승할 것은 한지 두께, 목재 결, 피부·의복의 재료감, 절제된 광원과 실제 조판의 밀도다. 그 그림의 완성 실내와 현대 양장 책 더미는 착공 전 사랑마당의 정본으로 채택하지 않는다. 기존 책 PNG의 상태도 `REFERENCE_ONLY`다.

시각 방향은 **공간이 이어지는 2.5D 동화·모험 RPG**를 추천한다. 테일즈위버에서 사용자가 설명한 인물 중심 챕터와 대화의 호흡을 참고하며 원작의 도트·창·로고·아트는 복제하지 않는다. C안의 고정 인물·문화적 재료를 유지한다.

## 3. 장면 미술 원칙

### 공간이 먼저 읽혀야 한다

사랑마당의 땅, 서안 다리와 발이 닿는 자리, 뒤쪽 경계와 산·하늘의 깊이가 한 카메라로 연결돼야 한다. 전경은 서안과 공부책, 중경은 현재 대화 인물, 원경은 출처를 확인한 고택 경계와 자연 환경으로 구분한다. 인물만 크게 올리거나 배경을 색·그라데이션으로 대체하지 않는다.

고정 캐릭터의 원래 시선·광원·포즈를 기준으로 배경과 카메라를 정한다. 임의 포즈, 새 얼굴, 손 모양 변경으로 자연스러움을 만들지 않는다. 발·서안 다리의 접지, 책과 손의 거리, 전경 가림을 별도 레이어로 설계한다. 수진 원본의 헤일로와 탈선비 가장자리 fringe는 200%에서 검토한다. 처리에 원본 수정이 필요하다면 별도 파생본으로 구분하고 먼저 검토한다.

### R16과 이야기 상태를 지킨다

이번은 사랑채 착공 전이다. 공정 0·1에는 건물과 건물 그림자가 표시되지 않는다. 완성 사랑채·기둥·처마·실내 벽을 배경으로 새로 그리지 않는다. 경계 솟을대문·담장은 11동 건설과 다른 영역이지만 승인 기하를 임의 재설계하지 않는다. 사용할 배경 출처가 없으면 ‘공간 자료 미확보’로 기록하고 단색 대체품을 완성본으로 납품하지 않는다.

기존 R16 원본과 foreground/shadow 계약은 유지한다. 건축을 보여 줄 후속 장면에서는 같은 원본 캔버스·contain rect·정렬로 사용한다. 새 배경 생성기는 건물 실루엣·부재·배치를 재해석하는 도구로 쓰지 않는다.

### 책은 이야기의 물건이어야 한다

현대 양장 책 두 권 대신, 원문에 맞는 **낡은 한지 공부책 한 권**의 후보를 제작한다. 소박한 제본·사용 흔적·종이 두께를 갖추되 존재하지 않는 역사 유물로 소개하지 않는다. 새로운 책 후보는 기존 정본 자산과 구분해 검토한다. 생성기의 임의 한글·장식 문장·연이 전용 문장·신수 인장을 페이지에 넣지 않는다. 학습 글자는 실제 폰트로 나중에 얹는다.

### 화면은 한 번에 한 차례의 대화다

플레이어 시점으로 구성하고, 별도 주인공 얼굴·외형 생성기를 추가하지 않는다. 입력 이름은 내 말풍선의 화자와 수진/탈선비의 후속 호칭에 이어진다. 현재 장면과 책은 대화 중에도 남아 있어야 한다. 대화창이 장면 전체를 밀어내거나, 상단 제목이 그림을 압도하지 않게 한다. 시작 제안은 장면 약 60~65%, 대화·행동 약 30~35%, 작은 상태 정보 나머지다. 이 비율은 독일어 가독성에 따라 조정할 제작 판단이며 고정 픽셀 규칙이 아니다.

책 가까이로 이동하는 것은 복원의 의미가 있을 때만 쓴다. 학습판으로 완전히 갈아타지 않고 같은 책과 마당에서 시점이 이어지게 한다. 대사 한 차례를 읽고 자기 속도로 답하는 경험이 중심이다.

## 4. 제작할 화면: 12개 핵심 + 8개 보조 상태

**20상태 × EN/DE = 전체 앱 화면 PNG 40장.** 아래 번호는 제작 관리용이며 사용자 화면에 표시하지 않는다. 같은 아트를 공유하고 문구·상태를 파생하므로 40개의 배경을 각각 생성하는 계획이 아니다. 모든 대사 문장을 별도 이미지로 복제하지 않고, 남은 턴은 연결 대본표로 전달한다.

| 번호 | 핵심 화면 | 행동과 다음 반응 |
|---|---|---|
| S01 | 이야기 속 이름 입력 | 닉네임 또는 기본 호칭으로 시작. 외형·국적·성별 설정 없음 |
| S02 | 사랑마당 도착·내 이름을 부르는 수진 | 첫 책 구간임을 알리고 같은 공간에서 대화 시작. 앞선 P1~P6를 새로 겪었다고 진도 표시하지 않음 |
| S03 | 조이가 찾은 공부책과 첫 장 | 책을 펼치겠다는 내 응답 → 수진의 안내. 탈선비 없음 |
| S04 | 도깨비가 기억하는 책의 목소리 | 도깨비의 흐릿한 기억 → 내 질문/계속 → 수진의 복원 제안 |
| S05 | 수진의 시범 | `ㅇ` 왼쪽, `ㅏ` 오른쪽, `아` 모형. 첫 조립은 도움 연습 |
| S06 | 내가 책 위에 두 조각을 놓는 중 | 탭/배치할 대상과 현재 놓인 조각이 명확함. 같은 공간과 책 유지 |
| S07 | 첫 `아`가 되살아남 | 실제 조립 결과에 수진이 반응. 발음 점수·단원 완료·엽전 표시 없음 |
| S08 | 직접 읽기/함께 읽기 선택 | 조용히 읽기·지원 경로 허용. 음성 없는 경로도 같은 본편으로 연결 |
| S09 | 내 이름의 화자가 `아`를 읽는 순간 | 극중 낭독임을 표현. 실제 마이크 감지·녹음·발음 채점으로 오인시키지 않음 |
| S10 | 책에서 탈선비가 깨어나는 순간 | 복원/낭독 이후에만 빛과 인물이 나타남. 짧은 각성 모션의 대표 키프레임 |
| S11 | 도깨비와 탈선비의 첫 재회 | 놀람→익숙한 농담→외로움을 알아보는 대화의 대표 턴. 같은 마당 유지 |
| S12 | 새 제자를 맞는 탈선비 | 내 이름으로 다음 배움을 이어 줌. 전체 F0.1 단원을 마쳤다고 선언하지 않음 |

|---|---|---|

| A02 | 조각 위치 도움 | 수진의 구체적 시범과 같은 조각. 도움받았다고 불이익 없음 |

| A07 | 대화 기록·다시보기 | 이미 공개된 대사만. 각성·보상 중복 생성 표현 없음 |
| A08 | 동작 줄이기 | 빛의 폭발/이동 없이 같은 각성을 정지 장면·자막으로 전달 |

## 5. 이미지 제작 방법과 원본 보호

1. **출처표 고정:** 고정 PNG/R16/폰트의 정확한 파일과 SHA, 정본·참고·새 후보의 지위를 기록한다. 이미지가 폴더에 있다는 것만으로 승인된 역할·포즈가 되지 않는다.
2. **대표 장면 한 컷:** S03 첫 공부책 장면을 먼저 만든다. 이 한 장에서 고택 배경·인물 크기·책의 물성·원근·광원·하단 대사창을 함께 평가한다. 품질이 맞지 않으면 나머지 상태를 증식시키지 않는다.
3. **보호 레이어와 생성 영역 분리:** 이미지 생성 도구는 새 배경의 허용 영역·책 소품 후보·효과판에 사용한다. 고정 캐릭터와 건물은 생성 모델에 다시 그리게 하지 않는다. 완성 목업은 원본 PNG/R16 레이어의 직접 래스터 합성과 실제 TTF 조판으로 제작한다. 이 합성 방법을 계획에 명시하며, 전체를 이미지 생성기에 재해석시키는 방식과 구분한다. 캐릭터를 자르거나 가로로 늘리거나 재색칠하지 않는다.
4. **같은 장면 파생:** 검토된 빈 배경·카메라·광원·서안/책 위치를 재사용한다. 각 화면마다 배경을 새로 생성해 건축과 사물 위치가 바뀌게 하지 않는다. 인물 입장/퇴장·대사·조각·효과만 해당 상태대로 바꾼다.
5. **실제 글자:** UI는 EN/DE, 학습 대상만 한국어. 제목 Lora 500, 본문 Source Sans 3 400, 버튼/화자 Source Sans 3 600, 학습 글자 Noto Sans KR. 독일어 줄바꿈과 패널 높이는 따로 맞추고 가로 압축하지 않는다. 이미지 생성기의 유사 글씨는 지정 서체로 인정하지 않는다.
6. **원본 동일성 보고:** 소스 바이트와 출력 변환을 기록한다. 균일 축소·알파 합성 후 화면 전체 픽셀이 원본과 같다고 주장하지 않는다. 보호 영역은 동일한 변환의 기준 레이어와 비교한다. EN/DE 아트 영역은 같고 텍스트 영역만 달라야 한다.

기본 제작 좌표 제안은 390×844, PNG는 3배인 1170×2532다. 일반 검토는 100% 글자 크기로 표시한다. 대표 4화면의 320px·200% 글자 시안 8장은 별도 QA로 구분한다. 40개 정규 화면·언어별 연락판 2개·QA 8개가 계획 산출물이며, 승인 전 후보·폐기 변형은 정규 수에 넣지 않는다.

## 6. 짧은 애니메이션은 우선 키프레임으로 설계

이미지 단계에서 `먹빛 복원 → 책의 짧은 반응 → 탈선비 등장 → 도깨비 재회`의 시작·중간·끝을 연결 표로 설계한다. 학습 글자와 입력 영역을 흔들거나 확대·축소하지 않는다. 캐릭터에 없는 관절 동작·새 표정을 AI로 만들지 않는다. 필요한 포즈가 없다면 같은 원본의 전체 입장·퇴장과 컷 전환으로 표현하고, 추가 포즈 제작은 별도 후보로 남긴다.

이미지가 확정된 뒤 Figma 프로토타입에서 짧고 건너뛸 수 있는 전환을 연결한다. 정지 이미지로 실제 모션·음성 재생·중단·복귀가 검증됐다고 보고하지 않는다. 실제 앱의 상태 저장·TTS·보상은 후속 Flutter 검증 대상이다.

## 7. 통과 조건

다음 중 하나라도 해당하면 다음 화면 제작으로 넘기지 않는다.

- 공간이 단색 면에 그치거나 인물·서안·책이 같은 바닥과 광원을 공유하지 못함.
- 첫 장면에 완공 건물/건물 그림자가 생기거나 R16·고정 인물의 형상이 바뀜.
- 새 책 후보가 현대 양장 책 더미이거나 생성된 가짜 학습 글자가 보임.
- 복원 전 탈선비가 나타나거나 학습 결과 없이 성공 효과가 먼저 나옴.
- 대화창이 얼굴·손·핵심 책을 가리거나, 다음 행동이 일반 뷰포트에서 불필요하게 멀어짐.
- 독일어를 축소/압축해서 넣거나, 지정 실제 폰트·문자·받침이 누락됨.
- 이름이 후속 대화에 연결되지 않거나 도움 경로가 본편에서 배제됨.
- 시각 검토를 Flutter/기기/학습 효과/접근성 동작 통과로 확대 보고함.

검토는 미술, 흐름/교육, 자산/조판의 세 관점으로 진행하고 이견을 기록한다. 인상 점수 하나나 자동 테스트 개수로 품질을 대신하지 않는다. 기존 목업과 같은 크기로 비교하며 일반 화면과 큰 글자 QA를 섞지 않는다.

## 8. Figma → 코드의 후속 순서

이미지 전체가 검토된 뒤 연결된 Figma 문서와 사용 가능한 도구 스키마를 확인한다. 현재 조사에서는 direct Figma 도구와 연결 문서 세션이 확인되지 않았으므로 계정/문서 접근은 그 단계의 선행 조건이다. 지금 연결 요청으로 이미지 계획을 중단하지 않는다.

Figma에서는 확정 PNG를 비교용 잠금 레이어로 두고, 별도 편집 프레임에 배경·원본 캐릭터·전경·대화 재질·실제 텍스트·입력·CTA를 복원한다. 텍스트와 행동 묶음에는 Auto Layout을 적용하고 장면 아트의 깊이/가림 순서는 별도로 유지한다. PNG 한 장을 붙이는 것으로 편집 가능한 화면이 됐다고 보고하지 않는다.

`image-to-code`/Code Connect를 전체 Flutter 앱 자동 변환으로 약속하지 않는다. 최종 Flutter 연결은 기존 콘텐츠 ID·진도·도움·보상 소유권을 보존하는 별도 단계다. 지금은 **앱 코드 변경 금지**이며 이미지·Figma 검토가 끝나기 전에 구현에 착수하지 않는다. 이후 사용자가 정한 Figma→코드 순서에서 구체 범위에 맞춰 동일 뷰포트·언어·글자 크기로 비교하고 실제 동작을 확인한다.
