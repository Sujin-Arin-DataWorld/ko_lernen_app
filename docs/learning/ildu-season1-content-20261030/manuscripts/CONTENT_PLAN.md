2. **가르침:** 새 자모·낱말의 뜻·표현 기능과 음성을 먼저 제공한다. 읽기·듣기·발화·입력의 준비 목록을 구분한다.
3. **시범:** 인물이 실제 행동과 한국어를 함께 보여 준다. 정답만 깜빡이는 장식으로 대체하지 않는다.
4. **도움 연습:** 조립·소리 재생·그림 선택·짧은 응답을 해 본다. 힌트 종류와 사용 여부를 보존한다.
5. **다른 예에서 확인:** 이미 가르친 목표를 다른 배치·대상에서 확인한다. 처음 보는 물건의 뜻이나 자모를 몰래 요구하지 않는다.
6. **상황에서 사용:** 배운 글자/낱말/표현으로 푯말을 놓거나 부탁하고 대답을 받는다. 단순 정답 선택과 생활 대처를 같은 능력으로 기록하지 않는다.
7. **결과:** 이야기에서 바뀐 것과 확인한 학습 범위를 각각 보여 준다. 미확인 듣기·말하기 능력을 성공 애니메이션으로 만들지 않는다.
8. **회수:** 나중 수업·현대 상황·다른 날에 무엇을 다시 요구할지 문항과 ID로 지정한다. 날짜 경과만으로 유지 성공을 만들지 않는다.

### 낱말 하나를 제작할 때 필요한 묶음

- 한국어 표기와 **이번에 배우는 뜻 하나**.
- 발음 감수한 원 음성, 화자·파일 ID·출처·검수 상태. 기존 TTS 경로를 재사용할 수 있으나 재생 가능=발음 검수 완료가 아님.
- 같은 개념의 시범 그림과 확인용 다른 그림. 새 그림 속 미학습 배경지식으로 정답을 추측하게 하지 않음.
- 짧은 EN/DE 의미 설명, 처음 소개하는 위치와 재등장 위치.
- 배운 범위로 구성한 정답·오답 보기, 오답 이유별 차분한 피드백.
- 해당 문항이 확인하는 것: 글자 조합/단어 뜻/소리 식별/제한 입력 등.
- 재시도·도움·새 문항의 규칙과 기록 범위.
- 교재 페이지는 제작 근거로 기록하되 원 교재의 그림·음성·문항을 앱 배포물로 그대로 복제하는 권리까지 있다고 가정하지 않음. 실제 앱용 자료는 독자 저작 또는 확인된 사용 범위로 준비.

## 6. 먼저 만들 제작 묶음

### 묶음 A — 첫 글자와 첫 관계

F0.1 세 단원에 v3.5 공부책 장면, 수진의 조작 시범, 탈선비 각성 순서를 연결한다. 인사·감사·다시 듣기를 병행한다. 첫 `아`의 의미는 '한국어로 누군가와 행동을 함께했다'는 경험이며 A1·발음 숙달의 증거가 아니다.

완료 조건: 신규 학습자가 미학습 한국어 없이 무엇을 할지 이해하고, 도움을 선택해도 같은 사건에 참여하며, 다음 행동과 이어하기를 찾을 수 있다. 수업 시간과 이탈 원인은 실제 관찰 전에는 미측정으로 둔다.

### 묶음 B — 창고에서 단어가 쓸모 있어지는 순간

기본 자음 단원은 짧은 준비 활동으로 재사용한다. 나무·모자, 도구·마루의 그림·뜻·음성을 제작하고 다른 대상을 고르는 확인을 붙인다. 나무의 식물 뜻과 재료 뜻을 구분한다. 기존 역사 단서 공개는 해당 건물/이야기 조건이 충족될 때 원 사건 시스템이 담당한다.

완료 조건: 같은 그림의 위치 암기와 실제 뜻 이해를 구분하고, 도움 이후 재시도를 독립 성공으로 바꾸지 않으며, 도깨비가 필요로 한 물건/푯말이 실제로 바뀐다.

### 묶음 C — 이름표와 첫 쪽지

문·방·길·마당은 각 받침·자모를 가르친 뒤 사용한다. LQ-04에서 집·이 집을 직접 입력하거나 동등한 조각 대안으로 만든다. 작은 쪽지는 피날레의 이미 정해진 회수 소재이고 추가 필수 단서가 아니다.

정식 LQ-04의 장면 조건은 v3.5의 **사랑채 완공**을 유지한다. 완공 전에 할 수 있는 입력·띄어쓰기 연습은 일반 연습이며, 정식 첫 쪽지·LQ 완료·건축 완료 플래그를 미리 만들지 않는다. 이미 완공/해당 사건을 진행한 사용자는 기존 사건·기록장 접근 계약으로 복귀하며 새 보상을 만들지 않는다. 건물 조건과 별도로 같은 결말을 도움 모드로 경험할 수 있다는 v3.5의 계약도 유지한다.

완료 조건: 글자 입력·회상·따라 쓰기를 구분하고, 키보드를 쓸 수 없는 사람도 계속하며, 이야기 재생과 보상을 중복 생성하지 않는다.

### 묶음 D — A1 첫 소개와 현대 생활 회수

LQ-05에서 도깨비에게 이름을 소개하고 놓친 이름을 다시 묻는다. 이어 기존 현대 이벤트가 제공되는 시점에 다른 상대에게 인사/요청을 사용한다. 새 현대 사건을 기존 MQ 번호에 자동 확정하지 않고 정본 자료와 맞는 시점을 확인한다.

완료 조건: 자기 이름의 미학습 글자를 읽어야만 참여할 수 없게 만들지 않고, 수진과의 기존 단짝 관계를 유지하며, 글자 선택/대본 따라 말하기를 독립 대화 수행으로 과장하지 않는다.

## 7. 확인과 기록

- 현재 구현의 저장 실패 복구, 계정 분리, 원 응답·도움·개정 보존을 재사용한다. 기존 기록을 삭제하거나 구간 선택을 자동 변경하지 않는다.
- 새 소품/대사/목표 개정에는 개정과 원본 해시를 기록한다. 이전 시도는 이전 범위의 근거로 보존하고, 새 미디어·새 목표 검증으로 자동 승계하지 않는다.
- '아 직후 탈선비 각성'처럼 수업 중간에 일어나는 사건은 이야기 체크포인트의 저장·재개·재생 계약이 추가로 필요하다. 기존 수업 완료 receipt 하나가 이를 이미 해결한다고 가정하지 않는다.
- 학습·이야기·건축·보상은 각 소유자의 상태를 사용한다. 같은 완료 이벤트의 재처리·오프라인 재시도로 보상을 늘리지 않는다.
- 교육 검수: 한국어 교원이 의미·소리·선행 조건·허용 답을 검수하고, EN/DE 검수자가 안내와 관계 말투를 확인한다.
- 실제 입문자 관찰: 조작을 알아내는가, 소리와 글자를 혼동하는가, 도움을 요청할 수 있는가, 나중에 같은 목표를 다른 대상에서 할 수 있는가를 본다. 체류시간·정답률만으로 효과나 재미를 확정하지 않는다.
- 이후 실제 Flutter와 기기에서 이어하기·오디오 실패·작은 화면·큰 글자·화면읽기·동작 줄이기·동기화·중복 보상을 검증한다. 이번 문서 검토가 그 검증을 대신하지 않는다.

## 적용한 스킬의 실제 영향

- Superpowers `brainstorming`: 기존 목표·금지 범위·제작자가 결정할 부분을 명시하고, 코드 작성 전에 검토 가능한 콘텐츠 설계와 별도 제작자 검토를 둔다. 사용자가 이미 지정한 세계관과 입문 대상은 다시 질문하지 않고 그 조건으로 구체안을 제안한다.
- ECC `search-first`의 저장소 재사용 확인: 기존 28개 데이터·생성 원천·첫 제작 대본·저장 계약을 먼저 찾아 유지/수정/추가로 나눴다. 이번은 패키지/유틸리티 구현이 아니므로 npm/PyPI 전수 조사는 하지 않았다.
- ECC `product-lens`: 첫 성취를 문화 지식 퀴즈 완료가 아니라 '첫 글자로 친구를 깨우고 다음 행동을 아는 경험'으로 정의했다. 실제 신규 사용자 실행·시간 측정은 하지 않았으므로 UX 감사 완료나 측정 성과를 보고하지 않는다.

별도 제작자 검토에서 첫 아의 비발화 도움 경로가 각성 인과를 생략할 수 있다는 점을 확인했다. 아바타의 극중 낭독은 유지하고 현실 학습자의 녹음/발음 평가는 요구하지 않는 제안으로 보완했다. 100단원 중 F0 28개 대응, LQ-04의 사랑채 완공 조건과 일반 연습의 경계도 명시했다. 이 검토는 교원 감수·실제 학습자·Flutter 조작 검증을 대신하지 않는다.
