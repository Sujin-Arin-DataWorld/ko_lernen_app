# 원고 편집 사전 대조

범위: 수정 전 네 원고를 전편 읽고 원고상 과제를 풀었다. 실제 음원을 재생하거나 발음·학습자 성취를 검사하지 않았다.

## 직접 계산한 문자 답

| 단원 | 도움 조립 | 모형을 가린 조립 | 근거 |
|---|---|---|---|
| sound-signs | P1 아, P2 어 | I1 어, I2 아 | 첫자리 ㅇ 왼쪽, ㅓ/ㅏ 오른쪽. 짧은 획의 방향과 모음 배치 자리를 혼동하지 않음 |
| above-below | P1 오, P2 우 | I1 우, I2 아, I3 오, I4 어 | 가로 모음은 아래, 세로 모음은 오른쪽. 목표 음절은 모두 선행 범위에 있음 |
| straight-lines | P1 으, P2 이 | I1 이, I2 으, I3 아, I4 오, I5 어, I6 우 | ㅣ/ㅏ/ㅓ는 오른쪽, ㅡ/ㅗ/ㅜ는 아래 |

듣기 답은 **표본 전사로만** 대조했다. sound-signs 확인 1 어·확인 2 아, above-below 연습 우·확인 1 오·확인 2 우, straight-lines 확인 1 이·확인 2 으. 파일 자체의 소리와 전사 일치는 미검증이다.

## A1 대본과 역할 답

- 지원 자기소개: `안녕하세요. 하린이에요.`; `저는 하린이에요.`도 의미를 보존한다.
- 반복 요청 뒤 상대는 `하린이에요.`를 그대로 반복, 학습자 `하린 씨예요?`, 상대 `네.`. 요청만 하고 상대 반응을 누락하면 회복 상호작용은 완성되지 않는다.
- 듣기 대본 문항: 이름을 다시 말한 사람은 크리스티안, 반복한 이름은 크리스티안, 이름은 바뀌지 않았다. 다시 말한 발화와 확인 뒤 `네`가 근거다.
- 기존 독립 확인의 가능한 산출: `안녕하세요. 준이에요.` → `다시 말해 주세요.` → 상대 `유나예요.` → `유나 씨예요?` → 상대 `네.` → 학습자 `감사합니다.`. 원고의 예시답에는 반복하는 상대의 중간 차례가 생략되어 있다.

## 원고 편집에서 확인할 지점

1. F0 독립 확인과 듣기 문항 옆에 답이 함께 있다. 편집자용 통합 원고를 독자가 바로 쓰면 답을 먼저 보게 된다. 지시·자료만 있는 학습자 구획과 뒤쪽의 진행자 답을 분리한다. 최초 시범/지원 모델은 계속 보여도 된다. 이것은 원고 편집이며 앱 UI 설계가 아니다.
2. sound-signs 생활 전이는 목표 자극 없이 서로 가리키기만 한다. 목표를 글자로 보여 주는 형태 찾기와 실제 준비된 음가를 듣는 소리 대응을 구분하고, 구체적으로 어떤 카드를 찾는지 정한다.
3. straight-lines 원래 `FOUNDATION.psv` transfer의 느·니와 다음 실제 원고의 니·무를 혼동하면 안 된다. 다음 단원 원고는 읽기만 확인했다. 이번 단원 안에서는 ㄴ을 가르치기 전에 느/니를 시험하지 않는다. 후속 참조 씨앗과 현재 다음 단원의 확정 과제를 구별해 메모할 수 있다.
4. straight-lines 소리 확인은 이·으 두 항목뿐인데 원본 FOUNDATION의 새 확인 계약은 배운 여섯 음절을 다른 순서의 소리표와 연결하기다. 미리 배운 여섯 음절의 누적 소리 대응을 원고에서 구체화하고, 음원 없는 현재 검토는 텍스트 계획 검증으로 남긴다.
5. A1 새 확인은 학습자 지시에 상대 이름까지 공개한다. 자기 역할 카드, 상대 역할 카드, 선택할 상황을 구분하고 실제 상대의 반복→확인→응답 차례를 제공한다. 재요청이 필요한 경우와 잘 들은 경우를 구별한다. 강제 청취 실패·잡음·발화 인증을 새로 만들지 않는다.
6. A1 이름 말끝 설명의 `이에요예요`는 읽기 어렵다. `받침이 있는 이름 뒤에는 이에요를 붙여요`처럼 바꾼다. 기존 필수 목표 범위에서 예요/이에요의 연습 기회를 구분한다.
7. 안내·정답 근거·도움 사용 조건 중 KO에만 있는 내용은 실제 학습자가 알아야 하는지 판단한다. 필요한 내용은 EN/DE에도 함께 제공한다. 집필자 메모는 KO로 남겨도 된다.
8. 문서 머리/끝의 검토 전 상태는 이번 정확한 바이트의 언어 재검토가 끝난 뒤 갱신한다. 사람 감수·소리 청취까지 완료됐다고 쓰지 않는다.
