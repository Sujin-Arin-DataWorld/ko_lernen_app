# 일두고택 전체 완성 화면 설계

사용자는 2026-10-29 R16 전체의 제작 정본 승격·커밋·푸시·main 병합과 전체 고택 완성 화면을 요청했다. 추가 확인에서 **고택이 중심, 캐릭터·문양은 보조 장식**을 선택했다. 이 문서의 화면 배치와 제작 순서는 제작자가 정한 구현안이다.

## 결과와 제작 순서

1. 먼저 11동·128공정·내장 Blender 22개의 제작 정본을 main에 등록한다. 원본은 비공개 아카이브의 고정 커밋과 해시로 연결하고 과거 승인 전 감사 기록은 유지한다.
2. 기존 `ildu-estate-r5-three-gates-canonical.blend`의 부지·담장·마당·문 위치에 실제 R16 건물을 연결해 전체 고택 렌더를 만든다. 기존 배치 원본 SHA-256은 `3195809855213946a330048b3b86cd3f75ccddac045dbaf640909cee4de36d48`이다. 이 조립의 배치 육안 검토는 기존에도 pending이었으므로 이번 렌더에서 담장·문·지붕의 연결을 다시 검수한다. 새로운 측량 인증을 뜻하지 않는다.
3. 조립 렌더로 390×844 기준 모바일 화면과 건물 선택·공정 보기 시안을 만든다. 먼저 Superdesign에서 구도와 화면 흐름을 검토하고 Figma 연결이 가능한 경우 편집 가능한 레이어로 옮긴다. 연결이 없으면 SVG와 원본 렌더·명세를 보존한다.
4. 화면 시안을 실제 조작·320px 폭·큰 글자·동작 줄이기로 확인한다. Flutter 통합·GLB PBR 베이킹·실기기·배포는 이후 별도의 검증 단계다.

## 아트와 배치

기존 건물의 형상·비율·창호·난간·지붕 곡선·UV·계층·공정 ID를 보존한다. 조립에는 R16 원본을 사용하며 첨부 고택 그림을 잘라 건물로 쓰거나 생성 이미지로 건축을 다시 그리지 않는다. 사랑채 현판 文獻世家·忠孝節義는 완성본과 공정 16에 포함한다. 협문은 별도 정본의 정확한 배치 행렬을 사용하며 담장·포털의 이음새를 확인한다.

사용자 추가 지정: 사랑채·중문간채는 단독 건설 공정에서 온전한 지붕, 실제 연결 후에는 연결부가 깎인 지붕을 보여준다. 기존 R12의 검증된 단독 지붕 복원 형상을 R16 재질에 연결한 별도 표시 변형을 만들고 기존 연결형 22개 원본을 보존한다. 새 지붕 부재는 대응하는 기존 부재의 requiredStage를 상속하며 기와가 없는 초기 공정에서 완성 지붕이나 전체 건물을 미리 표시하지 않는다. 건물·공정 ID와 보상/학습 해금은 그대로이며 전환은 기존 물리적 연결 상태를 사용한다. `ROOF_VARIANT_POLICY.json`에서 준비 상태를 따로 검증한다.

기본은 따뜻한 낮의 고택이다. 첨부 고택은 높은 사선 시점·부드러운 그림자·돌과 기와의 질감 참고다. 첨부 야간 캐릭터 장면은 보호하는 동행자의 분위기 참고이며 화면 전체를 파란 번개나 판타지 배경으로 바꾸지 않는다. 기존 승인된 캐릭터를 대체하지 않는다. 구름 문양은 제목 옆 또는 화면 가장자리의 작은 장식으로 사용하며 건물·글자·조작 영역과 겹치지 않는다. 원본의 투명 여부를 실제 검사한 뒤 사용한다.

렌더는 공통 카메라와 조명을 사용하고 배치 행렬을 검증한다. 16GB 로컬 메모리에서 전체 장면 평가가 과도하면 건물·문·마당을 같은 카메라로 나누어 렌더하고 깊이 정보를 사용해 합성한다. 이 경우 레이어·카메라·합성 원본을 남겨 수정 가능하게 한다. 형상을 줄이거나 건물 위치를 임의로 바꾸는 방식으로 메모리 문제를 해결하지 않는다.

## 화면과 조작

완성 화면은 한옥 탭에서 열리는 전체 고택 보기 시안이다. 상단에는 뒤로·일두고택 제목·도움, 중앙에는 화면의 대부분을 차지하는 고택, 하단에는 선택한 건물의 짧은 설명과 `공정 보기`를 둔다. 5탭 내비게이션과 학습 화면은 기존 소유자가 유지한다. 기존 아이콘을 새로 추정해 그리지 않는다.

전체 고택 → 건물 선택 → 선택 강조와 하단 설명 → 공정 보기 → 원래 1~마지막 단계 선택 → 전체 고택으로 복귀한다. 복귀하면 선택 건물과 줌을 보존한다. 확대·축소·전체 보기와 접근 가능한 건물 목록을 함께 제공하며 고정 건축 배치를 드래그로 바꾸지 않는다. 겹친 작은 건물도 목록에서 선택할 수 있다. 공정 ID와 유닛 연결은 APP_ASSET_CONTRACT.json을 읽는다.

이 시안의 `완성`은 건축 아트의 완성 상태다. 사용자의 학습 완료·소유·보상·해금으로 저장하지 않는다. 실제 앱 연결 시에는 기존 verified progression·entitlement를 읽고 완료 상태와 분리된 미리보기임을 표시한다. 로그인·오프라인·데이터 없음으로 완성 진도를 만들어내지 않는다.

로딩 중에는 같은 공간을 예약하고, 이미지 실패에는 재시도와 건물 목록을 제공한다. 닫기·뒤로는 언제나 가능하다. 공정 렌더가 없으면 이전 이미지를 다른 단계로 표시하지 않고 해당 공정의 재시도를 제공한다. 사진 확대를 닫으면 열었던 컨트롤로 키보드 포커스를 돌려준다.

## C안 재료·반응·접근성

한지 바탕·짙은 목재 텍스트·청록 선택 강조·금색 주요 행동을 사용한다. 입체감은 고택 렌더의 접지 그림자와 조명, 하단 설명판의 얇은 재료 두께, CTA의 2px 눌림으로 만든다. 글자 위의 과한 반사나 흐림은 사용하지 않는다. 본문 16px, 제목 24px, 관련 요소 4~8px, 묶음 12~16px, 조작 사이 8px, 조작 영역 최소 48×48px를 기준으로 한다.

선택 전환은 160~220ms의 짧은 강조·페이드로 관계를 알린다. 반복 흔들림·깜빡임·자동 회전은 사용하지 않는다. 동작 줄이기와 백그라운드에서 정지하며 같은 선택·결과를 제공한다. 100% 글자 크기로 기본 검수하고 200%와 320px 폭에서 별도로 겹침·잘림·가로 넘침·안전 영역을 확인한다. 색과 애니메이션만으로 선택 상태를 전달하지 않는다.

## 적용한 스킬과 공식 근거

- ECC: 현재 파일·출처·승인·검증과 후속 앱 적용 상태를 분리한다.
- Superpowers: 기존 조사 재사용, 구체적인 제작안과 검증 기준, 정본과 미완료 상태를 명시한다.
- Superdesign: 실제 렌더와 선택한 에셋만 전달하고 새 화면을 기존 화면의 복제라고 주장하지 않는다. 업로드한 이미지의 용도를 구분하며 불필요한 변형 생성은 하지 않는다.
- Figma: 기존 디자인 시스템과 편집 레이어를 우선하며 정지 시안을 Flutter 작동 증거로 대신하지 않는다.
- UI UX Designer mobile-app-ui/user-flows/high-fidelity-mockups: 390px 모바일 정보 위계·돌아오기·실패·큰 글자·터치 크기를 명세했다.

2026-10-29 확인: [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)의 콘텐츠와 조작층 위계는 한지·목재 재료와 얇은 판의 깊이로 해석한다. [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)은 짧고 목적 있는 선택 반응과 동작 줄이기로 적용한다. [Android 터치 크기](https://support.google.com/accessibility/android/answer/7101858?hl=en)의 48dp/8dp는 모든 조작과 건물 목록에 적용한다. 시스템 유리 재료로 C안을 교체하지 않는다.

## 완료 근거

원본 11동·3종 문·배치와의 해시/행렬/부재 대응, 실제 전체 렌더 육안 검수, 건물 선택·128공정·닫기/복귀 조작, 100%/200%/320px/동작 줄이기 결과를 각 파일에 남긴다. Figma·Superdesign URL, Git SHA와 CI 결과, 원격 보존 및 로컬 삭제 영수증은 검증 후 기록한다. 작성 시점의 이 문서만으로 그 단계를 완료 처리하지 않는다.
