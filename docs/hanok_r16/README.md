# 일두고택 R16 제작 정본

2026-10-29 사용자의 명시적 요청으로 R16의 11개 건물 완성본·128개 공정 렌더·Blender 원본 22개를 제작 정본으로 승격한다. 정확한 파일 해시와 범위는 [정본 등록](CANONICAL_PROMOTION_R16.json)에 있다. 이전 감사 기록의 userApproved=false는 당시 기록으로 보존하며 이 등록이 제작 정본 상태를 갱신한다.

[전체 고택 화면](estate/index.html) · [원래 연결용 갤러리](review/index.html) · [전체 고택 화면 설계](ESTATE_SCREEN_DESIGN.md) · [앱 에셋 계약](APP_ASSET_CONTRACT.json) · [복원](RESTORE.md) · [앱 적용 순서](APP_INTEGRATION.md)

Blender 파일과 과거 제작 단계 및 사용 원본은 비공개 보관 저장소의 정확한 ref/commit과 SHA-256으로 연결한다. 큰 바이너리는 이 저장소의 [ARCHIVE.json](ARCHIVE.json)이 가리키는 비공개 아카이브에 보존한다. 텍스처를 내장한 22개 독립 Blender 사본과 현재 협문 6개 사본, 입력·도면·도구를 각각 복원할 수 있다. Render 1·2와 이전 원본의 바이트는 유지했다.

메인의 tool/hanok_scene/r16는 실제 사용한 제작 코드의 원문이다. 이 스크립트들은 원래 제작 폴더 계층과 입력을 요구한다. 아카이브에서 해당 계층을 복원한 뒤 실행한다. 갤러리는 이 폴더를 HTTP 서버로 열어 볼 수 있다.

제작 정본 승격과 GLB/Flutter 적용 상태는 구분한다. 이 발행은 앱의 진도·보상·권한·공정 정책을 변경하지 않는다. 실제 배치의 R16 건물 11동·문 3개·문맥을 같은 카메라와 깊이로 합성한 전체 고택과 모바일 검토 화면을 포함한다. 건물 선택→공정→확대→복귀가 연결되어 있다. 여러 레이어를 깊이 합성했으므로 건물 사이의 간접광은 단일 장면의 경로 추적과 같지 않다. 마을은 후속 범위다. 일부 결의 크기와 옹이 표현 한계는 process-evidence 및 review/STAGE_VISUAL_REVIEW.json에 남겨두었다.

사랑채·중문간채는 [지붕 표시 계약](ROOF_VARIANT_POLICY.json)에 따라 단독 시공용 온전한 지붕과 연결 뒤의 깎인 지붕을 함께 보존한다. 추가 Blender 4개와 두 건물 28개 공정의 단독 표시를 검증했다. 화면의 ‘단독 건물 / 연결 후’ 비교는 같은 공정 번호를 유지한다. Flutter에서는 기존 물리적 연결 상태가 전환을 소유해야 하며 새 진도·보상이나 임의 공정 임계값을 만들지 않는다. 원래 연결용 22개 파일은 바꾸지 않았다. 새 원본은 별도 비공개 아카이브의 정확한 commit으로 복원한다.

하단 네비게이션의 최종 교체 에셋·Lernen 매핑은 아직 확정되지 않아 검토 화면에 임의로 추가하지 않았다. 기존 앱의 다섯 탭과 기능은 유지한다. Superdesign은 시각 시안이며 실제 공정 이미지·전환 검증은 이 저장소의 HTML 검토 화면에서 수행한다.

사랑채의 文獻世家·忠孝節義 현판은 나무판과 글자 텍스처가 내장되어 있으며 공정 16 ‘완성’부터 나타난다. 정면 검증 이미지는 process-evidence/sarang-plaque-*-front.png와 SARANG_PLAQUE_FRONT_INSPECTION.json에 있다.
