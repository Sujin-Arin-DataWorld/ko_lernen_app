# 앱 적용 실행 기준

현재 전달: 11개 완성 렌더, 공정 ID와 학습 단원 연결을 보존한 128개 단계, 독립 Blender 22개(완성+공정 타임라인). APP_ASSET_CONTRACT.json이 전달 목록이다.

1. 계약의 native SHA로 R16 파생 입력을 명시한다. R12 전용 exporter의 원본 SHA를 무력화하거나 R16을 R12로 위장하지 않는다.
2. 11개를 각각 PBR로 베이킹한다. Base Color에 조명을 통째로 굽지 않고 roughness/normal/emission을 분리한다. 부재별 목재색·결 방향, 단청, 종이의 발광/온돌 비발광, 돌 및 귀면와 부조를 확인한다. 360도 확대에서 평면 카드가 드러나지 않아야 한다.
3. 객체 이름·계층·부재 ID·공정 ID·추가 돌/기와의 원본 연결을 GLB extras와 선택 목록으로 유지한다. 오브젝트를 합치지 않는다. 82개 미확정/context 부재와 현재 공정 정책과 다른 7단계를 임의로 재분류하지 않는다.
4. 기존 앱의 공정 카탈로그/진도/엽전/권한은 변경하지 않고, 버전별 다운로드 manifest에서 모델·텍스처 크기와 SHA를 검증한다. 실패 시 기존 승인 에셋을 쓴다. 현재 runtime에 공정 이미지가 없는 곶간·측간 계열은 대응 시리즈를 먼저 추가하고 모든 ID를 검사한다.
5. 각 건물의 128개 원래 단계에서 동일 재질, 숨김 선택, 접지, 창호, 누마루/마루 난간을 검수한다. 모바일 메모리·로딩·확대·회전과 reduced-motion을 실제 기기에서 검증한다.
6. 개별 검수 통과 후 기존 배치·치수의 전체 고택으로 통합한다. 이후 마을로 확장한다. 회복 가능한 구버전 선택 및 에셋 버전만 전환하며 학습 진도를 초기화하지 않는다.

아직 미완료: GLB PBR 베이킹, 앱 런타임 연결, 기기 성능/다운로드 검수 및 배포. 이미지 갤러리 검증을 이 단계의 완료로 취급하지 않는다.
