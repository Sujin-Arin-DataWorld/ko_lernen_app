# 안사랑채·사당문·사당: 사람이 사용하는 2.5D 건축 공정

## 승인된 방향

Jin은 2026-09-14 대화에서 안사랑채 14단계·사당문 8단계·사당 12단계 분석과 공정안을 수용하고 다음 조건을 추가했다.

> 중요한건 3개 건물 전부 사람이 살고 이용했던 장소라는걸 명심해줬으면해. 절대 평면으로 건물이 완성되게 작업하지말고 2.5D 느낌으로 설계되어야돼. 안사랑채 오른쪽공간에 투명배경처리 덜 된거 제대로 투명배경처리하고 작업해줄래??

세 건물의 역사적 용도 차이를 유지한다. 안사랑채에는 생활·난방·휴식 공간이 있고, 사당문은 사람이 통과하는 경계이며, 사당은 제례를 위해 사용하는 공간이다. 사당문과 사당에 주거용 부엌·온돌·침구를 추가하지 않는다.

이 문서는 승인 방향과 제작·검수 조건이다. 후속 승인으로 잘 보존된 고화질 완성 PNG 3장을 정본 등록하고 바이트를 고정했다. 실행 가능한 34단계 설계와 구조 검증은 [공정 설계](../../assets/ildu_ansarang_shrine_construction_20260914/README.md), 화면은 [설계 뷰어](../../mockups/ansarang-shrine-construction/index.html)에서 확인한다. 중간 공정 원화 31장, 3D 모델, 앱 연결 또는 출시가 완료됐다는 뜻은 아니다.

## 잘 보존된 고화질 완성본

후속 요청에 따라 세 건물 모두 사람이 계속 돌보고 사용하는 건강한 한옥으로 표현한다. 단순한 채도·명도·대비 조정이나 저해상도 원본 확대는 이 요구를 충족하지 않는다.

- 목재는 썩음·벗겨진 칠·흰 긁힘 대신 건전한 결, 온전한 접합, 정돈된 무광 표면으로 다시 그린다. 사당문·사당은 적색 목부와 단청의 고유 재료 체계를 유지한다.
- 기와는 이끼·파손·뒤틀림 없이 겹침과 골, 막새와 용마루의 두께가 분명해야 한다. 흙기와의 무광 재질을 플라스틱 광택으로 바꾸지 않는다.
- 창호는 창살과 문짝 테두리가 명료하고 한지·회벽이 정돈돼 있어야 한다. 기둥 뒤로 물러난 창호와 방의 깊이를 유지한다.
- 기단은 온전한 돌과 줄눈으로 표현한다. 돌무늬를 모두 지우거나 건물 전체에 인위적인 반짝임을 더하지 않는다.
- 자연스러운 생활감은 깊이·출입·쓸 수 있는 마루와 따뜻한 재료에서 드러낸다. 정본에 사람·살림살이를 임의로 붙여 생활감을 대신하지 않는다.
- 고화질 시안의 실제 생성 해상도를 기록한다. 안사랑채·사당은 1536×1024, 사당문은 1086×1448이다. 4K 제작이나 8방향 전체 교체로 소개하지 않는다.
- 세 건물의 새 완성 정본은 `assets_unused/pending_review/personal_hanok_v3/canonical/{ansarangchae,sadangmun,sadang}/`에 보관한다. 승인한 `ansarang_shrine_maintained_v1/masters/`의 같은 바이트를 복사했다. 폴더별 CANONICAL_LOCK.json이 SHA-256·치수·승인 근거를 고정한다. 기존 8방향 런타임 파일과 구분한다.
- 공정 제작은 완성 시안의 건물별 카메라·기둥열·처마·기단 기준점을 먼저 확정하고, 승인된 14·8·12단계를 같은 좌표로 파생한다. 숨은 구조와 새로 드러난 마루 아래 부재는 도면·단면과 대조한다. 생성된 장식이나 가새를 실증된 시공법으로 그대로 가르치지 않는다.

실제 투명 PNG는 RGB와 알파 채널을 따로 검사한다. 생성기의 체크무늬 또는 분홍 마스킹 배경은 완성 배경이 아니다. 안사랑채 오른쪽 열린 툇공간은 외부가 비쳐야 하며, 양쪽 기둥과 마루 바닥은 온전히 남아야 한다.

## 입체 공간 계약

1. 기본 화면은 전면과 측면, 바닥 상면을 함께 읽을 수 있는 고정 사선 시점이다. 완성 정본의 시점을 먼저 고정하고 공정마다 같은 카메라를 사용한다. 도면 같은 정면 입면이나 위에서 내려다본 평면만으로 완성 화면을 만들지 않는다.
2. 부재는 앞면 장식으로 붙이지 않는다. 초석 위 기둥의 밑면, 기둥 머리와 보의 접합, 보·도리와 서까래의 지지, 마루 귀틀의 끝과 받침이 이어져야 한다.
3. 전면 기둥 뒤에 방 깊이, 후면 기둥열, 후퇴한 창호, 마루 밑 공간이 존재한다. 앞쪽 부재가 뒤쪽 부재를 가리는 관계와 그늘은 단계마다 일관돼야 한다.
4. 문에는 회전축·문짝 두께·열리는 공간이 있다. 벽을 통과하거나 사람의 통로를 막는 문 여닫힘을 허용하지 않는다. 역사적 철물의 구체 형태는 증거 범위에서만 그린다.
5. 동일 부재는 설치 이후 위치·굵기·재질·색이 바뀌지 않는다. 기단 모서리, 초석 중심, 주요 기둥 머리, 처마 끝, 용마루를 고정 기준점으로 삼는다.
6. 사람의 사용 모습은 공간의 크기와 목적을 이해하는 별도 설명 장면이다. 사람·짐·신주·제기 등 소품을 건물 완성 정본에 영구 합성하지 않는다. 특정 거주자·의례 배치·신분별 출입 규칙은 자료 없이 단정하지 않는다.
7. 스타일은 현재 V3의 `stylized hand-painted 2.5D architectural sprite art`를 따른다. 목재·석재·기와의 체적과 재질을 유지한다. 평면 벡터나 단순 다각형 블록으로 바꾸지 않는다.
8. 온돌·마루 아래·지붕 속 구조는 설명용 절개 또는 확대 보기로 드러낸다. 설명용 절개는 실제 미완성 상태와 구분하고, 기본 외관 그림과 같은 좌표 관계를 따른다.

### 안사랑채

- 방·부엌·대청·앞/옆 마루를 각기 깊이가 있는 공간으로 구성한다. 정면 4칸의 반복을 지키면서 방 구획이 모두 동일한 방으로 복제되지 않도록 한다.

- 학습 예: `세우다` — “기둥을 세워요.” / `따뜻하다` — “방 안은 따뜻해요.” / `-에서` — “마루에서 잠깐 쉬어요.”

### 사당문

- 얕은 단칸문의 크기와 기둥 사이 통과 공간을 유지한다. 큰 삼문이나 행랑이 있는 대문으로 확장하지 않는다.
- 앞의 태극과 뒤의 가새를 구분하고, 문짝을 열면 그 뒤 공간이 보이게 한다. 문짝이 기둥 자체를 지워 열리는 효과를 금지한다.
- 학습 예: `앞` — “문 앞에서 기다려요.” / `열다` — “문을 천천히 열어 주세요.” / `-아/어도 되다` — “들어가도 될까요?”

- 3칸의 골조, 기둥 뒤 툇공간과 창호, 목재 마루의 깊이를 살린다. 내부를 주거용 방·부엌으로 바꾸지 않는다.

- 학습 예: `위에` — “기둥 위에 보를 올려요.” / `안쪽` — “문 안쪽에 마루가 있어요.” / `기리다` — “조상을 기리는 공간이에요.”

## 안사랑채 투명 배경 수정 계약

- 우선 대상: 런타임 `ildu_ansarangchae_01_front_right.png`, `ildu_ansarangchae_07_front_left.png`의 오른쪽 열린 기둥 사이 흰 배경. 나머지 6방향도 확인한다.
- 실제 회벽·창호지·목재는 불투명 상태로 보존한다. 밝은 색 전체를 제거하는 전역 색상 키를 사용하지 않는다.
- 각 틈의 국소 영역에서 배경만 제거한다. 원본 RGB, 384×512 캔버스, 물체 위치와 크기는 그대로 둔다.
- 원본 바이트를 별도 원본 폴더에 보존하고, 수정 출력의 SHA-256·수정 영역·알파 변화·색상 불변 여부를 기록한다.
- 체크무늬가 RGB에 그려진 결과는 투명 이미지로 인정하지 않는다. PNG 알파 채널과 빈 공간의 알파 0을 직접 확인한다.
- 밝은 배경·짙은 배경·체크무늬 위에서 실제 알파 합성을 확인하고, 기둥 모서리와 툇마루가 잘리지 않았는지 확대 검수한다.
- 기존 승인 원화와 8방향 보관본은 역사적 해시를 유지한다. 수정본은 원본을 대체했다고 숨기지 않고 별도 수정 계보로 기록한다.

## 첫 제작 묶음과 검수

첫 제작 묶음은 안사랑채 `완성 기준`, `골조`, `온돌 설명`, `마루 완성`이다. 세 건물 전체 34단계 완료로 보고하지 않는다.

검수자는 네 장에서 동일 기단·초석·기둥·실내 깊이가 유지되는지 확인한다. 온돌 설명의 절개 위치와 생활 공간이 완성 건물과 맞아야 한다. 구조가 바뀌거나 깊이가 사라진 그림은 다음 공정의 기준으로 사용하지 않는다.

각 건물의 전체 공정 제작 전에 완성 기준 이미지의 해시·카메라·캔버스·기단 기준점을 고정한다. 회전 프레임 8장을 그대로 건축 단계 8장으로 취급하지 않는다.

## 앱 연결 범위

기존 사랑채의 최초 단원 완료 기반 획득과, 다른 건물의 공정 관람은 현재 별도 기능이다. 새 그림을 만드는 것만으로 세 건물의 획득 흐름이 연결됐다고 주장하지 않는다.

- 기본 경험: 실제 학습 단원 최초 완료 → 전후 모습 → 한국어 용어 하나 → 짧은 설명.
- 선택 경험: 구조 확대·설명용 단면·한국어 듣기·한영독 상세 설명·다시 보기.
- 관람, 반복, 미리보기, 말하기 시도, 단순 선택형 과제만으로 XP·아이템·지도 등록·건축 진행도·다음 건물 승인을 만들지 않는다.
- 기존 완료 기록이 재설치·복원 후에도 동일한 획득을 만들도록 별도 적립 카운터를 추가하지 않는다.
- 폰과 태블릿에서 한 건물의 구조와 전후 변화가 읽히는지 검수한다. 그림 파일 검사는 앱 렌더링·실기기 검증을 대신하지 않는다.

## 제작 결과의 상태 표시

원본·배경 수정본·공정 후보·승인 후 실행용 그림을 구분한다. 앱 코드와 `pubspec.yaml`에는 승인되고 실제 소비자가 연결된 결과만 등록한다. 커밋·푸시·메인 병합·스토어 배포는 각각 해당 요청과 검증이 있을 때 수행한다.
