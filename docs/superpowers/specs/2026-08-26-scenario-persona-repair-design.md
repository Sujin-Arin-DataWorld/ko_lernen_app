# 레벨별 내용 범위를 반영한 120개 정본 시나리오 설계

**상태:** 후보·파이프라인과 TTS 준비 완료, Jin 전수 승인 대기
**정본 세대:** `canonical_120_v1`
**범위:** A1~C2 각 20개 정본 후보, 48개 기존 코스 ID, 비출시 회귀 장면 12개, 캐릭터·TTS·진행도 세대 계약, 2026-08-27 승인된 TTS 합성·Firebase Storage 준비
**비범위:** 외부 LLM 콘텐츠 재생성, 런타임 승격 전 사람 승인 생략, 배포, 신규 인물 그림, `easy_localization`

## 목표와 권위

한국어를 유일한 의미 원문으로 삼아 실제 사건과 화자별 목적이 있는 장면을 먼저 쓴다. 문법은 장면을 만들기 위한 삽입 목록이 아니라 완성된 대사에서 추출하는 허용 범위다. 독일어와 영어는 한국어의 화행·관계·양태·선택권을 보존하되 각 언어에서 독립적으로 자연스럽게 현지화한다.

앱 운영에서는 한국어 1~6급과 CEFR A1~C2를 대응표로 사용하지만 공식적인 일대일 등가라고 주장하지 않는다. 레벨은 문장 길이뿐 아니라 내용 범위, 사회적 거리, 상황, 담화 깊이와 인지 과제로 구분한다.

## 레벨 계약

| 레벨 | 내용 범위 | 핵심 수행 |
|---|---|---|
| A1 | 나·주변·당장 필요한 구체적 상황 | 인사, 소개, 확인, 짧은 요청, 사과, 선호 |
| A2 | 익숙한 공공장소와 반복되는 생활 문제 | 요청·허락, 과거·계획, 이유 하나, 간단한 문제 해결 |
| B1 | 자신의 삶과 연결된 학교·직장·사회 상황 | 경험 설명, 조언, 원인·결과, 실수 수습, 의견 |
| B2 | 친숙한 사회·추상 주제와 기본 업무 | 비교, 동의·반대, 보고, 조건, 절충, 격식 조절 |
| C1 | 사회 전반과 업무·학업 | 협의, 체계적 정보 전달, 근거와 이해관계, 숨은 의도 |
| C2 | 전문·학술·사회문화적 특수 문제 | 논리적 설득, 추론, 프레이밍, 함축, 관점·문체 전환 |

레벨별 포트폴리오는 `scenario_corpus_manifest.json`에 고정한다. 각 레벨은 정확히 20개이며 동일 테마의 강제 반복은 출시 정본이 아니라 별도 회귀 세트에서 검사한다.

## 확정 장면과 자연성 잠금

- A1: 빵집 줄을 모르고 끼어든 뒤 `아, 죄송합니다. 줄 서 계신지 몰랐어요.`라고 수습한다.
- A2: 첨부파일을 두 번 빠뜨린 이메일, 그리고 `기사님, 천천히 좀 가 주실 수 있을까요?`를 포함한다.
- B1: 회사 인스타그램 계정으로 개인 게시물을 올린 실수를 수습한다.
- B2: 촬영의 사람·범위·시간을 협의하고, `fremdschämen`은 `내가 다 민망하다`, `보는 내가 다 부끄럽다`로 표현한다.
- C1: 퇴근 후 연락 관행의 암묵적 기대와 경계를 협의한다.
- C2: ‘숨은 명소’ 영상의 확산이 지역에 미친 영향을 프레이밍과 책임의 문제로 논증한다.

카카오T 화면에 이미 보이는 주소·가격·결제를 다시 묻거나 기사에게 `빨리 가 드릴까요?`라고 말하게 하지 않는다. 연락은 장면에 맞춰 카카오톡 QR, 인스타그램, 또는 실제로 필요한 경우의 `핸드폰 번호`를 쓴다. 2026년 기술 요소는 사건상 필요할 때만 등장한다.

## 오프라인 생성 파이프라인

사용자가 수정하는 권위 입력은 `ScenarioBrief` 하나다. 도구는 이를 네 단계의 고정 프롬프트 패킷으로 확장한다.

1. `ko_scene`: 장소, 관계, 사건, 화자별 목적과 전환점으로 한국어 장면을 완성한다.
2. `learning_extract`: 고정된 실제 대사에서만 어휘·문법·퀘스트와 필요한 문화 노트를 추출한다.
3. `localize`: KO와 의미 피벗을 기준으로 DE/EN을 각각 독립 현지화한다.
4. `audit`: 정확성, 자연성, 화용, 관계, 레벨과 런타임 계약을 검사한다.

정본 파이프라인 코어는 프롬프트 패킷 생성, JSON 가져오기, 자동 검사, 검토 문서 렌더링과 승인본 승격만 담당하며 네트워크 클라이언트를 포함하지 않는다. 이후 Jin이 Google AI API 사용을 승인했으므로 Gemini 감사 실행기는 별도의 선택적 운영 도구로 둔다. 이 도구는 비용 상한과 후보 해시를 기록하며 콘텐츠 생성·승인·승격을 직접 수행할 수 없다. 자동 감사의 `pass`는 사람 승인이 아니다.

문화 노트는 실제 화용 차이가 장면 이해에 필요할 때만 사용한다. 런타임과 동일한 `title.{ko,de,en}` 및 `body.{ko,de,en}` 형식을 강제하며 집단 일반화를 거부한다.

## 캐릭터와 런타임 계약

7인 캐릭터 바이블은 배경, 전공, 취미, 관계와 약한 MBTI 힌트를 제공한다. MBTI는 대사를 결정하지 않는다. UI에는 `수진`처럼 이름만 표시하고, 대사 속 호칭과 말투는 관계에서 결정한다.

`Scenario.playerCharacterId`와 `participantIds`가 장면의 인물을 잠근다. 퀘스트 호환성을 위해 플레이어 발화는 계속 `speaker == "user"`를 사용하지만 화면에는 해당 캐릭터 이름과 `(나)`를 표시한다. TTS 성별은 user/NPC 구분이 아니라 해결된 캐릭터 프로필에서 가져오며, 프로필이 없는 구형 장면에만 이전 규칙을 폴백으로 사용한다.

## 코스와 진행도 세대

기존 48개 코스 ID와 공동 퀘스트 wire ID는 유지한다. 사용자 노출 단원명, Can-do, 체크포인트와 콘텐츠 링크는 새 포트폴리오에서 조립하며 모든 단원에 최소 한 개의 새 시나리오를 연결한다.

`legacy_413_v1`에서 `canonical_120_v1`으로 처음 전환할 때 완료 단원, 일반 증거, 시나리오 체크포인트와 시나리오 별점만 초기화한다. 기존 생산 증거는 `archivedProductiveEvidence`로 이동하여 이미 획득한 보상과 한옥을 계속 증명한다. 계정, XP 원장, 연속 학습, 단어 SRS, 책장 노트, 사용자 단어 팩, 구매와 한옥 배치는 변경하지 않는다. 세대 표시는 마지막에 기록하여 중단 후 재시도가 가능하다.

## 승인·TTS·승격 게이트

승격은 A1 → A2 → B1 → B2 → C1 → C2 순서다. 한 레벨의 후보 20개 전체를 Jin이 읽고 승인한 정확한 후보 해시만 다음 단계로 간다. 승인 명령은 Jin이 실제로 검토한 레벨 후보 해시를 명시적으로 입력받고, 현재 전체 후보 해시와 일치하는 결정론적 편집 감사 및 별도 모델 감사 영수증을 함께 검증한다. materializer가 감사 합격을 임의로 만들 수 없으며, 영수증이 없거나 findings가 남아 있으면 승인 기록 자체가 실패한다.

시나리오 파이프라인 자체는 새 음성을 자동 생성하거나 업로드하지 않고, 후보에서 캐릭터 음성과 퀘스트 음성을 계산한 `scenario_tts_pending_manifest`를 출력한다. 별도 운영 도구와 Jin의 2026-08-27 요청으로 현재 후보 837개는 Storage 누락 0까지 준비됐다. 실제 런타임 쓰기에는 다음 두 증거가 모두 필요하다.

1. 그 레벨의 후보 해시와 TTS manifest 해시에 정확히 일치하고 `missingCount == 0`인 Firebase Storage 읽기 검증 영수증
2. `--runtime-write-reviewer Jin`으로 전달된 별도의 런타임 쓰기 승인

`promote-level --write`는 둘 중 하나라도 없거나 해시·개수·캐시 revision이 다르면 실패한다. dry-run은 이 영수증 없이도 staged 콘텐츠 전체 검증까지만 수행한다.

## 완료 기준

- 정본 120개, 레벨당 20개, ID 중복과 고아 링크 0개
- 코스 48개, 링크 120개, 체크포인트 48개, 퀘스트 360개
- 온보딩 첫 장면과 공동 퀘스트 wire ID 보존
- A1/A2 추상적 설명·비문 차단, 모든 장면의 실제 사건·목적·자연스러운 말차례 확인
- DE/EN 화행·관계·양태 보존, 독일어 동일 관계 구간의 du/Sie 혼용 0개
- 캐릭터 이름·플레이어·캐릭터별 TTS 위젯 계약 통과
- 세대 마이그레이션에서 코스·시나리오 진행만 초기화되고 보존 데이터 유지
- Python 콘텐츠 팩토리, 전체 콘텐츠 검증기, Flutter 정적 분석과 관련/전체 Dart 테스트 통과
- Jin의 각 레벨 20개 전수 승인과 TTS 누락 0 확인 전에는 런타임 승격·출시 완료로 판정하지 않음
