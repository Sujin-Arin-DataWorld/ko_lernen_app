## 1. 만들 경험

**친구의 방문 → 작은 목표 → Lernenweg 학습 → 건축 재료 획득 → 직접 조립 → 공간과 이야기의 변화.**

사용자가 선택한 태고 또는 조이가 기본 동행이다. 다른 친구는 특별한 방문에 등장한다. 학습하는 이유와 학습 후 달라질 장소를 먼저 보여 준다. 이미 공부한 내용은 의뢰를 받기 전이라도 인정한다.

기존 Today / Learn / Games / Hanok / Gye 5탭을 유지한다. 실제 Flutter 앱의 Lernenweg·결과 화면·Hanok 탭을 연결한다. 한옥을 위한 별도 웹사이트나 새로운 탭을 만들지 않는다.

이 표는 보상 배정이다. 모든 정규 수업을 건축 용어 수업으로 바꾸지 않는다. 예를 들어 연락 방법을 배우는 수업은 친구에게 연락하는 이야기와 연결할 수 있지만, 돌을 놓는 행동을 연락 능력의 평가로 주장하지 않는다.

## 3. 획득과 조립

각 stage의 권리 획득 조건은 **승인된 정규 평가 묶음 통과 OR 명시적으로 연결한 정규 unit의 검증된 완료**다. 두 경로는 같은 stage ID를 사용한다. 한 경로로 받은 단계를 다른 경로로 다시 지급하지 않는다.

짧은 평가 묶음은 기존 정규 평가에서 실제 학습 목표에 맞게 구성한다. 문제 개수를 임의로 고정하지 않는다. 과거 후보의 2문제×149 배정은 개수와 의미 양쪽에서 결손이 있어 채택하지 않는다.

각 매핑은 stage ID, unit ID, 평가 ID 목록, 허용된 내용 hash·revision·rubric·evaluator, 통과 조건, 한국어 의미 설명, 선행 조립 stage ID를 가진다. 숫자를 맞추려고 무관한 평가를 연결하거나 모든 판정을 참으로 만들지 않는다. 동등한 검수된 정규 평가가 필요하면 CP 콘텐츠 작업에 명시적 결손으로 전달한다.

상급 진입자는 통과한 기존 증거를 먼저 인정받고, 빠진 부분만 같은 정규 평가로 확인한다. 수업 설명·연습은 건너뛸 수 있으나 별도의 쉬운 진단으로 건물을 지급하지 않는다. 레벨 선택·placement·XP·출석·NPC 대화·스티커·장식·그림 탐색은 지급 조건이 아니다.

상태는 다음처럼 구분한다.

1. 미획득: 학습 조건이 충족되지 않음.
2. 획득: 검증된 증거를 저장하고 재료 권리를 확보함.
3. 조립 대기: 필요한 앞 단계 또는 아트 팩을 기다림.
4. 조립 완료: 권리가 있는 부재를 허용된 위치에 적용함.

이미 받은 재료는 다음 공간이 아직 열리지 않아도 보존한다. 일반 학습과 catch-up 모두 149단계 도달 가능성을 증명해야 전체 기능을 활성화할 수 있다. 처음 26단계만 연결된 상태는 내부 검증 구간이다.

## 4. 플레이의 밀도

**149개 시각 상태 + 13챕터 × 3개의 주요 조립 장면 = 39개 조립 장면 + 별도의 선택 생활 의뢰 26개**로 구성한다.

149번의 같은 탭을 요구하지 않는다. 주요 장면 사이에서 이미 획득한 연속 단계는 짧은 조립 연출로 묶어 적용할 수 있다. 미획득 단계를 몽타주에 포함하지 않는다. 단계별 완료는 각각 기록하며 복원일지에서 다시 볼 수 있다.

공통 조작은 세 종류다: 대상 찾아 정리하기, 재료를 맞는 위치에 놓기, 다음 작업 고르기. 실패하면 짧은 힌트로 다시 시도한다. 생명·재료 소모·실패 벌점은 없다. 도움 버튼과 탭 대체 동작으로 같은 결과에 도달할 수 있다. 조립 퍼즐은 별도의 한국어 숙달 판정을 만들지 않는다.

## 5. 태고·조이와 방문

동행은 선택한 친구를 유지한다. 솟을대문·사랑채·안채·사당 완성 시 다른 친구가 특별 방문한다. 일반 학습 화면에서는 작은 방문 표식만 사용한다. 활성 평가 중에는 새 표식·대화를 띄우지 않고 대기열에 보존한다. 평가 종료 또는 안전한 세계 진입 후에 표시하며, 진행 중 평가를 NPC 대화로 가리지 않는다.

화면에는 진행 중인 복원 목표 1개와 선택 의뢰 1개를 우선 표시한다. 전체 대기열은 별도로 보존한다. 미뤄 두기·다시 보기·다른 의뢰 보기로 이전 이벤트에 접근할 수 있다.

26개 생활 의뢰는 안정적인 ID와 버전을 갖는 유한 콘텐츠다. 열린 공간에서 아직 안 본 의뢰를 우선 추천하며 하루 최대 1개를 전면에 추천한다. 직접 목록에서 이어 할 수 있다. 추천 날짜·시간대·선택 결과를 계정에 보존하고 시계 변경으로 신규 보상을 만들지 않는다. 재설치·두 기기에서는 stable ID로 중복 여부를 판정한다.

미접속일의 의뢰가 숙제처럼 쌓이거나 사라지지 않는다. 모두 본 후에는 ‘지난 의뢰 다시 보기’로 표시한다. 재방문을 새 콘텐츠·새 첫 보상으로 표시하지 않는다. 매일 무한히 새로운 이야기가 생긴다고 약속하지 않는다.

39개 조립 장면과 26개 생활 의뢰는 서로 다르다. 생활 의뢰를 모두 건너뛰어도 학습과 조립으로 완공할 수 있다. C1·C2는 완성된 공간의 대화에서 이유·관점·조건·암시를 깊게 다루며 새 건축 단계를 요구하지 않는다.

의뢰 완료는 카탈로그에 선언한 조건으로 판정한다. 언어 연습 의뢰는 승인된 정규 평가 증거, 조립 관찰 의뢰는 조립 snapshot을 읽으며 수락 이전의 유효한 증거도 인정한다. 대화 감상은 별도의 ‘이야기를 봄’ 기록으로 남기고 언어 숙달·건축 권리로 해석하지 않는다. 완료 버튼 자체는 검증 조건이 아니다.

## 6. 자연스러운 한국어와 기존 그림

사용자에게 보이는 말은 ‘책을 어디에 놓을까요?’, ‘문을 열어 주세요’, ‘친구가 왔어요’, ‘같이 정리해요’처럼 익숙한 표현을 중심으로 쓴다. 반닫이·소반·문방사우 같은 낯선 사물 이름을 의뢰 제목이나 필수 정답으로 쓰지 않는다. 기존 파일명은 바꾸지 않아도 된다.

건물 이름은 지도에서 정확히 사용하고 뜻을 UI 언어로 보조한다. 고급 단계의 어려움은 생소한 단어 수가 아니라 설명·협의·책임 범위·관점 비교에 둔다. 친구 말투도 관계를 먼저 설정하며, 반말 예문을 공손한 말 수업의 정답으로 혼동시키지 않는다. NPC 안내가 학습 수준보다 길면 DE/EN 도움·짧게 듣기·건너뛰기를 제공한다.

한국어가 의미 정본이다. DE/EN은 관계·의도·높임·시점·방향을 각각 재구성한다. 역사 설명은 출처를 검증하고, 현재의 가상 친구 방문과 구분한다.

현재 카탈로그의 스티커 30개와 장식 36개는 다른 화면에서도 쓰인다. 이번 작업은 사용 빈도와 상황 적합성을 높인다.

- 방문: 인사·손 흔들기. 고민: 생각하는 자세. 발견: 놀람. 성공: 박수·하이파이브·춤. 휴식: 쉬는 모습.
- 의미가 맞는 다른 그림이 있으면 연속 중복을 피한다. 한 대화 안에서는 선택한 그림을 유지해 깜빡이는 교체를 막는다.
- 첫 26단계 체험에서 각 친구의 서로 다른 승인 그림·클립을 최소 4종씩 볼 수 있도록 구성한다. 특별 방문 때만 나오는 친구의 짧은 반응 전환도 포함한다.
- 13챕터마다 기존 비캐릭터 스티커 또는 장식을 최소 1종 의미 있게 활용한다. 모든 30·36개 항목은 상황별 사용표에서 용도 또는 공간상 제외 이유를 기록한다.
- 기존 `Mascot.kTigerAsset` 정본을 교체하지 않는다. 퇴역한 그림은 재등록하지 않는다. 원본을 새로 그리거나 색을 바꾸지 않는다.
- 대화·의뢰의 임시 소품은 장식 소유권이 아니다. 영구 지급은 기존 소유·보상 journal·배치 허용 규칙을 사용한다. 새 장식 화폐나 별도 보상 시스템을 만들지 않는다.
- 소리·동행 숨김·움직임 줄이기를 존중한다. 음성과 효과음을 겹쳐 재생하지 않는다. 흰 배경 클립을 어두운 마당에 그대로 합성하지 않는다.

## 7. 사람을 위한 입체 공간

2.5D는 고정 구도의 그림과 깊이 순서·가림·확대·정해진 이동 지점으로 구현한다. 공사 중에는 각 공정의 정해진 시점을 쓰고, 완공 건물은 45도 간격 8방향으로 돌려 본다. 사람이 드나드는 폭·문턱·벽 두께·앞뒤 기둥·방과 마루를 유지한다.

대문 수용 기준: 바깥길 → 문턱 → 안쪽 마당의 3지점이 읽혀야 한다. 캐릭터의 짧은 이동에서 문 뒤로 가려졌다가 안쪽에 나타나며 같은 길로 돌아올 수 있어야 한다. 정본이 닫힌 문이라면 승인된 열린 문 그림 또는 분리 문 레이어를 준비한다. 끝에서 두 번째 공정 그림을 ‘문 열기’로 사용하지 않는다.

수직 공정 이미지 전체를 지도에 붙이지 않는다. 지도 구도에 맞는 터·바닥 변화와 완료 건물 앵커를 사용한다. 기존 불투명 프레임만으로 자유 회전 3D·물리 조립·임의 실내 보행이 구현됐다고 설명하지 않는다.

50개 공정 그림 자체는 승인됐다. 추가 아트 범위는 필요한 조립 토큰·지도 바닥 상태·사랑채 8면도·솟을대문 8면도 일치 보완·열린 문 상태다. 전체 건물 공정 그림을 다시 생성하지 않는다. 존재하는 8장도 정본 최종형·지붕·창·앞뒤 형태가 일치하는지 검수한다. WIP의 담장 clip path를 승인된 지도 외곽선이나 축척으로 재사용하지 않는다.

## 8. 진도 보존과 계정

획득 권리는 학습 서비스의 검증된 저장 결과로부터 계산한다. 화면·애니메이션·영수증은 권한 근거가 아니다. 평가 저장 → 권리 확정 → 조립 대기열 → 안전한 시점의 표시 순서다.

최신 main에는 사랑채 16단계 투영과 B2 완료 비율을 34단계에 대응한 투영이 있다. 새 149 ID 원장을 권리 정본으로 전환하고 기존 투영은 호환 표시로 정리한다. 과거 표시된 건물을 잃게 하지 않되, 과거 이미지 공개를 새 수동 조립 완료로 조작하지 않는다. 이미 보유한 공간에는 강제 재조립 대신 선택적인 조립 다시보기를 제공한다.

현재 정규 세대의 unit 완료는 새 고정 매핑으로 소급 인정한다. 옛 curriculum 세대의 완료를 현재 능력으로 재해석하지 않는다. 옛 사랑채 보유 상태와 현재 B2 공개 권리는 세대 이전 전에 근거와 함께 일회성 보존한다. 보존 정보를 읽지 못하면 오류·재시도로 드러내며 0으로 덮지 않는다.

권리·조립·의뢰 기록은 계정별로 저장한다. 익명 계정 연결·로그아웃·계정 변경·클라우드 복원·삭제·동의 철회 경로를 기존 계정 계약에 포함한다. 재시도와 동기화는 안정 ID로 중복 방지하고, 검증되지 않은 클라이언트 완료 플래그를 집합 합치기로 신뢰하지 않는다. 다른 계정의 미완료 비동기 쓰기는 새 계정에 적용하지 않는다.

내용 버전이 바뀌어도 이미 확정된 권리는 유지한다. 허용된 과거 평가 정의를 기록한다. 학습 기록만 저장되고 권리 생성 전에 종료된 경우에는 재계산으로 복구한다. 일회성 표시 실패가 학습·권리 손실로 이어지지 않게 한다.

새 진단·사용성 이벤트는 기존 동의 설정을 따르고 안정 ID·상태·오류 코드만 기록한다. 답변 원문·녹음·자유 입력·평가 객체 전체를 telemetry에 넣지 않는다. 사용성 관찰에서도 원문 수집 없이 성공·도움 요청·중단 이유를 필요한 범위에서 기록한다.

## 9. 설치와 상용화 연결

아트 149장의 합은 약 256.64 MiB였으며, 최종 정확한 값은 배정 감사 JSON에 기록한다. 이는 기기 다운로드나 설치 크기가 아니다. 기본 앱과 필요한 시점에 받는 한옥 팩을 분리하는 CP S5 작업에 합류한다.

Android는 Flutter deferred components와 Android dynamic feature modules를 사용한다. 독립적인 두 번째 다운로드 구현을 만들지 않는다. 공식 설명: https://docs.flutter.dev/perf/deferred-components (2026-09-15 확인).

기본 앱에는 처음 사용할 작은 자산과 핵심 학습을 넣는다. 첫 26단계 검증에서는 최종팩과 같은 지연 로딩 경로도 시험한다. 전체 26단계를 무조건 기본 앱에 넣는 것은 아니다. 내려받은 팩은 이후 오프라인에서 동작해야 한다. 아직 안 받은 팩의 오프라인 상태는 설명·재시도·나중에 만들기를 제공하며, 학습과 재료 획득은 계속된다. 초기 iOS는 같은 자산 카탈로그의 번들 구현으로 대응한다. Web은 개발 검증용이며 별도 제품을 만들지 않는다.

CP의 콘텐츠·보안·진도 내구성·접근성·음성·스토어 게이트를 유지한다. A1/A2 국제통용 커버리지, B1 문법 67항목 대응, 전 레벨 오류·검수 부채 해소를 한옥 기능으로 대체하지 않는다. B2–C2의 전체 어휘 확장을 이 작업에 몰래 추가하지 않는다.

## 10. 실행 순서와 판정

1. 최신 기준선·149개 배정·학습 권한·기존 사용자 보존 계약을 고정한다.
2. 평가 연결, 진도 저장, 그림·조립, NPC 연출, CP 자산 전달을 독립적으로 작업한다. 공유 파일 수정 책임은 한 곳으로 정한다.
3. 승인된 첫 학습 묶음과 첫 공간 변화로 짧은 체험을 검증한다.
4. 터·돌담·솟을대문 26단계와 9개 주요 조립 장면을 앱에서 완성해 내구성과 재미를 확인한다. 지도 합성은 별도 승인 전까지 제외하며 부정확한 WIP clipper로 이 중간 게이트를 채우지 않는다.
5. 동일 구조를 149단계·39개 조립 장면·26개 선택 의뢰로 완성한다.
6. 전체 학습·catch-up·계정·기기·CP 게이트를 통과한 정확한 후보 빌드로 관찰한다.

10주를 고정 기간으로 삼지 않는다. 앞서 제시한 5~6주/7~8주도 처리량을 측정하지 않은 추정이므로 확정 일정에서 제외한다. 첫 작업 묶음의 평가 검수·반려 수정·그림 준비·기기 검증 시간을 측정한 뒤 병렬 작업의 임계경로로 예상일을 갱신한다. 14일 안정성 관찰은 유지하며 표본 분모·동의 코호트·빌드 버전을 함께 기록한다. 초기 26단계 파일럿만으로 최종 전체 기능의 안정성 통과를 선언하지 않는다.
