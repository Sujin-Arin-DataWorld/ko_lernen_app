공정 합계는 건축 목표이고 회차의 잠금 조건이 아니다. 각 회차는 `당장 필요한 일 → 가르침/시범 → 도움 연습 → 선택·사용 → 작은 해결 → 다음 질문`을 갖는다. 쉬어 가는 측간·현대 생활 사건에는 핵심 비밀을 억지로 추가하지 않는다. 선택은 질문 순서·도울 사람·말의 표현·후일담을 바꾸고 확정 사실은 유지한다.

## 3. 교육과정과 사건을 연결하는 방법

### 3.1 AP-1 접근과 AC-1 학습 판정

**AP-1:** 단원의 `episode`는 사용할 수 있는 이야기 소재의 위치다. 수업 입장·레벨 통과의 조건이 아니다. 해당 회차를 아직 보지 않았다면 같은 목표의 **스포일러 없는 현대 자료**로 배우고, 본편에서 그 사실이 공개된 뒤 선택 재사용한다. 같은 시점의 이야기 사실은 모든 언어 수준에 번역·그림·음성 대안으로 제공한다. 이미 끝난 회차의 배움터는 복습·새 자료에 재사용하며, 다음 고택마다 입문을 재시작하지 않는다. S1-POST는 후속 장소 미정의 새 맥락 과제다.

**AC-1:** [기존 수행 확인 계약](../../learning/lernpfad-v2/curriculum/ASSESSMENT_CONTRACT.md)의 모든 문항 요구 필드를 사용한다. 선택 레벨과 언어 능력, 시범·도움·독립·지연/새 상황 수행을 구분한다. L/S/R/W를 따로 확인하고 미평가 말하기·쓰기를 자동 합격시키지 않는다. 실제 수업에는 뜻·형태·음성·사용 시범·도움 연습을 먼저 만든다. 조사 빈칸은 해당 기능을 가르친 뒤 제한된 확인으로만 사용할 수 있다.

선택한 레벨의 목표·진도 → 오늘 배움 → 짧은 사건·시작 행동 → 전체 경로·자유 학습·고택의 순서를 유지한다. 이야기 진도를 앞서 본 F0 학습자에게 상급 자료를 출제하지 않고, C2 첫 방문자에게 아/어를 강제하지 않는다.

## 5. 건축·보상·저장 계약을 연결하기 전의 실제 차이

특히 월드 `ansarang` / art `ansarangchae`, `anchae-store`의 표시명, 중문채/중문간채·아래채/아랫채를 alias 표로 대조한다. 기존 ID를 한쪽 이름으로 일괄 치환하지 않는다. 원격 main의 세 건축/월드 JSON은 현재 작업공간과 같은 바이트였다.

## 6. 파일 구조와 미래 인터페이스

아래 새 코드/JSON 이름은 **실행 단계의 제안**이다. 지금 존재하는 API라고 주장하지 않는다. 기존 클래스의 소유권을 유지하고 필요한 어댑터만 추가한다.

T9에서 제안할 계약:

- `SeasonStoryCatalog.fromJson(Map<String,dynamic>)`: episode/event/fact·단서·한국어 목표·원본 revision·대체 접근을 검증한다. 건축 이벤트가 이야기 사실을 자동 해금하지 않는다.
- `SeasonStoryProjector.project({required SeasonStoryCatalog catalog, required SeasonStoryState story, required String selectedBandId, required Set<String> eligibleObjectiveIds, required Set<String> ownedStageIds}) -> SeasonStoryProjection`: 다음 사건·필요 준비·학습/현대 대안·후일담만 계산한다. 화폐/숙달 쓰기 없음.
- `SeasonStoryProgressService.apply({required LernpfadLease lease, required StoryOperation operation, required String expectedGeneration}) -> Future<SeasonStoryState>`: owner·epoch·원 상태를 확인하고 동일 operation ID의 정확한 재시도는 같은 결과, 충돌한 재사용은 오류로 처리한다.
- `StoryOperation`: `operationId, storyRevision, eventId, actionKind, choiceId?, factIds, assistanceKinds, curriculumEvidenceRefs, occurredAt`. 새 언어 성취나 돈의 양을 입력으로 받지 않는다.
- `SeasonStoryState`: version 1, storyRevision, 본 owner 영역에서의 seenEventIds/factReceipts/choices/cursor/operationReceipts. 사실을 보았다는 근거와 독립 한국어 수행은 별도다. 계정별 `kl_season_story_v1_<encoded-owner>`에 저장하는 권장안이다.

원 언어 근거를 먼저 저장한 뒤 이야기 연결이 실패하면 같은 원 근거 참조로 재시도한다. 이야기 도움 완료는 언어 근거가 없어도 기록 가능하다. 삭제된 근거를 이야기 참조만으로 재생성하지 않는다. 본편에 필요한 기억은 이야기 도감에서 복구하고 언어 능력의 상태는 원 서비스가 판정한다.

## 7. 실행 작업과 완료 조건

각 작업은 입력 해시 확인 → 작은 산출물 → 해당 범위 검증 → 검토 기록 순서다. 현재 체크박스는 완료되지 않았다. 커밋이 필요하면 사용자 지시 후 본인 파일만 명시적으로 스테이징한다. 작업별 작은 커밋을 권장하되 자동 실행 지시로 읽지 않는다.

실행 시작 시 현재 브랜치/HEAD·원격 main·WIP와 활성 세션 소유 범위를 다시 확인한다. 현재 앱 파일 변경은 기존 작업이며 본 계획 산출물과 구별한다. 진행 중인 Blender 협문/R12·Lernen 디자인·게임·보상 작업공간을 자동 병합하거나 자산을 덮어쓰지 않는다. 현재 살아 있는 V3와 운영 기능 보존 문서를 먼저 대조하고 필요한 통합은 명시적인 변경 목록으로 수행한다.

## 8. 의존 관계와 실행 순서

`T1 세계 규칙 + T2 건축 대조 + T3 교육/기존 콘텐츠 대조 → T4 첫 묶음 → T5 중반/T6 결말 → T7 입문·A1/T8 상급 순차 제작 → T9 상태·연결 → T10 원장 확장 → T11 관찰·수정 → T12 공개/후속 확장`.

T1~T3의 읽기/저작 조사는 병행 가능하다. T5/T6 대본과 T7/T8 콘텐츠는 합의된 자료·교육 계약 안에서 별개 묶음으로 진행할 수 있다. T9의 순수 상태 테스트는 데이터 계약 후 시작할 수 있으나 미검수 대사를 공개하지 않는다. T10이 막혀도 이야기 대본·언어 제작을 계속한다. 실제 UI 디자인은 현재 보류다.

기획자 권장 실행 방식은 기존 WIP를 보존한 같은 작업공간에서 native로 작업 묶음을 진행하고, 각 큰 경계에서 서사·교육·기술 검토를 받는 것이다. 이는 미래 실행 권장안이며 이번에 구현을 시작했다는 뜻이 아니다.

## 11. 계획 자체의 검증과 공개 기준

이번 계획 완료는 **연결표의 전 범위·원본/이미지 관찰·현재 기술 차이·작업 순서·완료 조건을 정리하고 검토한 것**이다. T1~T12의 실제 제작 완료와 구분한다. 구조 검사에서 확인할 값은 100고유 unit_id·16구간·99필수+1선택·원 목표/전이/회수 일치·11동 합계128·33고유 hook·모든 stage_id 미확정 표시·이미지9·원본 해시다.

실행 중 공개 완료는 목표별 실제 가르침·사용·타당한 확인/미평가·저장/복구/복습·다음 행동·언어/역사/학습자 근거가 모두 있어야 한다. UI 플래그 복귀와 구버전 앱의 쓰기·백업/복원은 별도 검사한다. 디자인·스토리·교육 설계 파일이 있다는 이유로 앱 공개 가능으로 표시하지 않는다.
