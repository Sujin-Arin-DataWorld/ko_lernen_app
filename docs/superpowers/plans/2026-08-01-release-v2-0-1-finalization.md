# Hangul Sori v2.0.1 Android Release Finalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce and evidence a release-signed Android App Bundle that includes the current reviewed MP4/video, UI, and asset updates; install the corresponding release build on the connected Redmi test device; then record the exact committed/pushed source state.

**Architecture:** Treat the current worktree, not earlier audit claims, as the release candidate. Establish a reproducible Git and toolchain baseline, prove every bundled media reference resolves and obeys the one-live-decoder budget, run Flutter's source gates, then build one signed AAB. Device validation uses the APK generated by the same release build and records logcat evidence separately from source-test claims.

**Tech Stack:** Flutter/Dart, Gradle Android App Bundle, `video_player`, Android Debug Bridge, Git, PowerShell, `ffprobe`/Python media checks, Flutter tests.

## Global Constraints

- User explicitly authorized autonomous execution, required an AAB, requested Git completion, and asked that final facts be recorded in `AGENTS.md`.
- Work in the existing `main` checkout because it contains the pending release candidate and the connected-device configuration; preserve and inventory all pre-existing changes before staging.
- Do not use `git add -A`, `git reset --hard`, destructive cleanup, or force push. Stage only the reviewed release set; retain intentional non-bundled source backups outside the commit.
- `AGENTS.md` is the project SSoT: any changed file requires a dated session-log entry with scope, verification evidence, and the resulting commit hash.
- Android test device is M2101K6G / Redmi Note 10 / Snapdragon 678 / Android 12. At most one live H.264 `video_player` controller may remain active; the evidence gate is no `MediaCodec` reclaim / `ExoPlayerImpl` release caused by decoder contention.
- MP4/video code must retain the project fallback contract: `videoReady && !reduceMotion`, static/PNG fallback on failure, and no hard-coded user-facing strings outside DE/EN ARB files.
- The release version in `pubspec.yaml` is authoritative. Before Play upload, compare its versionCode with Play Console; increment only if that code is already consumed.
- A passing static/test/build gate is not evidence of production Firebase, Play Console, iOS, RevenueCat, or Store acceptance. Record only observed evidence.

### Task 4: Enforce exclusive native-video ownership

**Files:**
- Create: `lib/widgets/sori/video_lease.dart`, `test/sori_video_lease_test.dart`
- Modify: `lib/widgets/sori/{route_observer,tiger_video,character_clip,hanok_header}.dart`, `lib/screens/intro_gate_screen.dart`
- Modify/add only when covering the changed behavior: focused video ownership/widget tests

**Consumes:** Task 1 device profile, Task 2's current media inventory, and
Task 3's passing focused source gate.

**Produces:** A single app-wide lease for native `VideoPlayerController`
instances. Hidden `IndexedStack` tabs, page/modal routes, lifecycle pauses,
and transient character clips release the lease and display their existing
static fallback.

- [ ] **Step 1: Write and run the failing ownership-contract test first**

  Add pure-Dart fake-handle tests for the lease coordinator before production
  code. Prove: (a) existing owner is revoked before disposal and a new handle
  is created only after disposal; (b) rapid competing claims serialize with no
  more than one live fake handle; (c) a stale asynchronous initialization is
  disposed and never published; and (d) releasing a transient winner restores
  the newest still-eligible retained request.

  Expected: the focused test fails because the coordinator does not exist,
  and its exact red result is recorded before implementation.

- [ ] **Step 2: Implement the coordinator and migrate every direct owner**

  The coordinator must retain registered requests, choose only the newest
  eligible one, revoke the old UI before awaiting disposal, serialize all
  handoffs, and use a generation token for async completion. Eligibility must
  include `videoReady`, reduce-motion, `TickerMode`, app lifecycle, and
  `ModalRoute.isCurrent`. Change the observer to `RouteObserver<ModalRoute>`
  so modal sheets revoke underlying video as well as page routes.

  Migrate `TigerStageVideo`, `TigerGreetClip`, `CharacterClipPlayer`,
  `SoriPosterLoop`, and `_IntroVideo`. The greet-to-pace transition must
  release the greeting controller before requesting the loop; do not retain
  the former texture for a crossfade. Preserve existing audio, one-shot
  completion, and static fallback behavior. Afterwards, the only
  `VideoPlayerController.asset` construction in `lib/` is the coordinator's
  native adapter.

- [ ] **Step 3: Add regression and source-ownership guards**

  Test tab-like `TickerMode` transitions and modal-route handoff with a fake
  backend where practical. Add a source guard that rejects direct native
  construction outside `video_lease.dart`. Run all focused media/video tests.

  Expected: no test or source path can allocate two live native video handles
  during a handoff, and every client has a safe static fallback while it does
  not hold the lease.
