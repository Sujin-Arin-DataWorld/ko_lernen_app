# A1–C2 30 Phase 콘텐츠 완성 실행 계획

> 실행 담당자는 `superpowers:executing-plans`로 아래 작업을 순서대로 수행한다. 별도 에이전트 실행을 선택한 경우에만 `superpowers:subagent-driven-development`를 적용한다. 이 문서는 계획이며 콘텐츠 승격·커밋·배포 승인을 대신하지 않는다.

**Goal:** 매트릭스와 Phase의 필수 목표를 학습자가 앱에서 배우고 연습하고 평가받을 수 있도록 A1부터 C2까지 완성한다.

**Architecture:** 기존 30 Phase를 학습 순서로 유지하고, 기존 콘텐츠·평가 엔진에 명시적인 목표–콘텐츠–평가 연결을 추가한다. 감사기는 실제 실행 가능한 근거를 수집하며, Phase 진도는 유닛 방문이나 기존 이수 상태가 아니라 해당 과제의 유효한 평가 기록으로 계산한다.

**Tech Stack:** Flutter/Dart, 번들 JSON/CSV, Python 콘텐츠 도구, 기존 TTS·발음 평가, 기존 로컬 저장·계정 동기화.

**Spec:** 이 문서 §2–§6이 구현 명세다. 언어별 목표의 정본은 `tools/content_factory/cefr_matrix/{ko,phases,taxonomy}.json`, 내용의 레벨·작성 규칙은 `docs/CONTENT_LEVEL_BIBLE.md`다.

**발행 계약:** 항목별 검수 장부는 content ID, 내용 hash, KO/DE/EN 검수 결과, 문제·정답·루브릭 검수 결과, 승인 근거를 가진다. 내용 hash가 달라지면 이전 승인은 해당 개정판에 적용되지 않는다. 레벨별 공개 목록에서 의존성을 닫은 하위 집합을 구성하고 그 안의 자료·과제·평가 정의를 정확히 일치시킨다. 기존의 전역 `runtimeContentApproved`를 단순히 true로 바꾸어 전 레벨 초안을 노출하지 않는다.

### 작업 2 — 학습·평가·저장 흐름, KP01 시범 완성

- [ ] Phase 화면에서 목표 → 자료/설명 → 연습 → 평가 → 결과/재연습으로 이동한다. 기존 이미지를 사용하고 화면 문구는 DE/EN ARB로 제공한다.
- [ ] 새 `/learning-phase/task` 진입은 `phaseId`, `taskId`, `mode(practice/assessment)`를 가진 타입으로 전달한다. 로더가 승인된 연결을 재검증한다. 기존 `/course/reassess`의 완료 유닛 전용 제한을 해제해 Phase 경로를 우회시키지 않는다.
- [ ] 듣기·읽기는 자료에 근거한 문항으로 채점한다. 음성·글을 열어 본 기록은 수용 능력 평가를 대신하지 않는다. 해설은 정답의 근거 구절과 오답 이유를 제공한다.
- [ ] 기존 `ProductiveAssessmentCatalog`, 구조화 쓰기, 근거 연결, 녹음·발음 평가를 재사용한다. 기존 `CourseProgressService.app()`에 평가 카탈로그가 주입되지 않는 경로와 로더의 필수 주입 조건을 실제 앱에서 연결한다.
- [ ] 산출 과제는 기존 최소 0.7 및 `requiredForPass` 조건을 유지한다. 듣기·읽기는 정본 `masteryCheck`의 구체 기준을 적용한다(예: 3개 중 2개와 필수 정보 보존). 총점만 높고 필수 의미가 틀린 답은 통과시키지 않는다.
- [ ] 모든 문법을 한 글에 강제 삽입하지 않는다. 항목별 연습·평가는 별도로 커버하고 통합 숙달 과제에서는 기존 `variantPolicy`와 의미 충족 기준을 보존한다.
- [ ] 구조화 글쓰기의 필수 정보·극성·근거·문체와 녹음의 필수 의미를 검사한다. 단어만 나열하거나 부정된 주장, 무관한 외운 문장, 서로 모순되는 슬롯을 통과시키지 않는다. 채점할 수 없는 자유 답변은 `unscored`로 표시하고 숙달 기록을 만들지 않는다.
- [ ] 고급 자유 글쓰기는 모범 구조·루브릭·재작성 피드백을 제공한다. AI 의미 채점이 없는 이번 버전에서 전체 글의 논리·문체 능력을 인증했다고 표시하지 않는다.

```text
PhaseAttemptEvidence
  attemptId, phaseId, taskId, contentRevision, rubricVersion
  evaluatorVersion, mode, score, passedCriterionIds[], occurredAt

CourseMasterySnapshot v5
  기존 v4 필드 보존 + phaseTaskEvidence[]

CourseProgressService.recordPhaseAttempt(validatedResult)
  기존 직렬화 저장 경로에서 기록; 화면이 넘긴 임의의 통과 bool은 받지 않음
```

- [ ] v1–v4 → v5 이전 시 Phase 증거 목록은 빈 상태로 시작한다. 유닛·SRS·XP·배치 기록은 보존한다. 기존 완료를 Phase 이수로 변환하거나 재보상을 지급하지 않는다.
- [ ] Phase 완료 여부는 해당 개정판의 모든 필수 평가 요구를 충족한 증거에서 계산한다. 단순 방문·연습 기록은 별도다. 개정 전 기록은 이력으로 보존하며 내용/루브릭이 달라진 평가에는 새 증거가 필요하다.
- [ ] 계정 병합·백업·삭제·클라우드 동기화의 직렬화/검증에 v5를 포함한다. `attemptId` 중복은 한 번만 반영하고 같은 ID의 다른 내용은 기존 충돌 처리 방식으로 거절한다. 기기 두 대의 서로 다른 유효 시도는 합친다.
- [ ] 원문 답안·녹음은 클라우드 숙달 증거에 넣지 않는다. 쓰기 초안은 기기에 저장하고 계정 전환·삭제 시 기존 로컬 데이터 격리/삭제 경로에 포함한다. 채점 실패·오프라인·마이크 거절은 통과 기록 없이 재시도 경로를 제공한다.
- [ ] 새 듣기 자료와 발음 예문을 TTS corpus 수집에 포함한다. 기존 텍스트·화자·캐시 키 계약을 사용하고, 승인된 공개 범위의 음성이 실제로 재생 가능한지 확인한다.

**KP01 시범의 구체 결과:** 인사·소개 문법 12개에 대해 학습과 항목별 연습을 연결한다. 서로 다른 명찰/교실 표지 자료를 읽고, 가상 인물 카드로 등록 서식을 작성하고, 소개를 듣고 정보를 구분하고, 처음 만난 학습 동료에게 직접 소개·되묻기를 녹음한다. 한국어 원문과 DE/EN 안내, 정답·루브릭·TTS, 재시도·재시작·진도 기록까지 검증한다. KP01에서 공통 경로가 통과한 뒤 KP02 이후를 진행한다.

## 5. 검사기·테스트·품질 승인 기준

### 감사기 게이트

`CAP_GAP_TOTAL = 560` 하나로 완성 여부를 판정하지 않는다. 기존 총 갭은 추세용으로 남기고 다음을 별도 실패 조건으로 추가한다.

1. 문법 336개의 도입 누락/중복/원 급 불일치 0, 승인된 의미 대응 없는 항목 0.
2. 완료 선언 레벨의 필수 목표에서 미연결·미승인·실행 불가·평가 부재 0.
3. 해당 레벨의 필수 R/P 장르, 필수 산출/인식 화행, 문체, 발음·전이 목표 누락 0.
4. 완료 레벨의 `thin` 및 해결되지 않은 레벨/의미 불일치 0. 선택 목표의 결손과 `beyond_matrix`는 별도 정보로 유지한다.
5. 다른 레벨 재사용은 그 목표에 맞는 과제·근거가 있을 때만 인정한다. 해당 레벨에서 학습하지 못하는 상위 위치의 카드만으로 통과시키지 않는다.
6. 정본·보고서·앱 카탈로그·승인 hash·TTS 수집 목록의 신선도 검사. 레벨별·축별 상한은 작업 0의 보정된 기준선에서 시작하여 완료 시 0으로 낮춘다.

```powershell
python -B -X utf8 -m unittest tool.test_audit_curriculum_matrix tool.test_audit_learning_phases tool.test_build_learning_phase_catalog tools.content_factory.test_build_productive_assessments -q
```

새 산출물 빌더의 `--check`도 CI의 실제 콘텐츠 검증 경로와 변경 범위 선택기에 등록한다. 새 과제 자료는 `audit_content_levels.py`가 읽게 하고, 문서 장르의 문장/문법/어휘 위반을 함께 보고한다. TTS는 승인 범위의 실제 Storage 누락과 재생을 확인한다. Android와 Web에서 대표 사용 흐름을 검증하고, iOS 녹음·재생 미검증 사항이 있으면 별도 상태로 표시한다.

레벨별 데이터 승격 전 모든 새/변경 ID를 검토한다. `beyond-humanizer`의 의미·관계·화행 기준과 `du-sie-check`를 적용한다. 고급 단계에서는 함의·불확실성·반론·출처·문체 전환의 요구를 평가 기준에 실제로 반영했는지 별도로 확인한다. 자동 검사 통과는 이 검토를 대체하지 않는다.
