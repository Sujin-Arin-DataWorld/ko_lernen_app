1. Who is responsible

Local-first promise. Learning progress, custom packs, bookshelf content, and their managed photos stay on the device for an anonymous-only user. Learning-data cloud backup starts only after the user deliberately links a Google or Apple account.

2. Processing that can occur at app startup

Anonymous Firebase identity and Remote Config

After Firebase starts, the app creates or reuses an anonymous Firebase Authentication user. Its random Firebase UID is an identifier even though it has no linked name or email. The app then contacts Firebase Remote Config to fetch a visual-configuration value. The anonymous identity may also support optional authenticated features such as study groups, sharing, and push-token ownership; it does not enable learning-progress or bookshelf backup by itself.

RevenueCat and purchases

If a platform RevenueCat public SDK key is present in the build, the release-candidate app waits for a ready, matching Firebase session and configures RevenueCat with that Firebase UID as its custom app user ID. It then obtains customer and entitlement information and listens for updates. RevenueCat can therefore process the Firebase UID, customer/entitlement information, and purchase or transaction state before the user makes a new purchase in that session. The identifier and purchase history must be treated as linked to the user. If no platform SDK key is present, the app does not configure RevenueCat. The exact signed build and live RevenueCat project remain release-verification gates.

3. Local data and optional cloud backup

The app stores learning progress, SRS state, game results, streaks, preferences, custom packs, bookshelf entries, notes, and managed book/word photos locally. Local storage remains the source of truth.

When the user explicitly links a Google or Apple account, Firestore backup/sync becomes eligible under that durable account's Firebase UID. Backup can include learning progress, game and streak data, SRS state, custom packs, and bookshelf text. Google or Apple sign-in can also provide the provider association and, when supplied by the provider, email address and display name.

Managed photo references and image bytes are removed from portable Firestore and shared payloads. Linking an account does not upload book or word photos.

4. Optional features

Optional tester feedback

After completing supported learning content, testers may voluntarily send structured feedback and optional free text so that we can identify technical or content problems and improve the learning experience. The submission contains the selected feedback category or structured assessment and any message the tester chooses to provide. The app automatically adds only the minimal context needed to interpret the report: content and completion identifiers, a content label, level and score summary where available, app version, platform, language setting, and an optional tester-mission identifier. The feedback is processed securely through Firebase and stored under the current Firebase UID, so free text may be associated with that UID. Raw exercise answers and device identifiers are not sent. Stored feedback is removed as part of account deletion.

Analytics and crash reports

Firebase Analytics and Firebase Crashlytics are separate voluntary opt-ins and are off by default in the native configuration. They may process app interactions, device/app information, identifiers, diagnostics, and crash traces after the relevant opt-in. Turning Crashlytics off stops future collection and asks the SDK to delete unsent local reports on a best-effort basis; it does not delete reports already transmitted under the provider/project retention settings.

Notifications

Firebase Cloud Messaging automatic initialization is off. The app requests notification permission and an FCM registration token only when the notification feature is enabled. The token is associated with the current Firebase UID for delivery. Disabling the feature invalidates the local token and attempts server removal; remote cleanup is retryable and is not guaranteed to be instantaneous.

Study groups (Gye)

Gye is optional community functionality protected by a local, year-only, self-attested age gate. The entered birth year stays on the device; it is not identity or age verification. When used, the app can process the Firebase UID, nickname, membership and role, group metadata, level/streak and contribution summaries, fixed feed events, fixed reactions/stickers/cheers, report reasons and optional report notes, block lists, moderation and cleanup markers, and notification-outbox data. The feature is presented for users who pass the app's 16+ gate.

Photos, OCR, analysis, and translation

Camera/gallery access is optional. The selected or captured image is cropped and recognized on-device with ML Kit and remains in app-managed local storage. Image bytes are not sent in the analysis or portable-backup payloads. When the user requests analysis, OCR-extracted text, including manual corrections, and the requested target language are sent over HTTPS to the configured analysis function. Text segments can be sent to DeepL for translation. The analysis service can store source segments and translations in a server-side translation cache; its live location and retention follow the deployed Firebase/Google project configuration.

Pronunciation audio

Built-in audio may be downloaded from Firebase Storage. When the user requests pronunciation for dynamic or user-entered Korean text, that text is sent over HTTPS to the configured TTS function and Google Cloud Text-to-Speech. Generated audio may be cached in Firebase Storage and on the device.

The optional pronunciation assessment is separate from playback and starts only after explicit voice-processing consent and microphone permission. A microphone recording of no more than 10 seconds and the displayed Korean reference phrase are sent through an authenticated, App Check-protected Firebase callable in europe-west3 to Microsoft Azure Speech in germanywestcentral. Hangul Sori does not write the recording, reference phrase, recognized words, or Gye-member identities to its server storage or logs. The callable returns only aggregate pronunciation, accuracy, fluency, and completeness scores plus a client-generated duplicate-prevention ID. The device stores those scores, the count of passed assessments, and bounded duplicate-prevention IDs as learning progress. A per-account rate-limit document stores only counters and time buckets under the Firebase UID. Azure acts as a processor for the transient assessment request under its configured service terms. Turning voice assessment off prevents future recordings; listen-and-repeat remains available.

Sharing

If the user deliberately shares a pack, a portable payload without local image references is uploaded for the sharing function. The Firebase UID can be stored as its creator identifier.

6. Security, locations, and retention

Network data is encrypted in transit using HTTPS/TLS. The repository configures the Gye and TTS functions for europe-west3, and the documented default analysis endpoint also uses europe-west3. This does not prove that every Firebase, Google, DeepL, Apple, or RevenueCat service or every datum is stored in the EU. Firestore, Authentication, Analytics, Crashlytics, Storage, RevenueCat, integration, and retention settings must be verified in the live consoles. We do not state fixed retention periods where the repository does not prove them.

  • Request access, correction, export, or processor-side RevenueCat erasure help at hello@hangul-sori.com.

See Account & Data Deletion for what each action does, subscription cancellation, and limits on already transmitted provider records.

2. Verarbeitung beim App-Start

Anonyme Firebase-Identität und Remote Config

Nach dem Firebase-Start erstellt oder verwendet die App einen anonymen Firebase-Authentication-Nutzer. Die zufällige Firebase-UID ist ein Identifikator, auch wenn kein Name und keine E-Mail-Adresse verknüpft sind. Danach ruft die App bei Firebase Remote Config einen Wert für die visuelle Konfiguration ab. Die anonyme Identität kann außerdem optionale authentifizierte Funktionen wie Gye, Teilen und Push-Zuordnung ermöglichen; allein aktiviert sie kein Lernfortschritts- oder Bücherregal-Backup.

RevenueCat und Käufe

Wenn im Build ein öffentlicher RevenueCat-SDK-Schlüssel für die Plattform vorhanden ist, wartet der Release-Kandidat auf eine bereite, passende Firebase-Sitzung und konfiguriert RevenueCat mit dieser Firebase-UID als benutzerdefinierter App-User-ID. Danach ruft die App Kunden- und Berechtigungsinformationen ab und hört auf Änderungen. RevenueCat kann daher Firebase-UID, Kunden-/Berechtigungsinformationen sowie Kauf- oder Transaktionsstatus verarbeiten, bevor in dieser Sitzung ein neuer Kauf erfolgt. Kennung und Kaufhistorie sind als mit dem Nutzer verknüpft zu behandeln. Ohne Plattform-SDK-Schlüssel wird RevenueCat nicht konfiguriert. Der genaue signierte Build und das Live-RevenueCat-Projekt bleiben Release-Prüfpunkte.

3. Lokale Daten und optionales Cloud-Backup

Lernfortschritt, SRS-Status, Spielergebnisse, Streaks, Einstellungen, eigene Lernpakete, Bücherregal-Einträge, Notizen sowie verwaltete Buch-/Wortfotos werden lokal gespeichert. Der lokale Speicher bleibt die maßgebliche Datenquelle.

Erst nach einer ausdrücklichen Google- oder Apple-Verknüpfung ist Firestore-Backup/Sync unter der Firebase-UID dieses dauerhaften Kontos zulässig. Gesichert werden können Lernfortschritt, Spiele und Streaks, SRS, eigene Lernpakete und Bücherregal-Text. Google/Apple können außerdem die Anbieterzuordnung und, soweit bereitgestellt, E-Mail-Adresse und Anzeigename liefern.

Verwaltete Fotoreferenzen und Bildbytes werden aus portablen Firestore- und Teilen-Payloads entfernt. Eine Kontoverknüpfung lädt keine Buch- oder Wortfotos hoch.

4. Optionale Funktionen

Optionales Testfeedback

Nach dem Abschluss unterstützter Lerninhalte können Testpersonen freiwillig strukturiertes Feedback und optional einen Freitext senden, damit wir technische oder inhaltliche Probleme erkennen und das Lernerlebnis verbessern können. Die Übermittlung enthält die gewählte Feedback-Kategorie beziehungsweise strukturierte Bewertung und eine gegebenenfalls eingegebene Nachricht. Die App ergänzt automatisch nur die zur Einordnung erforderlichen Kontextdaten: Inhalts- und Abschlusskennungen, eine Inhaltsbezeichnung, soweit vorhanden, Niveau und Ergebniszusammenfassung, App-Version, Plattform, Spracheinstellung sowie optional die Kennung einer Tester-Mission. Das Feedback wird sicher über Firebase verarbeitet und unter der aktuellen Firebase-UID gespeichert; Freitext kann daher dieser UID zugeordnet werden. Rohe Übungsantworten und Gerätekennungen werden nicht übermittelt. Gespeichertes Feedback wird bei der Kontolöschung mitgelöscht.

Analytics und Crashberichte

Firebase Analytics und Firebase Crashlytics sind getrennte freiwillige Opt-ins und nativ standardmäßig ausgeschaltet. Nach dem jeweiligen Opt-in können App-Interaktionen, Geräte-/App-Informationen, Kennungen, Diagnosen und Crash-Traces verarbeitet werden. Das Ausschalten von Crashlytics beendet künftige Erfassung und fordert bestmöglich die Löschung noch nicht gesendeter lokaler Berichte an; bereits übermittelte Berichte werden dadurch nicht außerhalb der Provider-/Projektaufbewahrung gelöscht.

Benachrichtigungen

Die automatische FCM-Initialisierung ist aus. Systemberechtigung und FCM-Registrierungstoken werden erst beim Aktivieren der Benachrichtigungsfunktion angefordert. Der Token wird für die Zustellung der aktuellen Firebase-UID zugeordnet. Beim Deaktivieren wird der lokale Token ungültig gemacht und die Serverentfernung versucht; die entfernte Bereinigung ist wiederholbar, aber nicht garantiert sofort.

Lerngruppen (Gye)

Gye ist eine optionale Community-Funktion mit einer lokal gespeicherten, jahresgenauen Selbstauskunft zum Alter. Das eingegebene Geburtsjahr bleibt auf dem Gerät; die Abfrage ist keine Identitäts- oder Altersverifikation. Verarbeitet werden können Firebase-UID, Spitzname, Mitgliedschaft/Rolle, Gruppenmetadaten, Level-/Streak- und Beitragszusammenfassungen, feste Feed-Ereignisse, feste Reaktionen/Sticker/Cheers, Meldegründe und optionale Meldungsnotizen, Blocklisten, Moderations-/Bereinigungsmarker und Benachrichtigungs-Outbox-Daten. Die Funktion wird Nutzern angeboten, die das appinterne 16+-Gate passieren.

Fotos, OCR, Analyse und Übersetzung

Kamera/Galerie sind optional. Das Bild wird auf dem Gerät zugeschnitten und mit ML Kit erkannt und verbleibt im verwalteten lokalen App-Speicher. Bildbytes sind nicht Teil von Analyse- oder portablen Backup-Payloads. Bei einer angeforderten Analyse werden OCR-Text einschließlich manueller Korrekturen und Zielsprache über HTTPS an die konfigurierte Analysefunktion gesendet. Textteile können zur Übersetzung an DeepL gehen. Der Analysedienst kann Quellsegmente und Übersetzungen in einem serverseitigen Übersetzungs-Cache speichern; Live-Speicherort und Aufbewahrung richten sich nach der eingesetzten Firebase-/Google-Projektkonfiguration.

Aussprache-Audio

Vorproduziertes Audio kann aus Firebase Storage geladen werden. Bei angeforderter Aussprache dynamischer oder selbst eingegebener koreanischer Texte wird der Text über HTTPS an die konfigurierte TTS-Funktion und Google Cloud Text-to-Speech gesendet. Erzeugtes Audio kann in Firebase Storage und lokal zwischengespeichert werden.

Die optionale Aussprachebewertung ist von der Wiedergabe getrennt und beginnt nur nach einer ausdrücklichen Einwilligung in die Sprachverarbeitung und der Mikrofonberechtigung. Eine Aufnahme von höchstens 10 Sekunden und der angezeigte koreanische Referenzsatz werden über eine authentifizierte und durch App Check geschützte Firebase-Callable-Funktion in europe-west3 an Microsoft Azure Speech in germanywestcentral gesendet. Hangul Sori schreibt weder Aufnahme noch Referenzsatz, erkannte Wörter oder Identitäten von Gye-Mitgliedern in Serverspeicher oder Logs. Zurückgegeben werden nur zusammengefasste Werte für Aussprache, Genauigkeit, Sprechfluss und Vollständigkeit sowie eine vom Client erzeugte ID gegen Doppelzählung. Auf dem Gerät werden diese Werte, die Zahl bestandener Bewertungen und eine begrenzte Liste der Doppelzählungs-IDs als Lernfortschritt gespeichert. Ein nutzerbezogenes Rate-Limit-Dokument speichert unter der Firebase-UID nur Zähler und Zeitfenster. Azure verarbeitet die vorübergehende Bewertungsanfrage als Auftragsverarbeiter gemäß der konfigurierten Dienstbedingungen. Das Ausschalten der Sprachbewertung verhindert weitere Aufnahmen; Anhören und Nachsprechen bleiben verfügbar.

Teilen

Wenn ein Nutzer bewusst ein Lernpaket teilt, wird ein portables Payload ohne lokale Bildreferenzen hochgeladen. Die Firebase-UID kann als Erstellerkennung gespeichert werden.

지원되는 학습 콘텐츠를 완료한 뒤 테스터는 기술적·콘텐츠 문제를 파악하고 학습 경험을 개선할 수 있도록 구조화된 피드백과 선택적 자유 텍스트를 자발적으로 보낼 수 있습니다. 제출 내용에는 선택한 피드백 범주 또는 구조화된 평가와 사용자가 입력하기로 한 메시지가 포함됩니다. 앱은 보고서를 이해하는 데 필요한 최소한의 맥락만 자동으로 추가합니다. 여기에는 콘텐츠 및 완료 식별자, 콘텐츠 이름, 가능한 경우 수준과 점수 요약, 앱 버전, 플랫폼, 언어 설정과 선택적 테스터 미션 식별자가 포함됩니다. 피드백은 Firebase를 통해 안전하게 처리되고 현재 Firebase UID 아래에 저장되므로 자유 텍스트가 해당 UID와 연결될 수 있습니다. 원시 연습 답변과 기기 식별자는 전송되지 않습니다. 저장된 피드백은 계정 삭제 시 삭제됩니다.

Analytics 및 오류 보고

Firebase Analytics와 Firebase Crashlytics는 서로 분리된 자발적 동의 항목이며 네이티브 설정에서 기본적으로 꺼져 있습니다. 각각 동의한 뒤 앱 상호작용, 기기/앱 정보, 식별자, 진단 정보와 크래시 추적이 처리될 수 있습니다. Crashlytics를 끄면 향후 수집을 중단하고 전송 전 로컬 보고서 삭제를 최선의 방식으로 요청하지만, 이미 전송된 보고서를 공급자/프로젝트 보관 설정 밖에서 삭제하지는 못합니다.

알림

FCM 자동 초기화는 꺼져 있습니다. 알림 기능을 켤 때만 시스템 권한과 FCM 등록 토큰을 요청하며, 토큰은 전송을 위해 현재 Firebase UID에 연결됩니다. 기능을 끄면 로컬 토큰을 무효화하고 서버 삭제를 시도합니다. 원격 정리는 재시도되지만 즉시 완료를 보장하지 않습니다.

학습 그룹(Gye)

Gye는 연도만 입력하는 로컬 자기진술 연령 게이트를 거치는 선택적 커뮤니티 기능입니다. 입력한 출생 연도는 기기에만 남으며, 이는 신원이나 연령 검증이 아닙니다. 이용 시 Firebase UID, 닉네임, 멤버십/역할, 그룹 메타데이터, 레벨/연속 학습/기여 요약, 고정 피드 이벤트, 고정 반응·스티커·응원, 신고 사유와 선택적 신고 메모, 차단 목록, 관리·정리 마커와 알림 아웃박스 데이터가 처리될 수 있습니다. 앱의 16세 이상 게이트를 통과한 사용자에게 제공됩니다.

사진, OCR, 분석 및 번역

카메라/갤러리는 선택 사항입니다. 선택하거나 촬영한 이미지는 기기에서 자르고 ML Kit으로 인식하며 앱 관리 로컬 저장소에 남습니다. 이미지 바이트는 분석 또는 이동 가능한 백업 데이터에 포함되지 않습니다. 사용자가 분석을 요청하면 수동 수정이 포함된 OCR 추출 텍스트와 대상 언어가 HTTPS로 설정된 분석 함수에 전송됩니다. 텍스트 일부는 번역을 위해 DeepL에 전송될 수 있습니다. 분석 서비스는 원문 일부와 번역을 서버 측 번역 캐시에 저장할 수 있으며, 실제 저장 위치와 보관 기간은 배포된 Firebase/Google 프로젝트 설정을 따릅니다.

발음 음성

내장 음성은 Firebase Storage에서 내려받을 수 있습니다. 동적 또는 사용자 입력 한국어의 발음을 요청하면 텍스트가 HTTPS로 설정된 TTS 함수와 Google Cloud Text-to-Speech에 전송됩니다. 생성 음성은 Firebase Storage와 기기에 캐시될 수 있습니다.

선택적 발음 평가는 음성 재생과 분리되어 있으며, 별도의 음성 처리 동의와 마이크 권한을 받은 뒤에만 시작됩니다. 최대 10초의 마이크 녹음과 화면에 표시된 한국어 기준 문장은 인증 및 App Check로 보호된 europe-west3 Firebase callable 함수를 거쳐 germanywestcentral의 Microsoft Azure Speech로 전송됩니다. Hangul Sori는 녹음, 기준 문장, 인식된 단어 또는 Gye 계원의 신원을 서버 저장소나 로그에 기록하지 않습니다. 함수는 종합 발음·정확도·유창성·완성도 점수와 클라이언트가 만든 중복 방지 ID만 반환합니다. 기기에는 해당 점수, 통과한 평가 횟수, 제한된 중복 방지 ID 목록이 학습 진도로 저장됩니다. Firebase UID 아래의 사용량 제한 문서에는 횟수와 시간 구간만 저장됩니다. Azure는 설정된 서비스 조건에 따라 일시적인 평가 요청을 처리합니다. 발음 평가 동의를 끄면 이후 녹음은 중단되며 듣고 따라 말하기는 계속 사용할 수 있습니다.

공유

사용자가 단어장을 직접 공유하면 로컬 이미지 참조를 제거한 이동 가능 데이터가 업로드됩니다. Firebase UID가 생성자 식별자로 저장될 수 있습니다.

6. 보안, 위치 및 보관

네트워크 데이터는 HTTPS/TLS로 전송 중 암호화됩니다. 저장소는 Gye 및 TTS 함수를 europe-west3로 설정하고, 문서화된 기본 분석 엔드포인트도 europe-west3를 사용합니다. 이것이 모든 Firebase, Google, DeepL, Apple, RevenueCat 서비스나 모든 데이터가 EU에 저장됨을 뜻하지는 않습니다. Firestore, Authentication, Analytics, Crashlytics, Storage, RevenueCat, 연동 및 보관 설정은 실제 콘솔에서 확인해야 합니다. 저장소가 증명하지 않는 고정 보관 기간은 명시하지 않습니다.
