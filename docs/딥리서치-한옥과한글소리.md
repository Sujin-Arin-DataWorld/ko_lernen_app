# 한글소리 ‘살아 있는 종갓집’ 한옥 월드 설계 백서

## 연구 결론 — 지금 필요한 것은 “건물을 더 넣는 것”이 아니라 “한옥의 공간 질서를 게임으로 만드는 것”이다

보내주신 다섯 장의 참고 이미지를 보고, 저장소의 2026년 8월 16일~19일 한옥 관련 HANDOFF·설계문서·현재 자산 구조를 대조하고, 국가한옥센터·국가유산청·국립민속박물관·UNESCO·CEFR 원문까지 다시 조사한 결론은 꽤 명확하다.

**지금 한글소리 한옥이 약간 “90년대 마비노기 마을처럼 복잡해지는” 문제는 한옥 건물이 많아서가 아니다.**  
문제는 건물을 하나씩 “획득하는 독립 오브젝트”처럼 같은 화면 위에 계속 추가하기 때문이다.

실제 조선시대 반가의 핵심 문법은 **채(건물) + 마당 + 문/담장 + 동선의 위계**다. 안채·사랑채·행랑채·별당·사당은 서로 다른 성격의 마당과 함께 조직되며, 한옥의 마당은 기본적으로 비워 두는 공간이었다. 사랑마당은 대문 쪽으로 비교적 개방되고, 안마당은 외부 시선으로부터 보호되며, 사당은 별도 담장과 문을 가진 독립 영역으로 두는 방식이 전형적이었다. citeturn10search0turn13view4

따라서 한글소리의 최종 한옥은 **“건물 수집 게임”이 아니라 “한 가문의 공간이 점차 질서를 얻는 게임”**이어야 한다.

제가 제안하는 최종 목표는 특정 실제 문화유산 한 채를 복제하는 것이 아니라,

> **조선후기 영남·중부 사대부 반가와 종가의 공간문법을 종합한 가상의 ‘한글소리 종가’**

이다.

하회·양동 같은 씨족마을은 종가와 사당, 큰 목조주택, 누정·학습 공간, 산·물·수목을 포함한 경관 전체가 유교적 사회질서와 연결되어 있었고, UNESCO도 건물 하나가 아니라 **주택·위계적 배치·학습공간·자연경관의 앙상블**을 그 핵심 가치로 본다. citeturn11search0turn11search1

그리고 여기에는 아주 중요한 미술 방향이 하나 따라온다.

**“사대부의 화려함”은 궁궐 같은 화려한 단청이나 물건이 빽빽한 화려함이 아니다.**

국가한옥센터 자료는 조선 살림집이 유교적 절제와 가사제한의 영향 아래 비교적 소박하게 장식되었고, 특히 민간 살림집의 단청·공포 등은 제한되었다고 설명한다. 사랑방 역시 사방탁자·문갑·책장·문방소품·방석·팔걸이·목침 등으로 **간소하게** 꾸미는 공간이었다. citeturn13view3

그래서 한글소리의 “엄청 부유한 종갓집”은 다음으로 부유해 보여야 한다.

**넓은 대지, 여러 겹의 문, 깊은 마당, 좋은 목재, 고운 기와선, 높은 솟을대문, 큰 사랑채와 누마루, 잘 가꾼 후원, 석축과 화계, 좋은 창호, 정갈한 장독대, 독립된 사당, 책과 문방구, 계절에 따라 변하는 나무와 정원.**

반대로 피해야 할 것은 **건물마다 단청, 등롱 20개, 색색의 소품, 거대한 연못, 사방에 장독·석등·나무·꽃·우물·표지판·반짝이 아이콘을 동시에 놓는 방식**이다. 국가한옥센터가 설명하는 전통 마당 자체가 “행사를 위해 보통 비워 두는 공간”이라는 점은 이 디자인 문제에 거의 정답을 준다. citeturn13view3

## 저장소와 HANDOFF를 전부 대조한 현재 상태

## 조선 사대부 종가의 공간 문법과 한글소리 최종 설계도

### 먼저 바로잡아야 할 용어

한옥 설계에서 이것은 아주 중요하다.

**사랑채와 사랑방은 같은 것이 아니다.**

사랑채는 하나의 채이고, 그 안에 사랑방·침방·사랑대청·누마루·서고 등이 들어갈 수 있다. 국가한옥센터도 사랑채를 남성 중심의 일상·접객 공간으로 설명하면서 대청, 누마루, 침방, 서고가 포함된다고 명시한다. citeturn13view4

마찬가지로:

**안채 ≠ 안방.**  
안채 안에 안방·건넌방·안대청·부엌·곳간 등이 들어간다. citeturn13view4

그리고 현재 앱에서 특히 수정하고 싶은 것이 하나 있다.

**대청마루는 원칙적으로 “하나의 독립 건물 종류”라기보다 채 안에 있는 마루 공간이다.**

안채에는 안방과 건넌방 사이에 안대청이 있고, 사랑채에는 사랑대청이 있다. 국가유산 두곡고택도 사랑채 5칸 가운데 대청 2칸과 방 2칸 등을 둔다. citeturn13view4turn9search14

따라서 현재 `daecheongmaru.png`를 버릴 필요는 없지만, 최종 종가에서는 세 가지 중 하나로 바꾸는 것이 좋다.

**가장 추천:** 사랑채와 안채 사이의 “열린 전이공간”을 상징하는 시각 레이어로 통합하고, 유저가 탭하면 **사랑대청/안대청 내부 venue** 중 하나로 들어간다.

또는 외관을 약간 수정해 **누정·정자 계열**로 승격한다.

반면 지금처럼 “솟을대문 / 안채 / 사랑채 / 사당 / 대청마루”를 모두 동일 레벨의 독립 건물 카드처럼 보여주면 건축학적으로도 조금 어색하고, 게임 지도도 더 잘게 쪼개져 보인다.

### 제가 권하는 종가의 성격

한글소리 종가는 **조선후기 영남 반가를 중심으로 한 복합형 종가**가 가장 잘 맞는다.

국가한옥센터는 영남 북부 반가에서 ㄷ자형을 볼 수 있고, 안동에서는 ㅁ자형이 두드러진다고 설명한다. citeturn10search1

실제 덕산고택은 안마당을 중심으로 안채·사랑채·행랑채가 연결된 전형적인 ㅁ자형 구성을 보이며 대문간채·방앗간채·서당 같은 부속채도 갖춘다. citeturn9search11

두곡고택은 사랑채, 중문, ㄱ자 안채, 아래채, 곳간·행랑, 방앗간 등을 갖춰 큰 사대부가의 기능 분화를 잘 보여준다. citeturn9search14

또 다른 상류주택 사례에서는 사랑채와 안채 사이를 중문과 담으로 구분하고, 사랑채 앞에 행랑채와 **행랑마당/작업마당**을 둔 구조도 확인된다. citeturn9search9

즉 게임에서는 어느 한 고택의 평면을 복사하지 않고 이 공통 원리를 취하면 된다.

### 이 설계에서 “고급 종갓집”으로 보이는 핵심

건물 수보다 **경계의 수**를 늘리는 것이 중요하다.

유저는 다음 순서로 공간의 깊이를 체감해야 한다.

`바깥길 → 솟을대문 → 행랑마당 → 사랑마당 → 중문/일각문 → 안마당 → 뒤뜰/화계 → 사당담 → 사당`

이렇게 하면 같은 1536×1152 화면에서도 단순히 집 여덟 채가 있는 것이 아니라 **“밖 → 반공적 → 가족 → 내밀 → 조상/후원”이라는 공간 서사**가 생긴다.

실제 씨족마을과 종가는 지형·경관·유교적 위계가 함께 작동했고, UNESCO도 하회·양동의 가치를 이와 같은 위계적 배치와 자연경관의 결합에서 찾는다. citeturn11search1

### 후원은 “놀이공원”이 아니어야 한다

국가한옥센터는 전통 정원에 화계, 담장, 문, 굴뚝, 장독대, 연못, 석물, 수목, 다리, 산책로 등이 사용되었고, 후면 경사지는 계단형 화계로 꾸민 경우가 많다고 설명한다. 누마루 주변에 연못과 수목을 배치하여 경관을 즐기기도 했다. citeturn10search0turn13view3

따라서 나무·정자·우물·연못을 모두 넣을 수는 있다.

하지만 **같은 마당에 넣지 않는다.**

제가 추천하는 분리는:

- **후원:** 노송·매화·화계·바위·작은 연못·정자
- **안마당 뒤:** 장독대
- **작업마당:** 우물·빨랫줄·물동이·광주리·장작
- **사랑마당:** 거의 비움 + 괴석/소나무 한 군락 정도
- **사당마당:** 거의 완전히 비움
- **대문 주변:** 큰 수목보다 담·기단·문 자체가 주인공

이다.

그렇게 해야 “정갈한 대가집”이 된다.

### 사랑방 자산은 현재 방향이 꽤 좋다

현재 HANDOFF에서 잡힌 사방탁자·보료·방석·반닫이·화로·등잔대·거문고·바둑·목침·소병풍·고비·향로는 대부분 공간 서사에 잘 들어간다. fileciteturn10file0L1-L7

국가한옥센터가 직접 사랑방 가구로 사방탁자·문갑·책장·문방소품·방석·팔걸이·목침 등을 언급하고 있고, 국립민속박물관도 사랑방의 대표 물건으로 서안, 문방사우, 연상, 책가도 병풍 등을 소개한다. citeturn13view3turn9search4

문방사우는 붓·먹·종이·벼루이고, 서안은 좌식 생활에서 읽고 쓰는 낮은 책상이다. citeturn9search1

사랑방은 과거시험을 준비하고 공부하는 장소로도 활용되었다. citeturn9search3turn9search7

그래서 여기서 중요한 것은 **소품을 더 많이 만드는 것보다 “사용 장면”을 만드는 것**이다.

예를 들어:

- 서안 + 문방사우 → 글쓰기
- 연상 → 벼루·문구 꺼내기
- 고비 → 편지 읽기
- 사방탁자 → 책/향로 전시
- 바둑 → 상대방과 추론·상태 설명
- 거문고 → 음악·감정·풍류 대화
- 보료·안석 → 집주인 접객 위치
- 방석 두 장 → 손님 도착 상태
- 향로 → 특별 이벤트 상태
- 화로 → 겨울 상태

로 만들면 소품 12개가 단순 decoration이 아니라 **언어행동 socket**이 된다.

여기서도 전부 사랑방 한 화면에 넣지 않는 것이 중요하다.

예컨대 **경대는 안방**, 연상·망건통은 사랑방, 약장은 별도 생활맥락, 자개함/보석함은 안방·별당, 백자병은 선반/사방탁자 같은 식으로 **공간 소속을 나눠야 한다.**

그래야 에셋을 많이 만들어도 화면이 복잡해지지 않는다.

### 한옥에서 “성별 공간”은 게임에서 너무 딱딱하게 고정하지 않는 것이 좋다

역사 자료는 안채를 여성 중심, 사랑채를 남성 중심 공간으로 설명한다. citeturn13view4turn9search2

하지만 게임 문구에서는 “남자는 절대로 여기 못 들어간다 / 여자는 절대로 사랑채를 쓰지 않는다”처럼 현대 사용자가 절대 규칙으로 오해하게 쓰기보다,

**“조선 사대부가에서 관습적으로 남성의 접객·학문 영역과 여성 중심의 안살림 영역을 공간적으로 구분하였다”**

정도로 교육하는 것이 더 정확하고 교육적으로도 안전하다.

## 맨땅에서 종갓집이 완성되는 전체 건축 진행

### 기존 A1 시공 순서는 버릴 이유가 없다

국가한옥센터가 제시하는 한옥 공사의 공식적인 큰 흐름은:

**집터잡기 → 설계 → 기초공사 → 초석 → 치목 → 조립 → 기와 → 수장 → 흙벽 → 온돌·마루·창호 마감 → 주변가꾸기 → 입택**

이다. citeturn13view0turn13view1

현재 한글소리의 A1 16단계는 이것을 게임에 맞게 훌륭하게 세분화했다. fileciteturn30file0L1-L2

| 현재 A1 | 실제 시공과의 관계 |
|---|---|
| 터잡기 | 공식 집터잡기 |
| 설계 | 설계 |
| 기초·기단 | 기초공사 |
| 초석 | 초석놓기 |
| 치목 | 치목 |
| 기둥 | 조립 시작 |
| 창방·보 | 구조 조립 세분화 |
| 도리·상량 | 종도리와 상량 |
| 서까래·추녀 | 지붕가구 |
| 개판·보토 | 기와 전 지붕 바탕 |
| 기와 | 기와잇기 |
| 수장 | 벽선 등 수장들이기 |
| 흙벽 | 흙벽치기 |
| 온돌·마루 | 마감공사 세분화 |
| 창호 | 마감공사 세분화 |
| 입택·조경 | 주변가꾸기 + 입택 |

그리고 목구조의 실제 순서도 기둥 → 창방 → 보 → 도리 → 종도리 → 상량 → 추녀·서까래로 이어진다. citeturn13view0turn13view1

즉 **A1 건축 교육의 골격은 그대로 유지**해야 한다.

### 다만 A1 이후 “완성 건물이 팝업”되면 안 된다

현재 B1/B2 계획은 솟을대문·행랑채·안채 등에 3~4개의 construction stage를 붙이는 방향이 이미 들어 있다. fileciteturn10file0L1-L7

제가 권하는 최종 구조는 이렇다.

#### A1 — 첫 집을 내 손으로 짓는다

**주역: 사랑채**

맨땅에서 사랑채 하나를 완성한다.

시각적으로 A1의 매력은 “아무것도 없던 대지에 초석이 생기고, 기둥이 올라가고, 처마곡선이 완성되는 것”이다.

이때 유저는 **한옥 자체의 문법**을 배운다.

A1이 끝났을 때의 장면은:

- 담장 일부
- 완성 사랑채
- 사랑마당
- 아직 막혀 있는 안쪽 터
- 아주 기본적인 나무 한두 그루

정도여야 한다.

**A1 끝인데 벌써 종갓집이 완성되어 있으면 안 된다.**

#### A2 — 집이 “살기 시작한다”

**주역: 사랑방 + 작은 생활 흔적**

새 대형 건물보다:

- 온돌에 불
- 굴뚝 연기
- 등잔
- 서안
- 책
- 문방사우
- 보료
- 바둑
- 거문고
- 까치
- 첫 장독
- 계절의 흔적

등을 통해 사랑채가 **모형 건축물 → 사람이 사는 장소**로 변한다.

이 단계의 목표는 “큰 실루엣은 거의 안 바뀌는데 정서적으로 엄청 달라진다”이다.

#### B1 — 종가의 앞·안 영역이 연결된다

**주역: 솟을대문 + 행랑채 + 안채 + 중문**

여기부터 단순 건물해금이 아니라 **공간이 깊어져야 한다.**

솟을대문은:

`기단/문설주 → 목구조·지붕 → 문짝·최종`

행랑채는:

`기단 → 골조 → 지붕 → 벽·문`

안채는:

`기단/초석 → 골조 → 지붕 → 흙벽·창호 → 입택`

정도로 축약한다.

A1처럼 16단계를 세 번 반복하면 지루하다.  
대신 B1에서는 A1에서 이미 배운 건축어휘를 사용해 **“공정을 지시하는 한국어”**가 어려워지는 것이 핵심이다.

그리고 B1 끝에는 반드시 **중문/일각문**이 생겨야 한다.

현재 계획에서 제가 가장 크게 추가하고 싶은 에셋 중 하나가 바로 **중문**이다.

왜냐하면 중문 하나가 생기는 순간, 안채가 단순히 지도 뒤쪽 건물에서 **“사적인 안공간”**으로 변하기 때문이다. 두곡고택처럼 사랑채와 안채 사이에 중문을 둔 실제 사례도 있다. citeturn9search14

#### B2 — “집”이 “종가”가 된다

현재 B2의 사당·후원 방향은 좋지만, **대청을 별채로 하나 더 추가하는 대신 서비스·의례·경관 영역을 완성**하는 편이 역사성과 디자인 양쪽에서 낫다.

제가 권하는 B2 주역은:

**사당 + 곳간/광 + 장독대·우물 작업영역 + 후원 + 정자**

이다.

사당은:

`기단·담 → 목구조 → 지붕·문 → 사당마당`

후원은:

`석축/화계 → 수목 → 작은 연못/정자`

서비스 영역은:

`우물 → 광/곳간 → 장독대/작업물`

순으로 발전시킨다.

이 단계가 끝나면 유저는 처음으로 “내가 집 한 채를 지은 게 아니라 **가문 하나의 생활 시스템을 만들었다**”는 느낌을 받는다.

#### C1 — 새로 짓기보다 “백 년을 버티게 한다”

C1의 현재 “돌보다” 개념은 오히려 한옥과 매우 잘 맞는다.

한옥은 목재·흙·기와·창호·온돌 등 다양한 재료와 장인의 기술로 이루어진 건축이다. 국가한옥센터는 대목수·소목수·기와공·흙벽공·석수 등 여러 장인이 한옥 시공에 관여한다고 설명한다. citeturn9search12

따라서 C1에서:

- 깨진 기와 교체
- 창호지 다시 바르기
- 흙벽 보수
- 목재 기름먹이기
- 장독 정리
- 화계 손보기
- 낙엽 쓸기
- 폭설 뒤 처마 점검
- 장마 전 배수 정리
- 봄 매화 / 여름 녹음 / 가을 국화 / 겨울 눈

을 반복 이벤트로 만든다.

이러면 **C1은 단순 cosmetic season unlock이 아니라 “집을 책임지는 단계”**가 된다.

#### C2 — “전하다”는 집에 역사를 만든다

현재 C2는 문집과 증표를 벽감에 쌓는 구상이다. fileciteturn10file0L1-L7

이것을 더 크게 확장할 수 있다.

C2에서는:

- 사당의 제례 맥락 설명
- 가문의 문집 정리
- 오래된 편지·상량문 해석
- 종가 방문객에게 집 설명
- 외국인 손님에게 한옥 문화 중재
- 후손 NPC에게 건축 용어 가르치기
- 별당 또는 서고 완성
- 가문의 현판/문집/소장품 기록

같은 활동을 한다.

UNESCO가 하회·양동을 건물만이 아니라 씨족·학문·의례·경관이 지속되는 문화적 체계로 평가한다는 점과도 잘 맞는다. citeturn11search1

### 종가 완성 후에도 절대 게임을 끝내지 않는다

이 부분은 사용자께서 말한 목표에 가장 중요하다.

> “C2까지 한다 해도 그냥 사람들이 한옥 지으러 한글소리에 들어왔으면 좋겠다.”

저도 그렇게 설계하는 것이 맞다고 본다.

86개의 검증된 `CanDoSegment`는 **영구 구조해금 권한**으로 그대로 둔다. 이것은 현재 repo 설계와 잘 맞는다. fileciteturn9file0L1-L2

하지만 C2 이후에는 CEFR을 늘리지 않고 별도의 **비권한적 한옥 장인 루프**를 둔다.

예:

**오늘의 돌봄 → 자재/공예 포인트 → 선택형 미관 개선**

- 창호 패턴 바꾸기
- 소나무 배치 선택
- 장독대 형태 선택
- 사랑방 가구 세팅 저장
- 정자 주변 계절 세팅
- 비 오는 날/눈 오는 날
- 봄맞이
- 추석·설 의례 준비
- 방문객 해설
- “내 종가” 사진 모드
- 여러 개의 사랑방 배치 프리셋
- 지역형 지붕/마당 변형
- 계절 한옥 앨범

같은 루프다.

즉 **언어 숙련은 집의 영역을 열고, 한옥 애착은 그 영역을 계속 살아 있게 만든다.**

## A1에서 C2까지 한국어 학습을 건축 퀘스트로 연결하는 방법

CEFR는 A1~C2 여섯 단계의 `can-do` 체계를 사용하고, 단순 지식이 아니라 실제 언어 사용 활동을 중심으로 학습 목표를 구성한다. Companion Volume은 학습자를 “사회적 행위자”로 보고, 수용·생산·상호작용뿐 아니라 **mediation**, 온라인 상호작용, 다언어·다문화 역량까지 확장한다. citeturn12search1turn12search2turn12search3

이것은 한옥 게임화와 이상할 정도로 궁합이 좋다.

왜냐하면 “집을 짓는다”는 것이 애초에 **목표지향 공동 작업**이기 때문이다.

### 레벨별 언어 행동 설계

| 수준 | 언어행동 | 한옥 역할 | 대표 퀘스트 | 보상 |
|---|---|---|---|---|
| **A1** | 물건 이름, 숫자, 간단한 위치·요청·명령 | 견습 목수 | “초석 네 개를 놓으세요”, “기둥은 어디에 있어요?”, “오른쪽 나무를 골라요” | 사랑채 시공 |
| **A2** | 일상 루틴, 단순 거래, 위치·시간·수량 설명 | 사랑채의 생활자 | “책을 서안 위에 놓아요”, “손님이 오기 전에 방석 두 장을 놓으세요” | 사랑방 가구·생활 흔적 |
| **B1** | 연결된 설명, 경험·이유 제시, 문제 해결 | 공사 현장의 책임자 | “비가 오기 전에 왜 지붕을 먼저 마쳐야 하는지 설명하세요” | 솟을대문·행랑·안채 |
| **B2** | 비교·논증·협상, 복잡한 정보 이해 | 집안 운영자/설계 협의자 | “사당은 어느 영역에 두는 것이 좋은지 두 안을 비교하세요” | 서비스영역·사당·후원 |
| **C1** | 암시·격식·긴 텍스트, 유연한 표현 | 종가 관리인 | 장인과 보수 계획 협의, 계절·의례 설명, 편지 작성 | 계절·보수·희귀 미관 |
| **C2** | 여러 자료 종합, 미세한 의미차, 문화적 중재 | 종가의 전승자 | 기록·편지·상량문을 종합해 방문객에게 집의 역사를 설명 | 문집·별당·서고·전승 요소 |

CEFR는 네 가지 핵심 언어 활동을 수용, 생산, 상호작용, 중재로 설명하므로 한 퀘스트도 “정답 한 번 탭”보다 이 네 축을 혼합하는 편이 더 CEFR다운 구조가 된다. citeturn12search9

### A1 예시 — 초석을 놓는다

화면:

초석 4개와 위치 표시가 보인다.

NPC 대목수:

> “이 돌은 초석이에요.  
> 기둥 아래에 놓아요.  
> 큰 초석을 왼쪽에 놓으세요.”

유저:

- 듣고 올바른 돌을 드래그
- `큰 / 작은`
- `왼쪽 / 오른쪽`
- `위 / 아래`
- `하나 / 둘 / 셋 / 넷`
- `놓다`

를 실제 행동으로 연결한다.

완료하면 **초석이 영구적으로 지도에 남는다.**

“한국어 문제 5개 풀고 보석 10개 받기”보다 훨씬 강한 기억이다.

### A2 예시 — 손님을 맞을 사랑방을 준비한다

NPC:

> “오늘 손님이 두 명 와요.  
> 방석을 두 장 놓아 주세요.  
> 서안 위에 책을 놓고, 화로는 문에서 멀리 놓아 주세요.”

유저는:

- 수량
- 위치
- 장소 조사 `에/에서`
- 목적격
- 일상 동사
- `-아/어 주세요`
- 순서

를 사용한다.

성공하면 방에 실제로 가구가 놓인다.

### B1 예시 — 목수에게 공정 설명하기

대목수 NPC가 묻는다.

> “기둥 다음에는 무엇을 해야 합니까?”

유저는 단순 선택이 아니라 짧은 연결문을 만든다.

> “먼저 기둥을 세운 다음에 창방을 짜 맞춥니다. 그다음 보와 도리를 올립니다.”

실제 목구조의 기둥 → 창방 → 보 → 도리 순서와 직접 맞는다. citeturn13view0

틀리면 **집이 망가지는 연출은 하지 않는다.**  
대신 장인이 다시 질문하고 힌트를 준다.

학습 실패를 건축물 손실과 연결하면 사용자가 집 꾸미기를 두려워하게 된다.

### B2 예시 — 마당 배치를 협의한다

두 NPC가 다른 제안을 한다.

> 청지기: “우물은 작업마당 가까이에 두는 것이 좋겠습니다.”  
> 안주인: “장독대에서 너무 멀지 않았으면 좋겠어요.”

유저는:

- 장단점
- 거리
- 동선
- 이유
- 조건문

을 사용하여 결정한다.

여기서 **게임의 designOption**이 진짜 언어활동이 된다.

### C1 예시 — 겨울 전에 집을 점검한다

처마 아래 깨진 기와, 찢어진 창호, 낙엽이 쌓인 배수로가 있다.

유저는 여러 정보를 읽고 우선순위를 세운다.

> “눈이 오기 전에 기와를 먼저 수리해야 합니다. 창호지는 실내에서도 고칠 수 있기 때문입니다.”

이 단계부터 정답은 하나가 아니라 **타당한 설명**을 평가할 수 있다.

### C2 예시 — 외국인에게 종가를 해설한다

방문객이 묻는다.

> “왜 안채와 사랑채가 이렇게 떨어져 있어요?”  
> “왜 마당에는 장식물이 별로 없어요?”  
> “사당은 왜 저쪽에 따로 있어요?”

유저는 짧은 안내문·자료·NPC 증언을 읽고 자연스러운 한국어로 재구성한다.

이런 활동은 CEFR Companion Volume이 강조하는 **mediation**, 즉 정보를 다른 사람에게 이해 가능하게 전달하고 문화적 맥락을 중재하는 능력과 매우 잘 맞는다. citeturn12search0turn12search2

### 한옥이 곧 단어장이어야 한다

외워야 할 “한옥 단어 목록”을 별도 페이지에 만들 필요가 없다.

유저가 직접 터치할 수 있게 한다.

예:

`기단 → 초석 → 기둥 → 창방 → 보 → 도리 → 종도리 → 추녀 → 서까래 → 기와 → 벽선 → 흙벽 → 온돌 → 마루 → 창호`

국가한옥센터는 실제로 이 부재들의 구조적 역할과 조립순서를 설명한다. citeturn13view0turn13view1

집을 오래 플레이한 사람은 어느 순간 별도 암기 없이:

**“도리는 서까래를 받는 부재구나.”  
“상량은 종도리를 올릴 때구나.”  
“누마루와 대청은 다르구나.”  
“사랑방은 사랑채 안에 있구나.”**

를 알고 있게 된다.

그게 이 기능의 가장 강한 교육 효과가 될 수 있다.

## 화풍과 에셋 설계 — “예쁜 종갓집”을 만들기 위한 새 규칙

### 지금 화풍 자체를 갈아엎을 필요는 없다

현재 repo의 estate 규약은 1536×1152 fixed canvas, north-up에 가까운 plan-locked oblique, 같은 축·광원·카메라를 공유하는 한 장의 한옥 지도를 목표로 잡았다. 기존 제작 시트도 개별 건물이 각자 다른 3/4 시점이나 소실점을 가지면 안 된다고 명시한다. fileciteturn24file0L1-L2

이 원칙은 맞다.

**지금의 “게임 느낌”은 Faceted Minhwa 때문이 아니라 세부 오브젝트의 크기·밀도·겹침·독립성 때문이다.**

따라서 estate V2 art rule을 다음과 같이 잡는 것을 권한다.

### 세계 지도에서는 “한 단계 덜 그린다”

**건물 근접뷰보다 디테일을 약 30~40% 덜 표현한다.**

예를 들어 기와 한 장 한 장을 다 읽게 만들지 않는다.  
지붕은 큰 면·용마루·처마곡선을 우선한다.

창살도 모든 칸을 강하게 보이게 하지 않는다.

나무도 가지 100개 대신 **큰 실루엣 5~8개 면**으로 잡는다.

마당에 떨어진 작은 돌·풀·꽃은 거의 삭제한다.

이런 방향은 역사적 절제와도 부딪히지 않는다. 조선 사대부 살림집은 궁궐·사찰과 달리 장식 자체가 비교적 절제되었다. citeturn13view3

### 기본 줌에서 보이는 오브젝트 수에 예산을 둔다

제가 권하는 **마당별 visual budget**은 다음이다.

**사랑마당**
- 사랑채
- 수목 cluster 1
- 작은 석물/화분 cluster 1
- 그 외 비움

**안마당**
- 안채
- 장독/생활 cluster 1 또는 없음
- 작은 생활 흔적 1
- 중앙은 비움

**행랑마당**
- 우물 cluster
- 작업 도구 cluster
- 행랑채
- 그 외 비움

**후원**
- hero tree 1
- secondary tree cluster 1
- 정자
- 작은 연못 또는 화계
- 계절 overlay 하나

**사당마당**
- 사당
- 아주 절제된 나무 1~2
- 거의 전부 비움

이렇게 하면 전체 자산 개수는 100개가 되어도 **한 화면에는 20개처럼 보인다.**

### 나무는 중요하다 — 하지만 “수목 스티커”처럼 놓으면 안 된다

사용자께서 원하는 “나무도 있고 정자도 있고 멋진 종갓집”은 역사적으로도 맞는 방향이다. 하회·양동 역시 산·숲·물과 주택·누정의 관계가 핵심 경관으로 평가된다. citeturn11search1

따라서 수목은 소품이 아니라 **공간을 프레이밍하는 건축요소**처럼 써야 한다.

추천:

- 사랑채 누마루 바깥에 노송 한 그루
- 후원 화계에 매화
- 사당 근처는 수목 최소
- 담 너머에서 일부만 보이는 대나무/소나무
- 정자 뒤에 큰 수관
- 화면 가장자리에서 일부 잘리는 나무 허용

반대로 **건물 앞 정중앙에 나무 sprite를 하나씩 배치하는 방식**은 피한다.

### 연못은 줄이고 정자는 살린다

현재 한옥 지도에 거대한 후원/연못 계열을 넣으면 1536×1152에서 건축보다 조경이 주인공이 되기 쉽다.

사대부 주택에서 연못과 누정·수목으로 경관을 구성할 수 있었던 것은 맞지만, 모든 종가에 거대한 연못이 필수인 것은 아니다. 국가한옥센터 역시 연못을 가능한 정원 요소 중 하나로 설명한다. citeturn10search0

따라서 한글소리에서는:

**작은 연못 + 정자/누마루 + 수목**

이 더 좋다.

연못을 화면 20~30% 차지하는 hero asset으로 만들지 않는다.

### 단청을 줄여야 “사대부 집”이 된다

현재 일부 옛 프롬프트에는 솟을대문이나 사당 등에 restrained dancheong을 넣는 표현이 있지만, 민간 살림집은 궁궐·사찰과 다르고 조선시대의 가사 제한도 있었다. citeturn13view3

따라서 V2에서는:

- 사랑채: 단청 거의 없음
- 안채: 없음
- 행랑채: 없음
- 곳간: 없음
- 별당: 없음 또는 목재 자체색
- 솟을대문: 구조·편액·기와선으로 격을 표현
- 사당: 역시 극히 절제

정도로 통일하는 것이 더 고급스럽다.

**화려함은 색칠이 아니라 비례와 목재·기와·창호의 정교함으로 표현한다.**

### 현재 “대청마루 독립건물”은 시각적 복잡성을 줄일 기회다

현재 production 구조가 여섯 건물이고 그중 하나가 `daecheongmaru.png`다. fileciteturn26file0L1-L10

이걸 독립 silhouette 하나로 계속 유지하면 새 별당·서고·정자까지 들어갈 때 건물 덩어리가 너무 많아진다.

그래서:

**사랑채 sprite 안에 사랑대청·누마루의 개방감을 더 분명히 표현하고, `daecheongmaru` 외관 asset은 별도 건물에서 제거하거나 정자로 전환**

하는 것을 추천한다.

그렇게 하면 기존 6채 + 별당 + 서고 + 정자를 다 넣어도 화면 실루엣 수는 오히려 비슷하게 유지된다.

### 미술 자산은 네 등급으로 나눈다

앞으로 한옥 에셋을 아래 네 타입으로 강제하면 관리가 훨씬 쉬워진다.

| 유형 | 예 | 지도 표시 |
|---|---|---|
| **Architecture** | 사랑채, 안채, 솟을대문, 행랑채, 사당, 별당, 정자 | 항상/해금 시 |
| **Infrastructure** | 담, 중문, 우물, 장독대, 화계, 곳간 | 영역 해금 시 |
| **Ambience** | 연기, 까치, 빨랫줄, 낙엽, 눈, 등불 | 조건부 하나씩 |
| **Interior furnishing** | 서안, 경대, 보료, 연상, 바둑 등 | 지도에는 절대 표시하지 않고 방 내부에서만 |

지금처럼 decoration 파일이 많다는 사실 자체는 문제가 아니다.

**실내 asset이 세계지도까지 올라오는 순간 문제가 된다.**

### 신규 건물도 A1의 결정론적 파이프라인을 그대로 쓴다

A1에서 가장 값진 기술적 성과는 바로 이것이다.

> 승인된 최종 건물의 기하를 고정하고  
> → 부재를 역분해하고  
> → 필요한 새 부품만 생성하고  
> → 좌표·z-order·manifest로 deterministic compose.

fileciteturn9file0L1-L2

별당·서고·정자·중문도 모델에게:

> “같은 집을 이번에는 골조 상태로 다시 그려 줘”

라고 하면 안 된다.

**완성본 한 장을 먼저 승인하고 역으로 시공단계를 만든다.**

특히:

`foundation → frame → roof → wall/window → lived-in`

5-state kit 정도가 적당하다.

B1/B2에서는 유저가 A1 공법을 이미 알기 때문에 16상태까지 갈 필요는 없다.

### 현재 pending-review 자산은 “있다”와 “쓸 수 있다”를 구분해야 한다

8월 19일 현재 별당·서고와 사랑방 소품 9종이 생성되었지만, 감사 문서 기준으로는 runtime에 연결되지 않았고 원장 append도 끝나지 않았다. fileciteturn21file0L1-L7

따라서 다음 세션은:

**“별당이 없다 → 또 생성”이 아니라  
“별당 후보가 pending-review에 있다 → 먼저 육안 검수”**

부터 해야 한다.

이것은 매우 중요하다.  
같은 asset을 다시 만들며 credit을 쓰면 안 된다.

### 현 단계에서 새로 꼭 필요한 한옥 에셋

기존 자산과 pending-review를 최대한 살린다는 전제에서 우선순위는 이렇게 본다.

| 우선 | 자산 | 이유 |
|---|---|---|
| 최상 | **중문/일각문** | 안채의 프라이버시와 공간 위계를 단 한 장으로 만든다 |
| 최상 | **곳간/광 또는 서비스 wing** | 현재 종가가 “주거 전시장”이고 생활경제가 없다 |
| 최상 | **우물** | 작업마당의 중심 인터랙션이 된다 |
| 높음 | **정자** | 사용자가 원하는 후원 fantasy와 역사적 누정 문화를 연결 |
| 높음 | **작은 화계/석축 kit** | 후원을 큰 sprite 없이 풍부하게 만든다 |
| 높음 | **담장·문 모듈** | 새 건물보다 공간을 나눠주는 핵심 asset |
| 높음 | **장독대 소형 변형** | 안채 뒤/서비스 영역에 맞춰 조절 |
| 중간 | **방앗간/작업채** | 부유한 큰 집의 생활경제 확장; 덕산·두곡 등 실제 고택 사례에도 부속 작업시설이 확인된다. citeturn9search11turn9search14 |
| 중간 | **작은 사랑/서고 wing** | C2 학문·문집 콘텐츠 |
| 후반 | **별당** | 이미 pending-review 후보 존재 |
| 후반 | **서고** | 이미 pending-review 후보 존재 |
| 조건부 | **연못/다리 변형** | 현재 화면이 충분히 정리된 뒤만 |

반대로 **새 사랑채, 새 안채, 새 솟을대문, 새 사당을 처음부터 다시 생성하는 것은 추천하지 않는다.**

현재 승인 자산을 masterplan V2에 맞춰 **위치·크기·z·주변 경계만 재조정하는 것부터** 해야 한다.

## 최종 제품 청사진 — 이 게임을 “한옥 때문에 돌아오는 한국어 앱”으로 만드는 방법

제가 한옥 설계자이자 게임 시스템 설계자라면 최종적으로 한글소리를 다음처럼 만든다.

### 첫 화면은 끝까지 “한눈에 보는 종가”다

1536×1152 master canvas는 유지한다. 현재 asset pipeline과도 가장 잘 맞는다. fileciteturn27file0L1-L7

하지만 모든 정보를 거기에 넣지 않는다.

기본 지도에는:

**지붕, 마당, 담, 나무, 문, 계절**

만 보인다.

유저가 사랑채를 누르면 카메라가 사랑마당에 초점을 맞추고,

다시 사랑방을 누르면 1086×1448 실내로 들어간다.

즉:

`종가 전체 → 채 → 방 → 물건`

이라는 네 단계 스케일을 만든다.

이렇게 하면 복잡한 종갓집을 만들어도 기본화면은 절대 복잡하지 않다.

### 집 전체에 “살아 있는 상태”를 만든다

같은 완성 한옥이어도 하루마다 조금 달라야 한다.

다만 한 번에 **한두 개만 움직인다.**

예:

- 아침: 솟을대문 열림
- 추운 날: 굴뚝 연기
- 저녁: 사랑방 등불
- 봄: 매화
- 비: 처마 빗물
- 가을: 낙엽 몇 장
- 겨울: 지붕 눈
- 손님 방문: 사랑마당 신발 두 켤레
- 공부 중: 사랑방 창가 빛
- 잔치: 대청에 방석 추가
- 제례: 사당문 상태 변경

이런 작은 변화가 **집 전체에 NPC 30명을 돌아다니게 하는 것보다 훨씬 고급스럽다.**

### “건물 해금”보다 “이 집에서 할 수 있는 일”이 늘어난다

사랑채를 지으면:

**독서 / 쓰기 / 손님 맞기 / 바둑 / 음악**

안채를 지으면:

**요리 / 옷 / 가족 / 바느질 / 살림 / 편지**

행랑·작업공간을 지으면:

**물자 / 숫자 / 주문 / 전달 / 거래**

후원을 만들면:

**날씨 / 계절 / 자연 묘사 / 시**

사당을 만들면:

**가족관계 / 역사 / 예절 / 설명**

서고를 만들면:

**긴 글 / 문헌 / 요약 / 비교 / 중재**

가 열린다.

그래서 한옥은 단순 reward가 아니라 **한글소리 전체 콘텐츠의 공간 UI**가 된다.

### 유저가 “내 집”이라고 느끼는 선택은 구조가 아니라 표면에서 준다

역사적 masterplan은 어느 정도 고정해야 한다.

사당을 대문 바로 옆에 놓게 하거나 안채 없이 우선 정자를 짓게 하는 자유배치는 역사적 공간성을 무너뜨린다.

그래서 **채의 위치는 고정**, 개인화는 다음에서 준다.

- 사랑방 가구 배치
- 병풍 선택
- 창호 pattern
- 장독 항아리 조합
- 소나무/매화 선택 socket
- 정자 주변 식생
- 계절 상태
- 서가 문집 배열
- 방석/보료 세팅
- 백자/청자 한 점 선택
- 현판/호 이름
- 야간 등불 여부

이렇게 하면 **심즈식 자유도와 역사적 설계의 정확성**을 동시에 얻는다.
