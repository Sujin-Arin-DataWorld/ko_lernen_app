## 제작 순서

1. **B1/B2 어휘 기반** — 생활·직장·주거·건강·디지털 생활(B1), 격식·협상·행정·사회·추상 논의(B2)를
   묶어 완전한 15열 draft와 리뷰 원장을 만든다. 기존 단어와 표제어 중복은 금지한다.
2. **문법 기반** — 새 시나리오가 참조할 B1/B2 문법을 먼저 만든다. quiz focus는 DE/EN 예문에
   정확히 한 번 나타나야 하며, 3개 distractor는 같은 레벨에서만 고른다.
3. **스몰토크와 게임 문장** — 스몰토크는 사람 대 사람의 자연스러운 turn을 새로 쓴다. Cloze/Satzbau는
   승인 후보 단어의 예문을 재사용해 능동 회상을 만들고, 억지 빈칸·답 유출·부자연스러운 distractor를
   수동 검수한다.
4. **시나리오와 코스 데이터** — 승인된 단어·문법 ID만 참조한다. 시나리오 하나가 듣기·퀘스트·코스에
   재사용되는 고레버리지 자산이므로 수량보다 대화의 자연성과 화법 차이를 우선한다.
5. **퍼즐·끝말잇기·OCR·발음** — 격자/사전/Cloud Function mirror/TTS처럼 별도 기술 계약이 있는
   콘텐츠는 마지막에 전용 검수로 처리한다.

## 품질 기준

- 한국어가 실제 상황에서 자연스러운가. 번역투, 교과서식 과장, 불필요한 고유명사·상표는 제외한다.
- 독일어는 독일어권 성인이 실제로 말하거나 이해할 표현으로 번역하며, 영어는 독일어의 직역이 아니라
  같은 의도를 전달한다.
- B1은 구체적인 일·관계·서비스 상황에서 이유·대조·완곡 요청을 할 수 있어야 한다.
  B2는 격식도·추상성·협상·간접화법·문어적 연결을 늘리되, 희귀어 나열로 난도를 만들지 않는다.
- 같은 표제어·문장·정답 조합의 중복을 금지하고, 새 항목은 기존 코퍼스와 대조한다.

## 검수와 병합

각 batch는 다음 세 파일군으로 남긴다.

1. `tools/content_factory/drafts/`의 schema-complete CSV/JSON
2. `tools/content_factory/review/`의 `id`·`상태` 기반 Jin 검수 원장
3. 필요 시 시나리오 전문 Markdown 검수본

`draft`·`fix:`·`no`는 절대 앱 자산으로 병합하지 않는다. `ok` 또는 `approved`만
preview 후 transactional apply 대상이다. 새 한국어 발화가 실제로 병합된 뒤에만
TTS dry-run 수량을 다시 확인한다.

## 첫 제작 배치

첫 배치는 "주거·계약·직장 소통(B1) / 격식 요청·협상·공적 소통(B2)"로 잡는다.
이 주제는 새 문법, 서비스 스몰토크, Cloze/Satzbau, 이후 시나리오에 모두 재사용된다.
배치에는 다음을 포함한다.

- B1/B2 각각 12개 단어와 완전한 15열 레코드
- B1/B2 각각 4개 quiz-ready 문법 항목
- B1/B2 각각 8개 스몰토크 턴
- 위 단어의 예문에서 파생한 Cloze/Satzbau 후보

수량 목표를 한 번에 무검수 병합하지 않고, 이 batch의 Jin 피드백을 이후 대형 batch의
스타일 기준으로 삼는다.
