- 짧은 녹청 헤더, 한지 판에 학습·확인·CTA를 함께 배치.

- 이번 생성 PNG의 백호는 승인 정본을 시각 참고로 사용한 목업 표현이다. **실제 앱에는 CompanionArt의 승인 원본을 같은 역할/점유율로 배치한다.** 생성 결과가 원본과 바이트 동일하다는 주장은 하지 않는다.

## 사용자 흐름

입문 시작/재개 → 원하는 단계 → 현재 첫 미실습 과제 → 실제 조작 → 학습자 확인 → 저장 대기 → 저장 확인 후 다음 과제 → 단계 저장 결과/입문 허브. 언제든 뒤로 가고 다른 단계를 열 수 있다. A1 이동은 입문 12개 완료 전에도 선택 가능하다.

입문 실습은 XP·엽전·CEFR 평가·A1 유닛 완료를 만들지 않는다. 따라 말하기 확인은 자기 보고이며 자동 발음 점수가 아니다. 조합은 현재 코드와 같은 탭 선택을 기본으로 하고, 드래그 강제 조작이나 신규 음성 분석을 추가하지 않는다. 기존 전체 Hangul의 `attempt.complete`와 완료·공통 보상은 기존 계약 그대로 연결하며 입문 무보상 규칙으로 덮어쓰지 않는다.

## 반응과 실패

- 버튼 단면 4dp, 눌림 배율0.99, 눌림 반응 약100ms. 탭 callback 즉시 실행.
- 조합 선택에 한 번만 짧은 그림 반응(120–180ms). 모션 감소 시 최종 선택 즉시 표시.
- 글자 읽는 동안 사물·주요 CTA는 안정. 글자/사물 반복 idle, 학습을 막는 연출 대기 없음.
- 획 통과만 잉크 색/진행 갱신. 틀린 획은 마지막 획만 거절, 기존 통과 획 보존. 텍스트로 방향/순서/길이/형태를 안내.
- 음성 오류는 같은 듣기 버튼 재시도, 성공하지 않은 재생으로 확인/저장 활성화 금지.
- 저장 실패는 현재 입력·선택·확인 보존, CTA로 다시 저장. 저장이 확정되기 전 진행 증가 금지.
- 계정/초기화/오래된 비동기 결과는 기존 lease/revision 계약을 유지.
- A1 선택 저장과 실제 화면 열기 실패를 구분. 실패해도 기존 실습과 선택은 보존.

## 수치·반응형·접근성

최신 공통 토큰: 제목30sp/700/1.12, 카드제목22sp/700/1.2, 본문16sp/1.35, 주CTA21sp/700/1.2, 작은CTA16sp/700. Paperlogy와 학습용 Noto Sans KR를 사용한다. PNG 글자를 읽어 정확한 sp를 복구한 값이 아니라 현재 공통소스 토큰이다.
최소 조작 영역48×48dp, 주요CTA54dp 이상. 바깥과 큰 한지 보드 안쪽12dp, 큰보드모서리18dp·일반카드14dp·작은선택10dp, CTA모서리9dp·단면4dp·경계1.3dp·안쪽가로12/세로10dp. 밀도에 맞는 보조 간격8/10/12dp를 공유하고 본문은 자연 높이로 증가한다. 학습 글자·쓰기판 크기는 작업별 별도 슬롯이며 소개 장면의 활자 크기를 그대로 복제하지 않는다.

입문은 Lernen에서 밀어 여는 학습 화면이므로 연습 중 하단 5탭을 새로 추가하지 않고 기존 back 흐름을 유지한다. 상단 녹청 배경은 실제 OS 영역과 자연스럽게 이어지되 상태바를 앱에서 다시 그리지 않는다.

320dp/큰 글자/가로: 본문을 스크롤하고 CTA가 접근 가능하도록 SafeArea. 글자 강제 축소·전체 화면 비례 축소 금지. 600–800dp: 중앙 읽기 폭과 쓰기 캔버스 비율 유지, 사물/작업 영역을 둘로 배치할 수 있다. 배우는 글자와 획 판을 장식 이미지에 굽지 않는다.

초점 순서: 제목 → 과제 진행 → 학습 내용/선택/캔버스 → 듣기/지우기 → 확인 → 저장. 선택/완료/비활성을 의미 정보로 제공하고 장식 그림은 초점에서 제외. 모션 감소와 실제 글자 확대는 Flutter 구현 시 검증해야 한다.

## 이번 검증 범위

- 현재 source의 FoundationStep/Task와 4단계·12과제를 대조했다.

## 적용한 스킬

ui-ux-help는 모바일 목업으로 요청을 정리했고, ui-ux-designer와 user-flows는 기존 행동·설정·예외·완료 흐름을 대조했다. ui-ux-pro-max는 진행 피드백·글자 확대·터치 기준을 적용했다. 일반 교육 추천 팔레트/서체는 승인 C와 달라 채택하지 않았다. ui-styling과 frontend-design-direction은 C질감·안정적인 학습 공간·짧은 헤더를 유지했다. flutter-dart-code-review는 기존 입력·완료·저장 조건을 읽는 기준으로 적용했다. 이미지 생성은 필요한 목업·수정에만 사용했다. 설치 상태나 플러그인 설정은 변경하지 않았고 외부 디자인 커넥터는 사용하지 않았다.
