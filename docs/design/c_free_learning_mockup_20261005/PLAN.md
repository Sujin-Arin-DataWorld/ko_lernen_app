# C 자유학습: 설계와 검수 계획

사용자가 지정한 5번 범위: 단어 팩 Learn·Quiz·Boss, 복습 카드, 문법 설명·연습, 발음 녹음·결과, native Hören·상황 퀘스트, 단어 관계 학습. 먼저 현행 소스를 읽고 이 계획을 작성한 뒤 목업을 구현한다.

## 1. 디자인 방향과 적용 스킬

- 목적: 자유학습에서 필요한 자료를 찾고 한 번 연습한 뒤 같은 자료로 재개한다.
- 대상: DE/EN 사용자가 한국어 A1–C2 자료를 반복해서 이용한다. 탐색 수준은 실제 계정의 학습 수준과 별개다.
- 승인 권위: `../c_approved_visual_contract_20261005/APPROVED_C_DESIGN.md`의 최종 메인 5탭·Einleitung 7장. 기존 C 소재·글자·비율을 사용한다.
- frontend-ui-engineering: 데이터/상태/렌더 분리, 실제 내용으로 모바일 검수, 키보드·포커스·실패·빈 상태.
- ui-styling: 의미 토큰, 재사용 컴포넌트, 시각적 위계와 접근성. 기존 순수 HTML/CSS 구조를 유지하고 shadcn/Tailwind 설치는 필요하지 않다.
- ecc:frontend-design-direction: 첫 화면에 실제 도구를 배치하고 긴 마케팅 설명·큰 활자·겹겹의 카드 대신 소재와 실제 학습 내용을 중심에 둔다.
- design-system: 원시 값 → 의미 → 컴포넌트 계약. 승인 토큰을 직접 import하고 추가 값의 역할을 기록한다.
- 사용자 흐름: 선택 → 자료 → 연습 → 첫 시도/도움 피드백 → 목업 저장/재시도 → 같은 ID 재개를 각 모듈에 적용한다. 이전에 지정된 uiuxdesigner user-flows의 1.1.0 파일은 현재 설치 경로에 없어, 적용했다고 표시하지 않는다. 이번 작업은 위 설치된 스킬과 명시된 흐름 계약으로 진행한다.

공통 간격은 화면 바깥 12px, 한지 안쪽 12px, 학습 카드 사이 10px, 그림→라벨 4px, CTA 최소 54px/간단 동작 48px. 값은 기본 100%의 CSS px이며 텍스트만 rem으로 확대한다. 제목 30px 이하, 상세 제목 22px, 기본 16px, 한국어 카드 24–30px. 200%에서도 글자 크기를 임의로 줄이지 않고 줄바꿈·세로 스크롤로 수용한다.

## 2. ‘전체 콘텐츠 100% 트리거’의 검증 단위

분모는 현재 작업공간의 이 7개 모듈에 배포된 원본이다. 저작용 초안·이전 버전·승인 전 자료를 새 수업으로 승격하지 않는다.

| 자료 | 확인한 개수 | 기본 진입 | 각 ID의 진입 | 끝까지 열 동작 |
|---|---:|---|---|---|
| 단어 | 2,968 / 254팩 | 팩·수준·주제·검색 | pack ID + vocab ID | 모든 단어 Learn → normal Quiz → 현재 팩 Boss → 결과·회상 |
| 복습 | 기본 2,968 + 사용자 입력 | 수준/전체 탐색·저장한 카드 | vocab ID / 사용자 입력 ID | 앞면 → 답 → 기억 판단 → 다음·결과·저장 실패/재시도 |
| 문법 | 264 | 수준·계획·검색 | grammar ID | 설명·용법·원본 예문·연결 표현 → 승인된 4지선다 → 결과 |
| 발음 | 84 | 수준·발음 초점·검색 | phrase ID | 원본 듣기 → 요청한 경우 로컬 녹음·재생 → 결과·재녹음 |
| Hören | 186레슨 / 744질문 | native 수준·주제·이어하기 | lesson ID + question ID | 전체 대화 → 3 choice + 1 order → 피드백·결과·재개 |
| Alltagsszenen | 186상황 / 579퀘스트 | 수준·장소·검색 | scenario ID + quest ID | 소개·단어·대화·문법·역할연습·퀘스트·결과 |
| 관계 | 114클러스터 | 수준·단어·관계 검색 | cluster ID + 관계 항목 | 유의·반의·연관·표현·차이·예문 → 기존 생성 계약에 맞춘 퀴즈 |

모든 소스 행에는 파일 SHA-256, 원본 ID/JSON pointer/CSV 행, record hash, 원본 revision 또는 ‘소스에 없음’, 목업 URL, 실제 Flutter route/인자/저장 서비스가 연결된다. 각 질문과 관계 자식 항목에도 직접 진입을 제공한다. 스크린샷은 화면 형태를 대표하며, 콘텐츠 전체 접근은 인터랙티브 목업·접근 원장으로 입증한다.

문법 257행은 quiz_enabled=true, 7행은 false다. authored distractor IDs·같은 수준·유일한 번역 초점이 유효한 경우만 퀴즈를 만든다. 나머지는 설명·예문으로 접근하고 제외 이유를 표시한다. ‘100%’를 위해 임의 문제나 평가를 만들지 않는다.

시나리오 엔진은 기존 8유형 계약을 보존한다. 현재 파일에 실제로 있는 것은 hoerverstehen·uebersetzen·satzBauen·luecken·diktat·particlePop의 6유형이다. batchimDrop·schreiben의 유무를 원장에 남기며 콘텐츠를 새로 작성하지 않는다.

## 3. 화면 구성

### 공통 자유학습 책장

Lernen의 자유학습에서 7개 도구가 기존 C 그림과 짧은 라벨로 열린다. ‘이어서’는 목업 저장이 있을 때만 생긴다. 다음 수준을 둘러보아도 계정 수준·평가·잠금을 바꾸지 않는다. 목록은 검색+수준+주제로 좁히며 페이지 이동으로 모든 항목을 제공한다. 긴 콘텐츠 원장과 구현 설명은 별도 검수 페이지에 둔다.

### 단어 팩

팩 표지와 현재 팩 단어 수, Learn/Quiz/Boss의 실제 구성. Learn에는 Boss 단어도 모두 먼저 노출한다. 단어는 듣기·뜻 열기·원본 예문·문화/용법을 제공한다. Quiz와 Boss의 질문은 원본 단어에서 인식 문제를 만들고 첫 시도/답 공개를 보존한다. Boss를 과거 팩 복습이라고 부르지 않는다. 단계별 결과와 중단 재개가 같은 pack ID를 사용한다.

### 복습

한지 카드 한 장을 중심으로 듣기·앞면·뒤집기·기억 판단을 배치한다. 실제 계정의 due 값을 읽었다고 표시하지 않는다. 기본 자료 전체와 사용자가 목업에 직접 추가한 내 단어·책장 자료를 동일한 목록에서 열며, 한국어 표제어 중복은 기본 자료 우선이다. 앱의 실제 scheduled/new·hard·defer 정책은 통합 계약에 남긴다.

### 문법

패턴 → 짧은 설명 → 원본 예문 → 용법/미디어 표현 → 연습. 평가 전 한국어 정답 예문을 노출하지 않는다. quiz_enabled와 authored distractor IDs를 따른다. 설명을 읽은 이력과 혼자 답한 이력을 구분한다. 문법 패턴 JSON의 별도 43행도 설명 탭에서 보존한다.

### 발음

원본 한국어와 뜻, 발음 초점, 실제 듣기 버튼, 녹음/재생/다시하기. 마이크는 사용자가 녹음을 누르고 동의했을 때만 요청한다. 녹음은 브라우저 안에서만 처리한다. 서버 발음 평가·XP 지급은 호출하지 않고, 점수는 만들지 않는다. 권한 거절·마이크 없음·재생 실패도 클릭할 수 있는 상태로 설계한다.

### Hören

native lesson의 실제 제목·상황·장면과 전체 대화, 질문 4개. 대화/스크립트와 근거·설명은 원본에서 온다. 스크립트를 도움으로 표시하고 도움 이후 맞힌 답을 혼자 수행으로 바꾸지 않는다. 질문 목록에서 모든 question ID를 직접 열 수 있다. 청취 완료와 상황 퀘스트 완료는 서로 덮어쓰지 않는다.

### 상황

원본의 등장인물·관계·의도·말투·배경·단어·문법·역할연습·퀘스트 전체를 보존한다. 7단계 탭과 퀘스트 선택으로 이동한다. 6개 실제 유형은 선택·빈칸·음절/어절 조립·받아쓰기 조작을 각각 유지한다. 사용자가 입력한 쓰기는 정답 문자열 확인 또는 자기 확인의 범위를 명시한다.

### 단어 관계

중심 단어와 유의/반의/연관/표현을 한지 면에서 펼친다. 각 항목의 nuance와 실제 예문, 연결된 vocab ID를 열 수 있다. 퀴즈는 기존 relation service가 정의한 첫 관계 후보·차단 집합과 같은 유형의 보기 풀을 적용한다. 전체 연결 항목은 학습에서 빠짐없이 접근한다.

## 4. 공통 동작과 상태

- loading/source error/retry/empty/검색 결과 없음/selected/disabled/정답/오답/힌트/답 공개/저장 중/저장 실패/재시도/저장된 결과/중단 재개.
- 오류를 빈 자료·완료·미가입으로 바꾸지 않는다. 없는 ID는 ‘자료를 찾을 수 없음’과 원래 목록으로 돌아갈 동작을 제공한다.
- 빠른 중복 클릭은 busy guard로 막고 처음 제출한 결과와 도움 여부를 보존한다.
- 뒤로/닫기 → 진행 중 확인 → 이어하기. modal Escape·Tab·포커스 복귀. 48px 터치 영역.
- DE/EN. 320/390/700×390 및 큰 글자 200%, reduced motion. 색만으로 상태를 구분하지 않는다.
- 승인된 원본 그림·폰트·소재만 사용한다. 이미지 파일은 재생성/수정하지 않는다. 신규 목업 이미지는 이 HTML의 실제 렌더링 캡처다.
- 음성은 기존 canonical manifest와 v3/voice/hash 계약에 있는 공개 오디오만 읽는다. 합성 API·과금 API·임의 TTS 대체는 없다. 로딩·실패·스크립트 도움을 보존한다.

## 5. 구현 순서와 완료 조건

1. 계획 확정 → 소스 전체 export·record/asset hash·trigger 원장 생성.
2. 승인 C 공통 화면/카드/CTA/검색/목록/대화·포커스 구성.
3. 단어·복습·문법·발음 → native 청취·상황 → 단어 관계 순서로 각 renderer와 상태 연결.
4. 모든 ID/참조/route resolver를 검사해 빠진 ID, 덮인 revision, 빈 renderer를 0으로 만든다.
5. 대표 화면·모든 실제 퀘스트 유형·예외 상태·DE/EN·320/390/가로·200%에서 실제 브라우저 검수.
6. 7개 흐름의 선택/자료/연습/결과를 비교할 갤러리와 PNG, 콘텐츠 접근 검수표를 제공한다.

파일 소유 범위는 이 새 폴더와 외부 QA 증거뿐이다. 공유 Flutter·ARB·pubspec·오디오·원본 에셋과 다른 세션 WIP는 수정하지 않는다. 실제 앱 계정·SRS·평가·XP·보상은 쓰지 않는다. 목업 저장은 독립 namespace와 원본 ID/revision/hash를 사용하는 브라우저 sessionStorage다. 계정 저장/실기기 QA 완료로 판정하지 않는다.

완료는 ① 원본 접근/참조 누락 없음 ② 모든 지정 모듈의 자료→연습→피드백→결과 조작 가능 ③ 승인 C 간격/소재 유지 ④ 브라우저 검수 통과 ⑤ 실제 Flutter 통합의 route/인자/저장 계약 인계로 판단한다. 새 화면의 인간 승인과 실제 앱 통합은 각각 별도 상태다.
