# Spiele Figma 및 Flutter 적용 계획

Spiele 카탈로그의 여덟 진입점을 기준으로 삼는다. 독립 게임 일곱 개와 Eigene Wörter üben의 네 가지 연습을 합쳐 열한 흐름이다. Spiele에서 Meine Wörter의 팩을 열어 연습하고 다시 돌아오는 경로도 검증한다.

## 원본과 기능 보존

- 각 화면의 비교 원본에는 Figma 노드 ID, 뷰포트, 언어, 글자 배율, 데이터 ID, 게임 상태를 기록한다. 다른 상태나 후보 목업에서 뽑은 좌표는 합격 수치에 포함하지 않는다.
- 한지, 청자색, 목재, 황동과 정본 캐릭터는 독립 이미지로 사용한다. 제목, 문항, 보기, 루브릭, 진행도, 선택 상태와 버튼에는 현재 앱 데이터와 접근성 의미를 연결한다.
- 기존 실제 라우트에서 화면을 띄운다. 정답 판정, 타이머, 재생 중단, 중복 음절, 첫 시도 기록, 결과 저장 재시도, 보상 지급을 소유하는 코드의 호출 지점과 스코프를 유지한다.
- 다른 워크트리의 미커밋 작업은 해당 파일을 기준 커밋과 비교하고, 각 게임에 필요한 변경을 검증한 후 통합한다.
- A/B/C는 검토 표본으로 기록한다. 실제 폰에서의 배치는 글줄 수, 보기의 너비, 교차판의 행·열과 SafeArea를 기준으로 결정한다.

## 화면별 검증 순서

| 흐름 | 확인할 기준 |
| --- | --- |
| Wörter-Quiz | 승인 A/B/C의 문구·보기·하단바. 좁은 화면의 보기 페이지, 오답 피드백, 음성, 다음 문항과 저장 재시도 |
| Matching | 승인 A/B/C의 중립·선택·정답 상태. 페이지를 오가는 두 언어 선택과 오답 후 재선택 |
| Silben-Rätsel | A1 승인 배치의 단서·교차판·음절패·도움. A1 5열, A2 12패, B1 중복 패, C2 교차점과 수동 음절 배치 |
| Wortkette | 승인 A/B/C의 타일·기록·보내기. IME 조합, 잘못된 단어, 사전 실패, 호랑이 턴, 시간 종료 |
| Lückentext | 승인된 A/B/C 재질과 실제 문장·번역·보기 길이. C2 `cloze_c2_0180`, 첫 오답 저장, 재시도, Hilfe와 Runde beenden |
| Satz bauen | 어절판·완성 문장·되돌리기·비우기·검사. 실제 장문과 중복 어절, 시간 종료와 코스 진입 |
| Schreiben | 단서 종이·입력·힌트·제출. 키보드 위 제출, 한글 조합 중 제출 보호, 정오답 및 다시 풀기 |
| Karten | 승인 하단바와 카드 앞·뒤 본문. 음성, 뒤집기, 자기 평가, 저장 및 탭 복귀 |
| Anlaut-Quiz | 승인된 자판과 음절 구성. 긴 표현, 전체 자판, 음성 공개 타이밍 |
| Tageschallenge | 시작과 정오답 상태. 기존 레벨 기반 문항, 날짜, 결과 및 일일 보상 중복 방지 |
| Blitz-Paare | 두 열과 시간 표시. 실제 레벨 전환, 오답, 시간 종료, 결과 저장 |

기본 크기에서는 동일한 Figma 상태와 실제 Flutter 캡처의 주요 요소 네 변을 각각 2dp 이내로 맞춘다. 텍스처, 그림자, 글꼴, 글자 잘림과 중첩은 캡처에서 별도로 확인한다. 새 모형이 필요한 상태에는 기존 승인 기준을 확대 적용할 수 있는지 먼저 확인한다.

작은 화면에서는 SafeArea와 키보드를 뺀 실제 높이로 판단한다. 본문이 길면 게임의 조작 순서를 보존하며 페이지 버튼으로 나눈다. 음성, 도움, 다음, 제출처럼 진행에 필요한 조작은 페이지에 관계없이 터치할 수 있게 배치한다. 320×640과 글자 200%에서 48dp 조작 영역을 실제로 터치하고, 긴 데이터가 가려지지 않는지 끝 페이지까지 확인한다. [Apple 큰 글자 기준](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/larger-text-evaluation-criteria) · [Android 접근성 기준](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility)

결과를 기록할 때 Figma 좌표, 기본 화면 캡처, 작은 화면 터치 테스트, 기존 엔진 회귀, 병합 상태, 실기기 확인을 각각 명시한다.

## 첫 적용 결과

- Wörter-Quiz와 Matching은 402×874의 A/B/C Flutter 캡처 여섯 장을 기존 대조 캡처와 SHA-256으로 비교했다. 기본 화면의 회귀 확인으로 사용한다. [편집 가능한 Figma 보드](https://www.figma.com/design/7IHizFZMk5G3ahsuVKiYwb?node-id=271-2)
- Silben-Rätsel A1은 독일어 `skz_a1_001`에서 교차판, 첫 교차 칸, 첫 음절패, 도움, 하단바 좌표를 Flutter 테스트로 확인한다. 네 변에 1dp 허용 오차를 적용하고 하단바는 정확히 비교한다. [편집 가능한 Figma A1](https://www.figma.com/design/7IHizFZMk5G3ahsuVKiYwb?node-id=385-1141)
- 세 화면의 작은 레이아웃은 실제 버튼을 눌러 페이지 이동, 게임 선택과 도움을 확인했다. Quiz와 Matching은 독일어·영어 팩의 결과와 다시 시작까지 검사했고, Silben은 실제 5열 교차판, 12패, 중복 음절과 C2 힌트를 검사했다. 전체 11개 흐름의 2dp 대조와 실기기 검증은 남아 있다.

## 다음 적용 단위

1. Wortkette의 입력과 보내기를 키보드 위에 고정한다. Lückentext는 승인 프레임과 실제 문항을 연결하며 문장·보기·도움·결과를 검증한다.
2. Satz bauen, Schreiben, Karten에서 각각 어절 편집, 한글 조합, 앞뒤 면 상태를 보호하는 테스트를 먼저 실행하고 승인 화면을 적용한다.
3. `spiele-figma-first-20261018` 워크트리의 Anlaut, Tageschallenge, Blitz-Paare 변경을 게임별로 검토한다. 세 화면에는 1,236줄의 추가와 366줄의 삭제가 있으며 공용 위젯 변경도 별도로 존재한다. 현재 브랜치의 기능 테스트를 기준으로 승인 재질과 필요한 입력·타이머 변경을 가져온다.
