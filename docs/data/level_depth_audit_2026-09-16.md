### 1.5 What the learner actually sees on the word card

The data model (`lib/models/vocab.dart:3-104`, class `Vocab`) carries exactly
the 15 CSV columns and nothing else -- no nuance, collocation, register, or
contrast field exists to render even if a screen wanted to.

The default flashcard back face is `_FlipBack`
(`lib/screens/vocab_pack_screen.dart:1728-1854`). It renders, in order: the
gloss (`v.translationFor(lang)`, line 1765), the part of speech
(`v.posFor(lang)`, line 1775), the romanization (line 1785, front-or-back
depending on a setting), and one example pair -- Korean + auto-romanization
+ translation (lines 1798-1854), tap-to-speak. That is the entire teaching
surface for every word at every level, A1 through C2: **one gloss, one
example, no nuance, no collocation callout, no register tag, no contrast**.

The one place nuance/contrast text actually exists and is actually
rendered to a learner is the separate "Word Web" feature
(`lib/screens/word_web_study_screen.dart:115,145`, `item.nuance(lang)`,
sourced from `word_relations.json`'s `nuanceDe`/`nuanceEn` fields via
`lib/services/word_relation_service.dart` and `lib/models/word_relation.dart`).
It is reached from Vocab Notebook Studio
(`lib/screens/vocab_notebook_studio_screen.dart:468`), not from the normal
study/review flow, and -- per 1.4 above -- only exists for 114 of 2,563
headwords (3.1% of B1+). A separate "Vocab Nuance" quiz
(`lib/screens/vocab_nuance_screen.dart`, `lib/services/vocab_nuance_service.dart`)
does something adjacent (hanja-root/register quiz questions) but draws on
`hanja_lexicon.dart`, a different, small, hand-curated dataset, not on
`korean_vocab.csv` or `word_relations.json`.

Net effect: for the other ~96.9% of B1+ headwords, and for 100% of them in
the default study/review loop, a learner sees a dictionary-style
gloss + one example, full stop -- structurally unable to receive the
nuance/collocation/contrast/register information Jin's German notes model
assumes is normal.

## PART 2 -- Judged deep sample

Deterministic sample: 30 headwords per level (B1/B2/C1/C2, sorted by `id`,
evenly spaced -- see `tool/audit_level_depth.py::_sample_every_kth` and
`vocab_samples_b1_c2_30each` in the JSON for the exact rows) + 15
`grammar.csv` rows spanning B1-C2. NIKL grade/delta/confidence columns below
were computed with the same `CefrLexicon.phrase_grade` used everywhere else
in this repo (not re-derived by hand), then judged.

Legend -- (a) fit: is the headword genuinely at this level for a
German-speaking learner? (b) typical use: does the example show natural
collocation/case pattern/register? (c) contrast: near-synonym(s) that need
disambiguating, and whether anything in our data does it (never, in this
sample). (d) gloss: nuance or bare dictionary equivalent (flagged `bad` where
the DE gloss looks like a mistranslation/awkward calque). (e) usage note:
required / helpful / not needed.

**B1 headline:** 26% exact NIKL match, but the pattern in this sample is
telling: single common words skew *too easy* (설명하다, 궁금하다, 게으르다,
똑같다 -- all A2 or lower per NIKL) while multi-word phrases skew *too hard*
or turn out not to be reusable lexical units at all (월급 이야기, 하루만
가다, 잔소리 해석 read as frozen frames of an ongoing B1 narrative thread,
not vocabulary). Two idioms/registers (취중진담, 협조/협력/도움) are the
clearest "needs a usage note" cases. One outright bug: `vocab_a2_0435`
마감하다's example is ungrammatical Korean.

## PART 3 -- Bible cross-check

### Does §B.3-§B.6 specify depth (collocation/contrast/usage note/register), or only counts/length?

Reading `docs/CONTENT_LEVEL_BIBLE.md` §B.3-§B.6 field by field (① can-do
... ⑩ forbidden examples), only three of the ten fields touch depth at
all, and none of them require it *per word*:

- **⑤ 문장 규칙 (sentence rules)** is almost entirely a counting rule: "B1
  ≤16어절, 절 ≤3" (line 202), "B2 ≤22어절" (line 240) -- length and clause
  caps, not usage requirements. The one qualitative rule that recurs is
  negative: "A1 어휘를 전문용어로 치환해 난도만 올리는 방식 금지" (B1, line
  203) and "상위 레벨을 '문장만 길게'로 만들지 않는다" (B2 forbidden-example
  #2, line 259-260) -- these ban *inflating* difficulty artificially, but
  say nothing about teaching a word's *typical* use.
- **⑥ 담화·화행·존대 (discourse/register)** does specify register content
  per level (B1: "완곡어법 확대, 간접화법 도입", line 205; B2: "공식적
  요청·협상 화행", line 243; C1: "공적 발표체", line 281; C2: "비판적 거리
  두기", line 315) -- but as *curriculum content to teach* (which
  can-do/situations to cover), not as a *field every vocab/grammar row must
  carry*. There is no instruction that a word's register (해요/습니다/반말)
  or formality must be marked on the entry itself.
- **④ 어휘 성격·수 (vocabulary character/count)** is the closest the bible
  gets to naming collocation directly, and only in passing, as a
  *description of the source list's character*, never as a requirement:
  C1 line 274, "5급 2,365(연구보고서 원문) ... **연어·담론표지**, 추상 논증
  어휘" -- "collocations, discourse markers" describes what NIKL's grade-5
  vocabulary looks like, it does not instruct the app to capture a
  collocation partner for each word it teaches.

**No field requires**: a collocation partner, a near-synonym contrast, a
case/particle-pattern note, a register tag on the vocab row itself, or two
examples (formal + informal) per word. §D 작성 규칙 (writing rules,
line 358+) requires natural Korean, independently-natural DE/EN, level
ceilings, and persona consistency -- but never requires more than the one
`example_korean`/`example_german` pair the CSV schema already has room for.

**The bible itself already flags this gap as unresolved, twice:**

1. §A's own coverage-target table names it explicitly for C1: "5급
   **연어·담화** 400(후속)" (line 41) -- "grade-5 **collocation & discourse**
   [items], 400, **follow-up**" is listed as a target column with **no
   built content yet** ("후속" = future work), sitting right next to A1's
   already-hit "735(1급 100%)". Depth work for the level Jin is asking about
   was already identified as a backlog item, nine days before this audit.
2. The curriculum-matrix appendix's closing callout (lines 438-442):
   "**아직 없는 것(2026-09-09):** 336형태의 뜻·기능·예문은 어디에도 없다...
   화행 39종의 **실현 문형(exponent)** 목록도 없다... 둘 다 후속 작업이다."
   -- as of one week before this audit, the project's own tracking
   document already says grammar-form meaning/function/example content and
   speech-act realization lists don't exist anywhere yet.

Conclusion: Jin's question is not "is content violating a written rule" --
there is no written depth rule to violate. It is "the bible never asked for
depth in the first place, and the two places it gestures at collocation/
discourse content both say 후속 (not yet built)."

### Backfill effort estimate (B1-C2)

Rows in scope: 650(B1) + 571(B2) + 240(C1) + 240(C2) = **1,701 vocab rows**,
plus 35(B1) + 57(B2) + 23(C1) + 23(C2) = **138 grammar rows** (from the JSON
`depth_fields.grammar_explanation_length_by_level`/`vocab_grade_fit`
counts). Per Jin's 7-field model, minus what a shared cross-reference table
can do once instead of per-row:

- **뉘앙스 (nuance sentence, ~1 per word):** 1,701 rows -- but 52 already
  have one via `word_relations.json`, so **~1,649 new** nuance sentences.
- **연어 2-3개:** 1,701 rows × ~2.5 collocations ≈ **~4,250 collocation
  entries**. High leverage: Part 2 found several words already sharing a
  cluster (지불/결제/정산, 협조/협력/협업, 확보하다/보장하다/마련하다,
  의사결정권/재량권/결정권/권한/권리) where ONE shared note would cover 3-5
  headwords at once -- a clustered authoring pass, not 1,701 independent
  ones.
- **유의어 대비 1-2개:** same 1,701 rows, but same clustering leverage --
  Part 2's 90-item sample alone surfaced roughly 20 reusable
  contrast-clusters covering ~55 of the 90 rows (61%), suggesting the real
  authoring unit is "~1,000-1,100 contrast-clusters across B1-C2," not
  1,701 independent pairs.
- **조사·격 패턴 note:** mostly a GRAMMAR-side fix, not vocab: 138 rows,
  ~85-90 of which (6/15 sampled = 40% already have some register/contrast
  signal) need only a contrast/register addition to an existing
  `explanation`, not a new field.
- **격식 표시:** 1,701 rows need a one-of-three tag (formal/haeyo/banmal) --
  cheap once `example_richness`'s register heuristic (Part 1.3) is promoted
  from a heuristic to ground truth by a human pass; not a new authoring
  burden, a classification pass.
- **예문 2개 (거격식·비격식):** the expensive one -- a genuinely new second
  example per row, 1,701 rows. Realistically the lowest-priority item of
  the seven (Part 2 found register variety mostly *already* present across
  a level's different words, just not within one word's two examples).

Rough order of magnitude: **~1,700 nuance sentences + ~1,000-1,100
contrast-cluster write-ups (not 1,701) + ~4,000+ collocation entries +
~90 grammar-note edits + a classification (not authoring) pass for
register + ~1,700 second examples if pursued** -- this is a multi-hundred-
hour content-authoring program, not a schema patch, and should be planned
as its own phased initiative (e.g. cluster-first: fix the ~20 contrast
clusters already surfaced in Part 2, which touch ~60 headwords, before
attempting exhaustive per-word coverage).

### Recommended schema extension (recommendation only, no implementation)

A sidecar `assets/data/usage_notes.json`, keyed by vocab/grammar `id`
(mirrors `word_relations.json`'s existing pattern rather than widening
`korean_vocab.csv`, so the 2,563-row CSV and its many existing consumers
--`Vocab.fromRow`'s positional parsing, cloze/satz generators, the relevel
tooling -- stay untouched):

```json
{
  "vocab_c2_0137": {
    "nuanceDe": "...",
    "nuanceEn": "...",
    "register": "formal",
    "collocations": [{"ko": "삭제 권한을 주다/가지다", "note": "..."}],
    "contrasts": [{"withId": "vocab_...", "ko": "권리", "noteDe": "...", "noteEn": "..."}],
    "casePattern": {"ko": "N에게 N을 주다", "noteDe": "..."}
  }
}
```

Rendering: extend `_FlipBack` (`vocab_pack_screen.dart:1728`) with an
optional, collapsed "더 알아보기 / More" expander below the existing
example block, populated only when `usage_notes.json` has an entry for that
id (graceful no-op for the ~98% of rows without one yet, so this ships
incrementally rather than blocking on full backfill) -- reusing the
existing `WordRelationService`-style lazy JSON load and the `CultureNoteCard`
widget's collapsed-note visual pattern (`lib/widgets/sori/culture_note_card.dart`)
as a template rather than inventing new UI.
