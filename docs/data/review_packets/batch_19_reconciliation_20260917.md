# Batch19: 선택 행 이력과 시나리오 퇴역 검토

상태: 독립 Standards/Spec 모델 검토 완료, 추가 finding 없음. 사람·원어민·CEFR 승인은 추가하지 않았다. Batch19 전체 완료나 203행 전체 언어 검수를 뜻하지 않는다.

## 실제 수정

현재 앱 문법 3행의 9필드를 고친다. 한국어 예문과 레벨은 유지한다.

- `grammar_b1_soft_request_batch19`: 독일어의 `Termin`을 `Zeitplan`으로 바꿔 일정의 범위를 보존한다. 같은 정중한 부탁으로 답할 수 있는 `-아/어 주시면 좋겠다`를 오답에서 제외한다.
- 연계 `grammar_b1_soft_request`: 반대 방향의 동일 문제도 수정한다. DE/EN의 일정·조건·가능한 한 빨리라는 요청을 맞춘다. KO가 수신자의 단·복수를 명시하지 않으므로 `mir/me`는 현지화 선택이며, 원문에 단수 정보가 있었다는 주장이 아니다.
- `grammar_b1_reason_context`: 현재 레벨은 B2다. 인과로 해석할 수 있는 `N에 따라`를 오답에서 빼고, EN 강조 범위에 `so`를 포함한다. note는 긍정 결과의 전면 금지 대신 일반적 쓰임을 설명한다. [국립국어원 온라인가나다 답변](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&pageIndex=1&qna_seq=312863)(2025-04-14)을 근거로 삼았다.

문법 퀴즈는 DE/EN 예문의 강조된 부분에 맞는 한국어 패턴을 고르는 방식이다. 한국어 예문과 note는 답한 뒤 나타나므로, 오답 판단을 화면에 없는 한국어에만 의존하지 않는다.

## 정확한 이력 범위

`batch_19_reconciliation_20260917.json`은 vocab 1·grammar 3·Cloze 3·Satz 3행의 frozen draft / review / live 이력을 보존한다. 최초 승격은 `fc0489b65da0e9c11631a37eabd57f22e9e6e3e8`, 후속 확정은 `85621a27de70ee8e865db1e709e1a363a540436f`, 첫 main 합류는 `fe19460338fb0361bd28856b694d6fdae6b9b20d`다. 후속 확정을 최초 승격으로 바꾸어 기록하지 않는다.

선택 10행은 최초 draft/live가 같았다. 이후 draft 변경 2행, review 전이 0건, live 전이 14건이 관측됐다. 선택 트랙의 CSV 파싱 공백은 0건이다. 과거 보고서의 끝점 `b0b1745c`와 이번 시작점 `065279c4` 사이에서 이 행들이 그대로임을 해시로 확인했다. 이 수치를 다른 Batch19 행의 역사 완전성으로 확대하지 않는다.

10행에만 before/after 전체 행 지문과 변경 필드를 등록한다. B2로 이동한 `grammar_b1_reason_context`는 기존 relevel 원장의 정확한 이동만 적용해 비교한다. 그 밖의 새로운 변경은 계속 실패해야 한다. 연계 Batch02 카드에는 새 예외를 등록하지 않는다. 해당 배치의 과거 권리·승인·이력 검토는 남아 있다.

Cloze 3행은 9개의 완성 치환 문장, Satz 3행은 6개 오답 타일을 제시 번역과 대조했다. 다른 상황에서 문법적으로 가능한 문장까지 불가능하다고 주장하지 않는다. 이번에 이 문장이나 타일을 새로 고치지는 않는다.

## 퇴역한 시나리오 3개

`a1_register_first_day_choice`, `a2_plan_weather_change`, `b1_work_deadline_soft_request`는 canonical corpus 교체 커밋 `ca00acad2ff0d1470dc241bfdfb8d15685a7d1a0`에서 삭제됐다. main 합류는 `9e8dd09f7b5dd3a1183eb54d93be821bb0169e3a`다. 삭제 직전 레코드 전체와 현재 보존된 draft의 의미 지문이 일치한다.

A1/A2는 최초 승격 후 `85621a27`에서 수정됐다. 따라서 현재 보존본을 최초 승격본과 같은 파일로 취급하지 않는다. B1 레코드는 동일하다. 원장은 퇴역 사건을 9월 1일로 기록하지만, 원장 자체의 도입은 9월 15일 `d8776426f1936df47bed6974eeabde4324771467`이다. 오래된 can-do 참조는 `78daf0ddff031524d3892bb7a0ae89ee5c2f3dc5`에서 정리됐다.

정확한 세 cluster/seed 쌍을 기존 퇴역 원장과 대조했다. 1:1 후속 시나리오나 완료도 이전 관계는 없다. 소스는 corpus 세대가 바뀔 때 시나리오 완료·별점과 일반 과정 숙련도를 초기화하고, productive/project 증거를 보관하며 XP·배치·phase 증거를 유지한다. 실제 학습자 기기에서 이 마이그레이션을 실행해 확인한 결과는 아니다.

퇴역 증거를 기록해도 `validate_promoted_batch.py`의 live 존재 검사는 변경하지 않는다. **Batch19 strict 검사는 퇴역 시나리오 누락에서 계속 실패한다.** 구 코퍼스를 되살리거나 모든 과거 차이를 허용하는 예외를 추가하지 않는다. 후속 코퍼스의 의미적 커버리지와 사람 검수는 별도 미완료 항목이다.

## 검증 상태

- 선택 회귀 검사 7개: 수정 전 실패를 재현했고 수정 후 통과했다.
- 전체 `content_factory` discovery: 1,295개, 실패 0, 기존 skip 20. 검사 전후 콘텐츠 860파일의 해시가 같았다.
- Flutter 문법·퀴즈 화면·TTS manifest 검사 42개 통과. 기존 corpus 세대 전환·cloud legacy evidence 회귀 2개도 통과했다. 로컬 자동 테스트이며 실제 기기 검증은 아니다.
- 독립 Standards/Spec 검토에서 추가 수정 사항 없음. 선택 10행의 전체 행 지문과 과거 전이, 문법 4카드·12보기를 검토했다.
- Phase catalog/tasks와 canonical TTS manifest가 최신이다. Storage 읽기 전용 검증: expected 12,630, remote 21,140, missing 0, stale 8,510. 오래된 객체는 삭제하지 않았다.
- Batch19의 manifest·draft·review 15파일과 연계 Batch02의 3파일은 byte hash로 보존한다.
- 새 사람 승인·권리 주장·TTS 발화 변경은 없다.

작업 브랜치 기준 historical manifest 24개 중 strict 통과 11개, 실패 13개다. Batch19의 미해명 copy 차이는 10행에서 0행으로 줄었지만 퇴역 3행으로 strict 검사는 계속 실패한다. Batch07의 미해명 823행과 Batch02의 5행·권리 태그 문제 등은 이번 검토로 해소하지 않았다. 이 숫자를 아직 병합되지 않은 변경까지 포함한 현재 원격 main의 결과로 제시하지 않는다.
