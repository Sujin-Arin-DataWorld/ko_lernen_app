## 1. 첫인상 (2초)

시선은 **호랑이 → 말풍선 → 4개 카드** 순으로 간다. 여기까진 의도대로다.
문제는 그다음 — 카드에 시선이 닿는 순간 **읽을 것이 거의 없다.** 카드마다
한 줄짜리 설명이 `…`로 잘려 있고, 한국어 예문에는 뜻이 없다. 즉 *선택 화면인데
선택에 필요한 정보가 화면에 없다.*

한마디로: **분위기는 성공, 의사결정 지원은 실패.**

## 3. 시각 위계

- **시선이 먼저 닿는 것**: 호랑이(200dp) — 맞다. 온보딩 첫 대면.
- **두 번째**: 말풍선. 그런데 읽을 수 없는 문자라 시선이 튕겨 나온다.
- **읽기 흐름**: 호랑이 → 말풍선 → 타이틀(22px) → 부제(12.5px) → 카드.
  타이틀과 부제의 **크기 차가 1.76배**밖에 안 되는데 부제는 2줄이라
  덩어리 무게가 비슷하다. 위계가 눌린다.
- **강조 오류**: 화면에서 가장 큰 텍스트는 타이틀인데, 정작 사용자가 비교해야
  할 대상(레벨 이름 14px, 설명 11px)이 가장 작다. **비교 대상이 가장 작은 화면.**

## 6. 히어로 영상 선정 — `welcome_hero` vs `welcome_hero2`

**전 121프레임 픽셀 스캔** (ffmpeg 디코드 → numpy, 표본 아님).

| 항목 | welcome_hero | welcome_hero2 | 판정 |
|------|--------------|---------------|------|
| 해상도 | **960×960** (프로젝트 캐릭터 규격) | 1280×720 (16:9) | **hero** |
| 길이 / fps | 5.085s / 24fps / 121f | 동일 | 동률 |
| 파일 크기 | 2.10 MB | 1.43 MB | hero2 |
| 피사체 점유 면적 | **44.6%** | 25.7% | **hero** |
| 피사체 bbox | 폭 100% / 높이 89% | 폭 80% / 높이 91% | — |
| 가장자리 배경색 | `#ECDDCD` | `#EBD9C6` | 동률 |
| 배경 프레임간 흔들림 | 최대 ±10 | 최대 ±4.9 | hero2 |
| 루프 이음새 diff | 14.46 (인접의 **11.9배**) | 5.33 (인접의 **10.4배**) | 둘 다 결함 |
| 최적 루프 구간 | f12–f110 | f12–f110 | 동일 |
| 프레임 54 가장자리 검은 픽셀 | **97개 (아티팩트)** | 없음 | hero2 |
| 오디오 트랙 | AAC 있음 (무음이어야 함) | AAC 있음 | 둘 다 |

### 결론: **`welcome_hero.mp4` 채택**

1. **세로 폰 히어로는 정사각이 맞다.** 16:9를 정사각 슬롯에 넣으면 좌우 40%가
   잘리고, `welcome_hero2`의 피사체 bbox가 x131–1159라 **어깨 위 까치가 화면
   밖으로 나간다.** 까치(쌤쌤이)는 마스코트 2인조의 한 축이라 잘리면 안 된다.
2. **같은 슬롯 크기에서 얼굴이 약 1.7배 크다** (면적 44.6% vs 25.7%).
   온보딩 첫 대면에서 마스코트 인식이 이 화면의 정서적 목표다.
3. **프로젝트 계약 일치.** 캐릭터 클립 규격이 960×960/24fps라
   렌더·검수 파이프라인을 공유한다. 1280×720은 예외를 만든다.
4. 크기 차(0.67MB)는 앱 번들에서 무의미.

### ⚠️ 남은 결함 (원본 보존 — 사용자 판단 대기)

두 파일 모두 **깨끗한 루프가 아니다.** 5초마다 한 번씩 튀는 것이 보인다.
원본 에셋을 임의로 덮어쓰지 않았다. 정제하려면:

## 7. 잘 되어 있던 것

- 인트로 게이트 → 마당 도착이라는 **서사적 연속성 발상** 자체는 좋다.
  v4는 사진 대신 히어로 영상 속 마당 풍경 + 벚꽃 입자로 그 연속성을 잇는다.

- `LearnerLevel` enum · `Storage.setUserLevelCode` · `showAccountNudgeSheet`
  까지 선택 이후 흐름이 이미 깔끔히 분리돼 있어 화면만 갈아끼우면 됐다.
- `soriClampPadding`으로 태블릿·웹 폭 클램프가 이미 되어 있었다.
- arb에 예문 번역 4개가 **이미 준비돼 있었다** — 쓰이지 않았을 뿐.

## 8. 우선순위 권고

1. **레벨 설명 잘림 제거 + 예문 번역 병기** — 이 화면의 존재 이유를 복구하는
   단 하나의 변경. 사용자가 레벨을 *비교할 수 있게* 된다.
2. **한지 배경으로 전환** — 대비를 확률에서 보장으로 바꾼다. 부수적으로
   히어로 영상(크림 배경)이 화면에 자연스럽게 녹는다.
3. **사계 단청 팔레트 + 채움 도트** — A1·A2가 같은 색이던 버그를 고치고,
   색에 의존하지 않는 서열 신호를 만든다.
4. **말풍선 다국어화** — 첫 문장을 읽을 수 있게.
5. **비교 시트** — 「A1과 A2가 뭐가 달라요?」에 답한다.

## 9. 남은 리스크 / 후속

- 컨테이너에 Flutter SDK를 설치할 수 없어(네트워크 차단) `flutter analyze`를
  **돌리지 못했다.** 정적 검증은 괄호·문자열 균형 + 전 심볼 정의 대조 +
  추상/구현 getter 938개 일치 확인까지만 수행했다. 실행 전
  `flutter gen-l10n && flutter analyze && flutter test` 를 반드시 돌릴 것.
- `flutter gen-l10n`은 생성 파일을 다시 쓴다. 이번에 손으로 넣은 16개 키는
  arb에도 동일하게 들어가 있으므로 재생성해도 결과가 같아야 한다 — 다르면
  arb 쪽이 정답이다.
- 히어로 루프 이음새(§6)는 미해결. 사용자 판단 필요.
- 한국어 예문 4개를 완성 문장으로 되돌렸다(§2). 조각 문장을 의도한 것이었다면
  `_exampleKo` 맵 한 곳만 되돌리면 된다.
